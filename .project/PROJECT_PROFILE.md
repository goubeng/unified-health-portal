# 项目档案

- 项目名称：卫健XC统一门户系统
- 项目简称：卫健XC统一门户
- 项目类型：new
- 当前阶段：P4（核心Mock可运行版；P3整体验收已通过，真实集成未验收）
- 项目目标：建设位于身份来源层（闽政通=公众用户、闽政务=政务用户）与下层约43个业务子系统之间的统一门户中间层，提供统一登录承接、最小统一身份索引、门户角色权限、应用入口资格、跨系统账号映射、单点登录、待办/消息汇聚、门户通知公告、连接配置、运行监控及日志审计。
- 交付目标：开发交接 + 全量包 + 数据库包 + 最终文档 + 部署包；当前P4核心页面与CRUD演示。最终交付物在 P7 复核/P7.5 冻结后形成。
- Base Project 版本：office-house 0.1.0（2026-09-18读取UI入口、样式、布局及依赖；本项目本地实现，不复用其业务数据/权限）
- 技术栈：Vue 3 + Vite + TDesign Vue Next
- 数据策略：已核验 PostgreSQL 14.20 + NocoDB；仅在 base `pb3gir75kkooyea` 内原生建表，不关联其他项目数据源。199物理约束及事务回滚反例通过；P4浏览器演示隔离为Mock，不向真实库写示例数据。
- 公共模块：
  - 用户管理：启用门户用户访问/权限维护（PG-228），不启用权威身份主数据CRUD；闽政通/闽政务为权威认证来源
  - 组织管理：启用门户组织索引管理；政务用户组织优先由闽政务提供，公众用户不强制存在组织；门户不取代权威组织主数据
  - 角色：启用；仅管理门户中间层的菜单、页面、操作权限和门户数据范围；公众/政务用户类别不是角色
  - 字典：启用
  - 消息：启用；约43个子系统消息 + 门户自身消息纳入范围
  - 日志审计：启用；登录、认证、访问、门户操作、接口调用、异常日志纳入范围
- 当前版本：0.2.0
- 当前设计标识：V20260920-02（Draft，下一阶段改造目标；当前代码仍为0.2.0 P4基线）

## P2 阶段说明

本阶段以 P1 的角色、业务对象、功能和范围基线为输入，完成菜单结构、页面清单、页面规格、业务流程、状态机和字段规则。

P2 原则：
- DEMO 原型优先，先保证页面完整、可操作、核心链路可演示；
- 页面数据优先使用 Mock / Derived，真实接口在后续阶段替换；
- 待办、消息均采用子系统主动 PUSH 到门户，门户本期不主动拉取；
- 通知公告支持附件；
- “我的应用”不提供收藏能力；
- 消息、待办、日志留存周期配置化，P2 不冻结最终天数；
- 底层数据库物理模型、接口协议、鉴权、幂等、重试细节在后续阶段收敛。

P2 不生成 Schema / Migration / Seed，不生成最终用户手册、详细设计说明书、测试用例或部署交付文档。

## 2026-09-18 角色与公共服务口径

- 管理端用户统一称为“门户管理员”，按权限范围区分职责。
- 不设置固定门户管理员（集成管理权限）；上层短信等公共服务若需门户参与，由集成管理权限承担。
- 二维码、验证码等认证能力由上层身份平台提供，门户负责接入、展示状态、回调和Session。
- 短信费用统计已移出当前功能范围。


## 2026-09-20 当前三层架构与角色口径

- 身份来源层：闽政通对应公众用户，闽政务对应政务用户。
- 门户中间层：维护最小身份索引、门户用户状态、门户系统角色、门户权限、应用入口资格及子系统账号映射。
- 子系统层：继续维护各自账号、业务角色、菜单权限、数据权限及业务审批。
- “公众用户/政务用户”是用户类别；“闽政通/闽政务”是身份来源；均不得作为门户角色维护。
- 原独立门户权限配置并入角色管理。
- 系统分类最终迁入字典管理；现有application_category结构在迁移完成前保留兼容。
