# 项目范围

## 本期目标

建立“卫健XC统一门户系统”的项目基线，明确统一门户与上层身份平台、43 个子系统之间的职责边界，为后续 P1 需求范围细化提供稳定输入。

> 以下保留 P0 初始范围历史；当前有效范围以本文件末尾“当前范围同步”及 docs/product/范围边界.md 为准。当前正在复核 P2 并启动 P3。

## 本期包含

- 统一门户用户端入口。
- 统一门户管理端。
- 登录入口及与上层身份平台的跳转/衔接边界。
- 43 个子系统全部纳入“全部应用”。
- 43 个子系统待办接入门户统一聚合。
- 门户自身角色及门户自身权限管理。
- 门户到子系统的入口、导航和聚合能力。
- 为后续数据库、接口、权限、消息和操作履历设计保留项目级基线。

## 本期不包含

- 门户自行维护用户主数据。
- 门户自行维护完整组织主数据。
- 门户决定或维护各子系统内部的应用访问授权。
- 门户统一处理各子系统内部开户逻辑。
- P0 阶段不设计最终页面字段、页面交互、状态机、数据库表、消息触发规则、操作履历和统计口径。
- P0 阶段不生成最终用户手册、详细设计说明书、测试用例或部署交付文档。

## 核心角色

P0 仅做范围定位，角色细分在 P1 完成：

- 门户用户：使用统一门户访问应用与聚合待办。
- 门户管理员：管理门户自身配置与门户权限，不拥有用户主数据管理权，也不接管子系统内部权限。

## 核心业务对象

P0 暂按以下对象建立范围占位，详细字段和关系在 P1/P3 收敛：

- 门户应用
- 子系统
- 聚合待办
- 门户角色
- 门户权限
- 导航/入口配置

## 核心演示路径

统一登录/身份平台 → 进入统一门户 → 查看门户首页/全部应用 → 进入目标子系统；同时可在门户查看由 43 个子系统汇聚的待办入口。

## 已知限制

- 用户注册跳转至上层身份平台完成。
- 子系统开户由各子系统自行决定和处理。
- 应用访问授权由各子系统负责，门户只管理门户自身权限。
- 43 个子系统的待办聚合依赖各子系统提供可接入的数据或接口能力。
- 当前未在项目档案中明确 Base Project 的具体版本号。

## 待确认项

以下内容不阻塞 P0 建档，进入后续阶段按需确认：

- 项目代码（project.code）。
- Base Project 的实际版本号。
- 43 个子系统正式清单、系统编码和接入优先级。
- 上层身份平台的 SSO/注册跳转接口协议。
- 43 个子系统待办接口的数据契约、刷新机制和异常处理要求。
