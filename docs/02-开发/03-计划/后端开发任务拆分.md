# 后端开发任务拆分（0.3.0-B / 0.3.0-C）

> 基线：V20260921-01  
> 目标：把当前“前端可演示 + 本地 Node 原型 API + P3 数据库历史结构”逐步升级为可进行真实数据库与外部系统联调的后端实现。

## 1. 当前后端事实

仓库已经具备：
- `server/api.mjs` 本地 HTTP API；
- `server/repository.mjs` MEMORY_A 与数据库 Repository；
- `src/services/portal.js` 原型业务服务；
- TODO/MESSAGE 本地 PUSH 接收器；
- P3 PostgreSQL/NocoDB 32表结构；
- Mock、Fixture、审计样本与测试。

但当前实现不是最终后端：

1. 默认 `npm run api` 使用进程内 MEMORY；
2. DB 模式仍以 `system_config.P4RUN_STATE` JSON 快照作为主要运行状态；
3. Session 保存在 Node 进程 Map，重启即丢失；
4. API 以 `/api/portal/read?resource=` + `/command` 为主；
5. 门户访问主体与门户管理用户仍共用 `state.users`；
6. 权限使用粗粒度 scopes；
7. TODO/MESSAGE 外部接入当前使用 Bearer 环境变量；
8. SSO 尚未实现一次性 Ticket；
9. 应用进入仍依赖单一 `app.runtimeStatus`。

后续应保留当前原型作为回归参考，但不要继续在通用 command 服务上无限叠加正式后端能力。

## 2. 推荐后端形态

首期采用模块化单体：

```text
HTTP / REST API
      ↓
Authentication / Session / RBAC
      ↓
Domain Services
  ├─ Identity
  ├─ Admin User / RBAC
  ├─ Application
  ├─ Integration
  ├─ Mapping
  ├─ Todo
  ├─ Message
  ├─ Announcement
  ├─ Audit
  └─ Monitor
      ↓
Repository / Transaction
      ↓
PostgreSQL
```

闽政通、闽政务、子系统等采用 Adapter，避免把某一外部协议直接写进核心业务层。

## 4. BE-00 后端基础框架

建立：
- 统一成功/失败响应；
- 401/403 语义；
- Trace ID / Request ID；
- 参数校验；
- OpenAPI 3.x；
- 日志脱敏；
- 统一异常处理；
- Repository 事务边界；
- DEV/TEST/UAT/PROD 环境配置。

验收：
- 前端不再解析 message 文本判断业务；
- 每个请求可通过 traceId 定位；
- 用户端、管理端、外部 integration API 路由域分开。

## 5. BE-01 Schema / Migration

依据《数据库Schema设计》执行 005～010。

要求：
- 先在数据库副本演练；
- 不改写 001～004；
- 每阶段具备验证 SQL；
- 删除旧表放在最后；
- 不影响 0.3.0-A Mock 回归。

## 6. BE-02 Session 与认证主体

实现：
- 持久化 Portal Session；
- EXTERNAL 普通访问主体会话；
- EXTERNAL 门户管理员会话；
- LOCAL 门户管理账号会话；
- logout/revoke；
- Session TTL；
- `GET /api/auth/me`。

返回至少包含：
- accessSubject（可空）；
- adminUser（可空）；
- adminAccess；
- roles；
- permissions；
- authType；
- identitySource。

LOCAL 管理账号不得再伪造 unified_user。

## 7. BE-03 门户管理用户与 RBAC

实现：
- portal_admin_user CRUD；
- LOCAL credential；
- 密码失败锁定/重置；
- 角色与权限；
- 最后一个有效超级管理员事务保护；
- 管理 API 权限中间件。

权限粒度改为 `resource:action`，正式后端不继续使用前端粗粒度 scopes 作为安全边界。

## 8. BE-04 应用与接入配置

实现：
- application CRUD / 启停；
- application_integration 三类能力；
- 配置完整性计算；
- Secret 引用；
- 连接测试；
- runtime_status 计算；
- integration_event。

原则：
- application.enabled 与 integration.enabled 分离；
- runtime_status 禁止管理端直接写；
- 应用列表若继续展示综合运行状态，应由后端派生。

## 9. BE-05 应用访问与账号映射

实现：
- DIRECT / BIND / REQUEST；
- application_access_request；
- application_access_grant；
- account_opening_request；
- application_user_mapping；
- 候选发现；
- VERIFYING / REVIEWING / BOUND / FAILED / CONFLICT；
- 管理审核、解绑、冲突处理；
- 全程审计。

门户只管理入口资格与映射，不创建子系统业务权限。

## 10. BE-06 TODO / MESSAGE

### TODO
- 列表、详情；
- PUSH upsert；
- 状态同步；
- 幂等；
- 来源更新时间/乱序保护；
- “去处理”只生成跳转，不改业务状态。

正式契约移除：
- priority；
- dueAt；
- sourceRevision；
- terminalAt；
- EXPIRED。

### MESSAGE
- 消息本体 + 收件人；
- 未读/已读；
- 批量已读；
- 用户级逻辑删除；
- PUSH 幂等。

## 11. BE-07 公告

实现：
- 草稿；
- 立即发布；
- 定时发布；
- 已发布编辑；
- 撤回；
- 撤回后回草稿或重新发布；
- 失效日期；
- 发布范围；
- 附件；
- 定时任务。

数据库主状态仅 DRAFT/PUBLISHED/WITHDRAWN。API 可以返回 `displayStatus=SCHEDULED/EXPIRED` 以保持当前前端体验。

## 12. BE-08 审计、运行监控、首页

审计：
- LOGIN/AUTH/ACCESS/OPERATION/API/ERROR；
- actor 区分 ACCESS_USER / PORTAL_ADMIN_USER / APPLICATION / SYSTEM；
- 高风险管理写操作记录前后摘要。

运行监控：
- SSO/TODO/MESSAGE 分别统计；
- 最近成功/失败；
- 错误摘要；
- “重新检测”只触发检测，不直接改状态。

管理首页：
- 纳管应用；
- 启用应用；
- 门户访问用户；
- 门户管理用户（如页面需要可单列）；
- 三类接入健康；
- 待处理申请/映射异常。

## 13. BE-09 SSO Ticket

实现：
- 一次性短期 Ticket；
- 生成；
- 服务端校验；
- consumed；
- 过期；
- 重放防护；
- SSO 审计。

进入前校验：
- 应用启用；
- SSO integration 有效；
- 用户适用范围；
- REQUEST grant；
- BIND mapping（如需）。

## 14. BE-10 外部 PUSH 鉴权

替换当前 Bearer 原型：

- X-App-Key；
- X-Timestamp；
- X-Nonce；
- X-Signature；
- X-Request-Id；
- HMAC-SHA256；
- 防重放；
- 限流；
- 幂等；
- Secret 轮换扩展点。

正式路径：
- `POST /api/integration/v1/todos`
- `POST /api/integration/v1/todos/status`
- `POST /api/integration/v1/messages`

## 15. BE-11 上层身份 Adapter

抽象：
- 创建扫码认证；
- 查询扫码结果；
- 手机号认证发起/回调；
- 获取最小身份；
- 认证错误标准化。

没有正式闽政通/闽政务资料前只实现 Adapter 接口和受控 Stub，不伪造真实协议。

## 16. BE-12 子系统联调

按应用逐个建立接入档案，不要求 43 个系统一次开发完成。

每个应用验收：
- SSO；
- TODO；
- MESSAGE；
- 用户标识；
- 测试/生产地址；
- 业务/技术联系人；
- 接入测试；
- 运行监控证据。

未提供能力的项目应明确“待配置/不接入”，不得使用 Mock NORMAL 作为真实接入证明。

## 17. BE-13 数据切换与回归

切换前：
- Mock 回归通过；
- Migration 副本演练通过；
- 新 API 契约测试通过；
- 前端完成必要差异改造；
- 有回滚方案。

切换后：
- 禁止继续以 `system_config.P4RUN_STATE` JSON 快照作为正式业务权威；
- Mock 只保留开发/测试模式；
- 生产运行状态只来源正式数据库和接入检测。

## 18. 推荐顺序

```text
BE-00
  ↓
BE-01
  ↓
BE-02 → BE-03
  ↓       ↓
BE-04 → BE-05
  ↓       ↓
BE-06   BE-07
  └──→ BE-08
        ↓
BE-09 + BE-10 + BE-11
        ↓
      BE-12
        ↓
      BE-13
```

不要先做 43 个系统联调再补身份、映射、权限和幂等基础，否则后续接口与数据模型返工概率很高。
