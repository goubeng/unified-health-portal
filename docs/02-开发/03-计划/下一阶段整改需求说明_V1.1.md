## 1. 最新身份与权限结论

最终身份来源调整为三类：

```text
闽政通 → 公众用户
闽政务 → 政务用户
门户本地 → 门户本地用户
```

用户类别与门户角色必须分开。

默认门户角色只保留：

```text
门户超级管理员
门户管理员
```

不再预置应用管理员、集成管理员、公告管理员、映射管理员、审计管理员等细分角色。

RBAC菜单/页面/操作能力仍保留，未来按实际人数和分工扩展。

## 3. 本地账号方案

### 使用场景

主要面向：
- 项目维护人员；
- 系统管理员；
- 运维人员；
- 不具备闽政通/闽政务账号的门户维护人员。

### 首期限制

- 不开放用户自助注册；
- 仅超级管理员创建本地账号；
- 默认用于管理端；
- 没有管理角色不得进入管理端；
- 本地用户不自动参与普通应用访问。

### 安全要求

- 密码Hash保存；
- 禁止明文；
- 初始密码不入Git；
- 支持首次改密；
- 支持失败计数/锁定；
- 支持超级管理员重置密码；
- 登录/失败/重置必须写审计日志。

## 6. 登录改造

不拆分用户端和平台管理端登录页面，统一保留 `/login`。

登录页三个入口：

- 公众用户 → 闽政通；
- 政务用户 → 闽政务；
- 管理账号 → PORTAL_LOCAL账号密码。

认证成功后统一建立Portal Session：

- CITIZEN/GOV默认进入用户端；
- CITIZEN/GOV拥有有效管理角色时允许进入/切换平台管理端；
- LOCAL拥有有效管理角色时第一阶段默认进入平台管理端；
- LOCAL没有管理角色不得进入平台管理端。

当前手机号登录滑块下方多余图标/说明继续按已确认要求删除。

A阶段管理账号仅做演示：保留用户账号、登录密码、验证码、登录按钮，但点击登录直接进入默认Mock管理账号，不校验输入、不访问数据库；真实PORTAL_LOCAL认证留B/C阶段。

## 7. 应用访问申请与子系统账号关联

继续按：
- DIRECT
- BIND
- REQUEST

申请只授予门户入口资格，不授予子系统业务权限。

### 7.1 BIND账号关联

实现AUTO / SELF / REVIEW / ADMIN：

- AUTO：可信唯一标识唯一匹配；
- SELF：候选账号 + 二次验证；
- REVIEW：用户完成必要验证后进入管理员审核；
- ADMIN：管理员基于有效依据人工关联。

候选发现可使用姓名+已登记手机号、姓名+工号等，但不得直接建立BOUND。

二次验证优先支持：

1. 子系统跳转认证；
2. 子系统原登记手机号OTP；
3. 闽政通/闽政务重新认证；
4. 子系统账号密码一次性认证；
5. 管理员审核。

必须实现：

- UNBOUND / VERIFYING / REVIEWING / BOUND / FAILED / CONFLICT；
- application_id + external_user_id唯一有效BOUND；
- 已绑定其他用户时禁止自动覆盖；
- 高权限账号可强制REVIEWING；
- 子系统账号状态与映射状态分离；
- 解绑/重绑/冲突处理审计；
- 密码、OTP、Token不落库、不进入日志。

### 7.2 跨身份源关联

如后续需要把CITIZEN/GOV关联为同一自然人：

- 稳定权威跨源ID优先；
- 无稳定ID时只生成候选，不直接合并；
- 使用上层重新认证/更强实名核验完成二次验证；
- 门户不自行保存人脸模板；
- 关联后保留两个identity_mapping及审计证据。

## 7A. 原型Mock演示闭环

本阶段即使不接真实闽政通/闽政务/短信/人脸/子系统接口，也必须在Vue原型中完整实现用户可见交互。

必须覆盖：

- 应用卡片状态驱动：进入/申请使用/关联账号/继续验证/等待审核/重新关联/查看异常；
- REQUEST申请使用弹窗与“我的申请”；
- BIND三步关联向导：查找候选→二次验证→关联结果；
- 手机验证码Mock（演示固定码可使用123456）；
- 原系统账号密码一次性验证Mock；
- 上层重新认证Mock；
- 未找到账号后的“申请开通/前往原系统/联系管理员”；
- 子系统账号开通申请Mock；
- FAILED/CONFLICT/ACCOUNT_DISABLED/MULTIPLE_CANDIDATES等失败分支；
- REVIEWING高权限账号审核；
- 管理端应用访问申请、账号关联审核、冲突处理；
- 用户端与管理端共用Mock数据并实时联动；
- 至少10类固定可复现演示场景。

详细实现以《应用访问与账号关联Mock演示闭环实现方案_V1.0.md》为准。

本阶段不要求真实外部联调，但页面字段、按钮、状态、提示和流程必须完整，后续真实接口只替换Service层。
