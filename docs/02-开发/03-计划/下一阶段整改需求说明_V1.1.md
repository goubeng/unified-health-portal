## 3. 0.3.0-B 数据库统一清理

### 3.1 原则

- P3数据库验收事实保留，不删除历史记录；
- `database/schema.sql`、001/002/003及已验收数据库表示历史P3结构；
- 新目标只通过新的Migration演进，不修改历史Migration伪造“当时就是最新结构”；
- 先做差异清单，再做DDL；
- 所有写入前记录目标base/source/schema、备份/快照和回滚策略。

### 3.2 用户与本地身份

需要确认/落地：

- `unified_user.user_type`支持LOCAL；
- 身份来源支持PORTAL_LOCAL；
- 组织字段允许按当前规则为空；
- LOCAL首次登录、最近登录、门户启用状态等字段；
- 新增`portal_local_credential`；
- password_hash不允许出现在前端DTO、日志或Git；
- 首个超级管理员通过部署期安全方式初始化，不写固定明文密码。

### 3.3 角色与权限

- 默认角色Seed仅保留SUPER_ADMIN / PORTAL_ADMIN；
- 继续保留MENU / PAGE / ACTION；
- 两默认角色首期按ALL_PORTAL；
- 历史细分管理员角色如数据库中仍存在，进入B阶段后按迁移方案处理，不在A阶段直接删数据。

### 3.4 组织与字典

- 门户组织只作为门户索引/LOCAL组织维护能力；
- GOV组织权威来源仍为闽政务；
- CITIZEN不强制组织；
- 补齐统一字典结构；
- 应用分类、公告类型、组织类型逐步归入字典；
- 旧application_category在迁移期间保留兼容，完成数据迁移后再决定退役方式。

### 3.5 应用访问与账号映射

数据库目标需覆盖：

- application.access_mode：DIRECT / BIND / REQUEST；
- application_access_request；
- application_access_grant；
- application_user_mapping最新字段；
- UNBOUND / VERIFYING / REVIEWING / BOUND / FAILED / CONFLICT；
- match_method；
- verification_method；
- verification_status；
- risk_level；
- external_account_status；
- reviewed_by / reviewed_at；
- verified_at；
- conflict_reason；
- application_id + external_user_id的有效BOUND唯一约束；
- 验证过程不得保存明文密码、OTP、Token。

### 3.6 待办字段清理

`todo_item`目标只保留门户聚合和跳转所需最小字段。

0.3.0-B统一删除：

- `priority`；
- `source_revision`；
- `due_at`；
- `terminal_at`。

TODO状态收敛为：

- PENDING；
- COMPLETED；
- WITHDRAWN。

TODO不再使用EXPIRED，也不再生成“逾期”信息。

历史P3数据库和历史Migration当前保持原样，直到B阶段真正执行Migration。

### 3.7 公告

数据库目标补齐：

- SCHEDULED；
- publish_mode；
- scheduled_publish_at；
- submitted_at / submitted_by（如最终实现仍需要）；
- effective_end为空表示永久有效。

删除、撤回、过期等历史记录与留存方式在Migration设计时统一确认。

- loginMethod；
- module；
- page；
- action；
- application；

异常处理如采用结构化字段，补：

### 3.9 历史短信与上层公共服务预留

当前正式口径是：认证二维码、验证码、短信等公共能力优先由上层平台提供，门户不重复建设独立短信费用平台。

B阶段需要统一复核：

- `sms_channel`；
- `sms_template`；
- `sms_application`及相关表；
- `sms.*`系统配置；
- `auth.qr_ttl_seconds`；
- `auth.otp_ttl_seconds`。

处理原则：

- 有明确上层接口依赖的，改为接入配置或删除门户自主管理能力；
- 未取得最终外部资料前，不在A阶段提前删表；
- 不再恢复短信费用统计；
- 不单独设置“短信管理员”默认角色。

### 3.10 Repository正式化

当前 `server/repository.mjs` 中DATABASE模式仍保留 `P4RUN_STATE` 整体JSON快照作为过渡运行状态。

0.3.0-B/C需要逐步改为：

```text
业务表
  ↓
Repository
  ↓
Service
  ↓
API
```

而不是把P4RUN_STATE作为生产业务真相源。
