## B：演示数据与接口模拟完善

A3后按实际演示需要选择性执行，不进行不必要的生产级建设。

### B1 演示数据

- 补齐应用、用户、申请、映射、待办、消息、公告、日志、监控典型数据；
- 每个关键状态至少有可演示样本；
- 保证重新启动后的演示可重复。

### B2 接口模拟

重点不是“真实联调”，而是“模拟方式符合真实技术逻辑”：

- OpenAPI 3.x；
- requestId/traceId；
- AppKey/AppSecret + timestamp + nonce + signature目标设计；
- eventId幂等；
- 标准HTTP状态与错误码；
- TODO终态规则；
- MESSAGE用户级阅读/删除；
- SSO协议/回调/Ticket设计；
- 连接配置字段与接口文档一致。

当前本地Mock接口如采用简化Bearer等方式，必须在文档中清楚标识，并同时给出目标正式鉴权口径。

### B3 数据持久化（可选）

只有演示确实需要重启保留数据时才做：

- 可使用本地PostgreSQL；
- 只实现当前演示模型所需表；
- 页面冻结DTO优先；
- 不要求完成历史P3→生产Schema的全量Migration；
- 不要求NocoDB生产切换；
- 不以生产数据安全/高可用作为本轮目标。
