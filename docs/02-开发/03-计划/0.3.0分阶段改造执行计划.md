## B阶段：0.3.0-B 数据库改造

### 启动前置
必须先完成A阶段验收并冻结前端DTO/状态/Service契约。

### 本阶段内容
- 先对P3历史结构与V20260920-03目标结构做差异清单；
- 新增Migration，不回写或覆盖历史001/002/003；
- Schema/Seed调整；
- PostgreSQL 14约束；
- NocoDB原生表结构同步；
- 本地数据库实际执行；
- 数据库读回、反例验证与回滚验证；
- 将P4RUN_STATE过渡Repository逐步收敛为正式表级Repository。

### 统一清理清单

0.3.0-B启动时至少统一处理以下差异，当前A阶段只登记、不执行：

1. **用户与身份**：确认`unified_user`支持CITIZEN/GOV/LOCAL及PORTAL_LOCAL，外部身份主数据仍只读；
2. **本地凭证**：新增/落地`portal_local_credential`，密码Hash仅服务端保存；
3. **角色与权限**：默认Seed收敛为SUPER_ADMIN / PORTAL_ADMIN，保留MENU/PAGE/ACTION RBAC；
4. **组织与字典**：补齐门户组织索引和统一字典目标结构，迁移期间处理旧分类兼容；
5. **应用访问**：补齐application_access_request / application_access_grant及访问模式字段；
6. **账号映射**：按最新BIND/REVIEW/CONFLICT模型补齐映射、验证证据、风险与外部账号状态字段；
7. **待办**：删除`priority`、`source_revision`、`due_at`、`terminal_at`，TODO状态移除EXPIRED；
8. **公告**：补齐SCHEDULED、publish_mode、scheduled_publish_at等当前目标字段；
9. **审计**：补齐身份来源、登录方式、模块/页面/动作、异常处理等结构化上下文；
10. **历史短信预留**：结合“公共服务优先复用上层平台”的当前口径复核`sms_*`表和`sms.*`配置，删除不再需要的费用/独立平台能力，不在A阶段提前删表；
11. **上层认证参数**：复核`auth.qr_ttl_seconds`、`auth.otp_ttl_seconds`是否仍应由门户持久化，以上层接口最终资料为准；
12. **运行Repository**：正式数据库模式不得继续以`P4RUN_STATE`整包JSON作为生产业务真相源。

上述清理必须在进入B阶段后一次性设计Migration顺序，并保留P3历史验收证据。

### 数据库访问安全标记
任何本地数据库操作必须记录：
1. 执行日期；
2. 执行者/执行环境；
3. 目标base/source/schema；
4. Migration文件及SHA；
5. 是否只读/写入；
6. 执行结果；
7. 回读结果；
8. 回滚/恢复方式。

未取得上述信息或未实际执行时，只能标记：
> **数据库改造：未执行 / 待本地环境验证**

不得因为Git中已有SQL就写“数据库已完成”。
