# 当前 P4/P5 阶段 Gate 复核

> 核对日期：2026-09-24  
> 范围：当前本地数据库演示版本；保留此前 Mock 版人工验收和 P3 验收的历史结论，不将其直接继承为当前版本的 Gate 结论。  
> 状态：演示数据和关键权限已完成本轮收口；当前数据库版本已补多页面浏览器回归及公告草稿 CRUD，但完整业务闭环仍待验证，阶段 Gate 尚未签署。

## 1. 当前结论

| 阶段 | 当前判断 | 已有证据 | 尚缺的 Gate 证据 |
|---|---|---|---|
| P4 可运行原型 | 核心页面和本地读写主体已实现；**当前数据库版本尚不能宣称 Gate 完整通过** | 2026-09-22 的前端人工验收为历史 `MANUAL_PASS`；当前本地 API 为 `DATABASE`。浏览器已验证管理员/公众/内容管理员切换、监控 42 应用及本地演示提示、公众应用多状态、待办/申请/公告、主要管理页和五类审计页；审计字段兼容缺陷已发现并修复 | 当前版本还缺完整页面视觉复核、浏览器网络失败清单与多身份全路由无阻断记录；修复后虽已有定向回归，不能沿用历史全页人工 PASS |
| P5 主要业务闭环 | **进行中，Gate 待验证** | 应用、申请/审批/授权等有服务/HTTP/数据库自动化证据；公告已在当前浏览器以 DATABASE 模式完成草稿新增、刷新读回、编辑、刷新读回和经确认的软删除清理；公众 12/12 差异场景及四态接入数据已再回查 | 公告发布/撤回及附件、申请提交—审核—授权、账号开通/绑定、消息待办读写、异常处理等尚缺当前版本的跨身份浏览器写入闭环；第三方仅为本地模拟，不作为真实联调结论 |

判定口径沿用项目过程教训：P4 关注核心页面无阻断及 Mock/读写可运行，P5 关注主要业务路径完整跑通。真实外部系统接通不是当前高保真原型的 P4/P5 Gate 条件；但“页面可显示”和“单个接口测试通过”也不能替代当前版本的业务闭环验收。

## 2. 已落实的本地演示能力与边界

- 默认 `npm run dev` 使用数据库模式 API；`npm run dev:mock` 才显式使用隔离内存数据。公告、应用/分类、待办/消息、申请/授权/账号开通分别通过业务表持久化；组织、字典、用户、角色、映射、配置及部分演示对象仍使用逐实体 JSONB 兼容表。旧 `P4RUN_STATE` 保留兼容快照和全局版本控制，**不是最终生产关系模型**。
- 真实库已有迁移、备份、读回及精确清理记录，核心 HTTP CRUD 链路已有样本验证；这仅证明所测路径的本地持久化，不证明所有页面、身份和场景都已验收。
- 登录页继续模拟会话，管理员登录不校验数据库用户名/密码；数据库用户用于门户业务身份与演示切换，不等于正式身份认证。
- SSO、TODO、MESSAGE、子系统账号确认及运行状态中的第三方部分仍是本地模拟/接口预留。连接配置和演示样本可接近真实技术契约，但不能称为真实联调、正式 PUSH 或生产监控。
- 2026-09-23 本机优化后，冷读取约 1.1–1.2 秒、同页 6 个并发读取约 1.1 秒、缓存命中单次应用读取约 15 毫秒；这只是当时环境的测量，不是性能验收保证。进程内只读快照最长约 1 秒可见延迟，跨进程写库后的回查需考虑这一点。
- 本轮受保护接入配置事务提交后，`P4RUN_STATE.version=301`；后续浏览器模拟切换写入登录审计，版本号继续递增，301 不是当前固定版本。公众用户 `MOCK_USER_1` 的 12/12 个原先不同的应用访问状态/操作已与原 Mock 场景一致，`APP_3`、`APP_24` 已恢复公众/政务双端范围。冲突关联的 7 条待办、7 条消息已先备份并归档，不再保留错误的当前操作入口；原文可追溯。第三方接入演示配置中 125/126 条完成本地模拟场景同步，`APP_1` 的 TODO 配置因已有成功维护审计而被保护、未覆盖。以上是本地演示状态，不表示第三方接通。
- 当前自动化测试结果为 `227/227` 通过，构建通过。浏览器已验证本地 admin、用户切换列表、内容管理员公告、公众场景状态及内置超级管理员禁降权；续接验证了监控、核心管理/审计页与公告草稿 CRUD。五类审计初查曾因实际 `audit_event.details` 为 text 而读取失败，修复并重启后均能显示数据库数据，浏览器控制台无 error 级记录。以上是定向结果，不能外推为全站浏览器验收。

## 3. 当前阻断与待验证项

1. 已关闭的数据问题：42 份应用场景字段补齐；公众用户 12/12 差异恢复；`APP_3/24` 范围恢复；7+7 关联待办/消息备份归档；125 条接入配置同步，唯一有既有成功维护记录的 `APP_1 TODO` 保持原值。精确结果仍应以当前数据库读回为准，不把本地模拟状态写成真实第三方结果。
2. 已取得的权限证据：数据库本地 admin 可建立 `LOCAL` 管理会话；切换列表包含数据库用户；浏览器验证了内容管理员公告列表可正常加载、公众用户切换到内容管理员后进入管理端，以及内置超级管理员角色控件禁降权。当前管理用户页面/命令没有删除操作，内置本地超级管理员停用和移除超级角色会被服务端拒绝并有专项测试；尚须按当前最终版本复核全部权限边界，不应只凭角色字段推断无误。
3. 页面数据源已完成代码路径审计；管理首页异常数、监控页和五类审计页已在浏览器定向回归，期间发现的审计字段类型问题已修复。尚须对所有现有可见页面的最终运行结果做全量视觉/网络回归；同时区分代码权限字典、数据库业务记录与第三方模拟配置，不能笼统称“所有页面都是真实外部数据”。
4. 数据修复先于业务场景测试的顺序已经遵守；监控页和公众正常/失败/冲突/未接入的显示及入口已实测。但跨身份申请审批、映射处理、待办/消息写入、公告发布/撤回/附件、配置更改和异常处理的页面动作仍未构成完整闭环，不以自动化测试或只读页面替代。此前平台用量审核阻止的监控页已在本轮恢复后验证，不再列为当前阻断。
5. Gate 签署前还需汇总当前版本的全页视觉与 Network 定向回归、上述跨身份写入闭环、自动测试和构建结果，并记录环境、提交号、所用身份与实际结果。`227/227` 测试通过仅是自动化证据，不能直接使 P4/P5 通过。

## 4. 阶段与交付边界

- A1 Mock 前端闭环、A2 既有人工验收是历史事实；A3 当前数据库版本尚未冻结。最小演示持久化已经实施，不能再写为“未启动”；完整生产级 0.3.0-B 数据模型、正式认证与外部 0.3.0-C 联调则仍未完成。
- 当前 `P4/P5` 不以 `.project/project.yaml` 标签或历史 PASS 自动判定；最终状态应在第 3 节各项关闭并取得最新版本证据后复核。
- 用户当前无需把正式第三方凭据、密码或生产对接环境提供给原型；真实联调另立阶段并取得接口资料与授权。
