已经冻结的前端业务模型：

| 范围 | 冻结口径 |
|---|---|
| 门户访问主体 | accessSubject / unified_user，仅 CITIZEN、GOV |
| 门户管理用户 | adminUser / portal_admin_user，authType=EXTERNAL/LOCAL |
| LOCAL | 仅管理端本地认证方式，不是普通访问用户类型 |
| 门户权限 | resource:action permissions 为权威字段 |

| 公告 | status=DRAFT/PUBLISHED/WITHDRAWN + displayStatus=SCHEDULED/EXPIRED |
| Session | accessSubject + adminUser + adminAccess + roles + permissions + authType + identitySource |
| 审计主体 | ACCESS_USER / PORTAL_ADMIN_USER / APPLICATION / SYSTEM 目标语义 |

## 2. 本轮前端收口完成项

### 2.1 管理用户与访问主体
- 管理端“用户管理”只按门户管理用户语义展示。
- 管理用户页面字段为：管理账号、姓名、认证类型、身份来源、门户角色、启用状态、最近管理端登录。
- 本地管理账号通过 authType=LOCAL 表达，不再使用 userType=LOCAL 作为页面/DTO身份类别。
- “身份与子系统映射”只处理 CITIZEN/GOV 访问主体。
- 停用外部管理资格不影响对应访问主体继续使用用户端。

### 2.2 权限
- RoleManagement 已按菜单 → 页面 → 操作维护 resource:action permissions。
- 页面、路由、按钮和 Mock Service 已优先使用 permission code。
- 新 Seed 与新写入不再生成 scopes。
- permissionsFromScopes 仅保留为读取历史 Mock/旧缓存数据的兼容适配，不属于冻结 DTO，也不得进入正式 REST API。

### 2.3 应用与接入
- 应用页面/卡片使用 enabled 判断启停。
- 应用列表展示 aggregateRuntimeStatus，不把单一 runtimeStatus 当应用权威字段。
- SSO/TODO/MESSAGE 统一使用 configStatus / enabled / runtimeStatus。
- connection/configuration/status 等旧接入字段不再作为页面 fallback。
- 运行监控状态由 Service 派生，页面不能直接写 NORMAL。

### 2.4 TODO / MESSAGE
- TODO 页面只保留标题、来源应用、业务类型、状态、接收时间、待办说明和去处理。
- TODO 列表/详情统一使用 receivedAt。
- MESSAGE 列表/详情统一使用 receivedAt。
- 消息删除在 Mock Service 中保持当前用户级逻辑删除语义。

### 2.5 公告
- 持久化主状态按 DRAFT/PUBLISHED/WITHDRAWN 语义处理。
- SCHEDULED/EXPIRED 通过 displayStatus 派生展示。
- publishMode / scheduledPublishAt / effectiveEnd 已进入前端契约。

### 2.6 Session
前端运行态已消费拆分 Session：
- accessSubject；
- adminUser；
- adminAccess；
- roles；
- permissions；
- authType；
- identitySource。

正式 /api/auth/me 路由和持久化 Session 留 B/C 阶段实现，页面不再要求回到旧的单 actor 数据模型。

## 3. A阶段仍保留但不进入正式 DTO 的兼容层

以下内容是为了保持当前 Mock/历史 P3 可回归，不代表目标数据结构：

1. Mock 内部 state.users 仍是单数组存储访问用户和管理用户；对页面输出已拆分语义。B阶段物理落库时改为 unified_user + portal_admin_user。
2. pages.js / portal.js 允许读取历史 scopes 并转换为 permissions；新 Seed、新角色保存、新用户授权不再写 scopes。
3. repository.mjs 的 api:db 镜像逻辑仍适配 P3 历史数据库旧字段。A阶段禁止运行 api:db，B阶段由 005～010 Migration 后替换。
4. 当前 API 仍是 /api/portal/read + /command，本地 Session 仍为进程内 Map。
5. TODO/MESSAGE 外部 PUSH 仍是本地兼容路径 + Bearer；正式 /api/integration/v1/* 与签名鉴权属于 C阶段。
