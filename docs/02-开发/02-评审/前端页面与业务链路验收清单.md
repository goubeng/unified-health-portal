## 1. 验收结论规则

每一项记录以下状态：

- **PASS**：页面、交互、状态与当前需求一致；
- **FAIL**：存在可复现问题，需要修复；
- **BLOCKED**：受本地环境或缺失演示数据阻塞；
- **N/A**：当前原型范围明确不验。

A2通过条件：

- P0页面无阻塞性FAIL；
- 核心业务链路全部PASS；
- 无持续白屏、路由错误、异常空态、关键按钮失效；
- 控制台无影响演示的未处理异常；
- 非预期4xx/5xx清零；
- 下载接口文件可解析；
- npm test、npm run build通过。

## 2. 验收前准备

1. 执行 `npm ci`；
2. 终端1执行 `npm run api`；
3. 确认 `/api/portal/health` 返回 `repository=MEMORY_A`；
4. 终端2执行 `npm run dev`；
5. 浏览器访问 `http://127.0.0.1:4010`；
6. 打开DevTools Console和Network；
7. 验收期间禁止使用 `npm run api:db`；
8. 每发现一个问题记录：页面、操作步骤、实际结果、预期结果、截图、严重级别。

## 5. 接口模拟与下载文件验收

### 5.1 下载文件

从“应用列表 → 下载接口文件”执行：

- [ ] 文件可以正常下载；
- [ ] JSON/YAML语法正确；
- [ ] `openapi` 为3.x；
- [ ] Swagger Editor / Swagger UI可以打开；
- [ ] Postman可以导入；
- [ ] 包含服务器地址；
- [ ] 包含TODO接口；
- [ ] 包含MESSAGE接口；

- [ ] 包含成功/错误响应；
- [ ] 包含示例数据；
- [ ] 包含鉴权说明；
- [ ] 包含幂等规则；
- [ ] 明确当前Mock接口与目标正式接口的边界；
- [ ] 文档字段与“连接配置”页面一致。

### 5.2 TODO Mock接口

至少验证：

1. 正常PENDING推送；
2. 相同eventId+相同载荷重复推送保持幂等；
3. 相同eventId+不同载荷返回冲突；
4. 无效用户/映射返回明确错误；
5. 接入停用返回403类语义；
6. PENDING→COMPLETED；
7. 终态不允许无规则回退。

### 5.3 MESSAGE Mock接口

至少验证：

1. 正常消息推送；
2. 重复eventId不产生重复消息；
3. 用户阅读状态不被重复推送重置；
4. 用户删除后不因重复eventId重新出现；
5. 非法接收人返回明确错误。

### 5.4 SSO配置真实性

人工检查连接配置是否至少具有：

- 协议；
- clientId/应用标识；
- authorizeUrl；
- tokenUrl（需要时）；
- callbackUrl；
- credentialRef；
- 启用状态；
- 配置状态；
- 运行状态；
- 错误/说明。

SSO当前允许只做配置与跳转模拟，不要求真实Ticket服务上线，但页面和文档不能把模拟成功写成真实连通。
