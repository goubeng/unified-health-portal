# 状态机（V1.0）

> 基线：V20260920-03。

## 1. 门户本地账号

门户用户启用状态：

```text
ENABLED ↔ DISABLED
```

登录锁定属于凭证安全状态，不改变用户启停状态：

```text
可登录
→ 连续失败达到阈值
→ 临时锁定
→ 到时自动解锁 / 超级管理员解锁
→ 可登录
```

密码：

```text
初始/重置密码
→ must_change_password=true
→ 用户修改密码
→ must_change_password=false
```

本地账号删除策略首期优先停用，不要求物理删除。

## 2. 门户角色

角色：
```text
ENABLED ↔ DISABLED
```

用户必须至少拥有一个有效管理角色才能进入管理端。

默认角色：
- SUPER_ADMIN
- PORTAL_ADMIN

## 3. 应用访问申请

```text
PENDING
├─ APPROVED
├─ REJECTED
└─ WITHDRAWN
```

授权：
```text
ACTIVE → REVOKED / EXPIRED
```

## 4. 公告

```text
DRAFT

SCHEDULED
├─ PUBLISHED
└─ DRAFT

PUBLISHED
├─ PUBLISHED
├─ WITHDRAWN
└─ EXPIRED
```

## 5. 子系统映射

```text
UNBOUND
  ↓ 查找候选/发起关联
VERIFYING
  ├─ 验证失败 → FAILED
  ├─ 重复绑定/多候选冲突 → CONFLICT
  ├─ 普通账号验证通过 → BOUND
  └─ 高权限/风险策略 → REVIEWING
                         ├─ 审核通过 → BOUND
                         └─ 审核拒绝 → FAILED

BOUND
  └─ 合法解绑 → UNBOUND
```

规则：

- 姓名+手机号只用于候选匹配，不触发UNBOUND直接到BOUND；
- VERIFYING必须存在实际验证依据；
- 同一application_id + external_user_id不能同时处于多个有效BOUND；
- 已绑定其他用户时进入CONFLICT，不自动覆盖；
- 子系统账号ACTIVE/DISABLED/UNKNOWN是独立账号状态，不复用binding_status；
- BOUND账号被子系统停用时，映射可以保留，但enterApp必须拒绝；
- 解绑、重绑、审核和冲突解决均写审计。

LOCAL首期默认无子系统映射需求。

## 6. 待办

PENDING → COMPLETED / WITHDRAWN / EXPIRED。

门户“去处理”不改变业务状态。

## 7. 消息

UNREAD → READ。

## 8. 异常日志

OPEN → RESOLVED。
