# 子系统统一接入规范

## 1. 范围

42 个业务子系统按应用维度纳管。每个应用的 SSO、TODO、MESSAGE 能力独立配置、独立启停、独立监控。

## 2. 基础资料

每个真实应用至少登记：
- applicationCode；
- 正式名称；
- 适用用户；
- 测试/生产地址；
- 业务/技术联系人；
- SSO 方式；
- TODO 是否接入；
- MESSAGE 是否接入；
- 用户标识规则；
- 账号验证/开户注册方式；
- 验收证据。

没有正式资料时只能标为“待核验”，不得用 Mock 名称宣称 43 个真实系统已接入。

## 3. 外部调用鉴权

子系统调用门户使用：
- X-App-Key；
- X-Timestamp；
- X-Nonce；
- X-Signature；
- X-Request-Id。

建议 HMAC-SHA256 签名。生产与测试环境必须使用不同凭证。

## 4. 安全要求

- 正式环境使用 HTTPS；
- Timestamp + Nonce 防重放；
- 可叠加 IP 白名单，但不能替代签名；
- AppSecret 不得明文回显；
- 子系统密码、OTP、Token 不持久化到门户普通业务表和日志。

## 5. 接入生命周期

```text
未配置 → 配置 → 联调测试 → 启用 → 正常运行
                         ↓
                       异常
                         ↓
                    修复/重检 → 正常
```

运行状态统一：UNCONFIGURED / DISABLED / NORMAL / ABNORMAL。

## 6. 用户定位

TODO/MESSAGE 不允许只使用姓名定位用户。优先采用上层稳定身份ID；若只能依赖子系统账号，则先通过 USER_APP_MAPPING 建立可信映射。

## 7. 门户边界

门户负责：
- 统一入口；
- 身份衔接；
- 待办/消息汇聚；
- 映射与运行监控。

子系统负责：
- 自身账号；
- 业务角色/权限；
- 业务流程；
- 待办最终业务状态；
- 是否允许开户注册。

## 8. 重试与失败

网络超时、503 等可指数退避重试；认证失败、签名失败、业务校验失败不得盲目重试。多次失败应进入失败队列并保留 requestId、错误码、重试次数和最近失败时间。

## 9. 运行监控

SSO/TODO/MESSAGE 分别监控。一次瞬时失败不必立刻永久置为异常，应按连续失败次数和时间窗口判定，并允许健康检测成功后自动恢复 NORMAL。
