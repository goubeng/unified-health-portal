# 数据设计（V1.0 目标增量）

> 目标设计：V20260921-01。历史 P3 数据库验收事实保留；本文件描述 0.3.0-B 及以后目标结构，Migration 完成前不得宣称已落库。

## 1. 核心调整

原设计将 CITIZEN/GOV/LOCAL 放在同一个 unified_user 中，并直接通过 portal_user_role 给统一用户授权。

本轮确认改为：

```text
外部身份
→ unified_user（门户访问主体，仅 CITIZEN/GOV）
                     │
                     ├→ application_user_mapping
                     ├→ todo_item
                     └→ message_recipient
                     │
                     └→ 可选绑定 portal_admin_user
                                      │
                                      └→ portal_admin_user_role
                                              → portal_role
                                              → portal_role_permission
```

门户本地管理账号不再作为第三类普通访问用户。

## 2. unified_user

继续复用现有表作为用户端访问主体索引。

目标：
- user_type 仅 CITIZEN/GOV；
- identity_source 仅 MINZHENGTONG/MINZHENGWU；
- 外部权威字段只读；
- 保存最小展示/匹配信息；
- first_login_at / last_login_at；
- 不承担管理端角色关系。

现有 LOCAL 记录如已存在，Migration 前先做数据盘点，再迁移到 portal_admin_user。

## 3. portal_admin_user（新增）

建议字段：
- id；
- account/display_account；
- name；
- auth_type：EXTERNAL / LOCAL；
- access_user_id（绑定 unified_user，可空）；
- enabled；
- protected_flag；
- last_login_at；
- created_at/updated_at/version。

约束：
- EXTERNAL 必须绑定有效 access_user_id；
- LOCAL 可不绑定 unified_user；
- 一个外部访问主体原则上最多绑定一个有效 portal_admin_user。

## 4. portal_admin_credential（新增）

仅 LOCAL 管理用户使用：
- id；
- admin_user_id（唯一）；
- username（唯一）；
- password_hash；
- password_algorithm；
- must_change_password；
- failed_login_count；
- locked_until；
- password_updated_at；
- last_login_at；
- created_at/updated_at/version。

password_hash 永不返回前端。

## 5. 门户 RBAC

继续复用：
- portal_role；
- portal_permission；
- portal_role_permission。

原 `portal_user_role.user_id → unified_user` 目标迁移为：

`portal_admin_user_role.admin_user_id → portal_admin_user`

默认 Seed：
- SUPER_ADMIN；
- PORTAL_ADMIN。

第一阶段不引入复杂数据范围。

## 6. application

应用自身只保存：
- code/name/category；
- target_user_type；
- entry_url；
- description；
- enabled；
- 展示排序等。

应用启用状态不等于接入运行状态。

## 7. application_integration（目标统一模型）

建议将当前 sso_config、push_integration_config 的共同管理信息统一抽象为：
- id；
- application_id；
- integration_type：SSO/TODO/MESSAGE；
- connection_mode；
- config_status：UNCONFIGURED/CONFIGURED；
- enabled；
- runtime_status：UNCONFIGURED/DISABLED/NORMAL/ABNORMAL；
- last_check_at；
- last_success_at；
- last_error_code/message；
- config_version；
- created_at/updated_at。

协议特有配置可以保留扩展表或 JSON 配置，但 Secret 只保存 secret_ref。

## 8. application_user_mapping

主体字段改为 `unified_user_id`（访问主体）。

建议状态：
- UNBOUND；
- VERIFYING；
- REVIEWING；
- BOUND；
- FAILED；
- CONFLICT。

继续保留候选匹配、验证方式、风险、子系统账号状态，并保证 application + external_user_id 只有一个有效 BOUND。

## 9. todo_item

保留：
- application_id；
- source_todo_id；
- target_user_id；
- title；
- business_type；
- summary/content；
- status；
- source_created_at/received_at；
- source_updated_at；
- business_url；
- created_at/updated_at/version。

移除：
- priority；
- due_at；
- source_revision；
- terminal_at；
- EXPIRED 状态。

状态：PENDING / COMPLETED / WITHDRAWN。

## 10. message / message_recipient

沿用“消息本体 + 收件人状态”模型。

message_recipient 目标增加：
- deleted；
- deleted_at。

用户删除只做用户级逻辑删除。

## 11. announcement

建议字段：
- status：DRAFT/PUBLISHED/WITHDRAWN；
- publish_mode：IMMEDIATE/SCHEDULED；
- scheduled_publish_at；
- published_at；
- effective_end（NULL=永久）。

“定时发布”和“已失效”优先作为派生展示状态，不强制增加永久主状态。

## 12. integration_event

新增/明确接入事件历史：
- integration_id；
- event_type；
- result；
- http_status；
- error_code/message；
- duration_ms；
- trace_id；
- occurred_at。

application_integration 保存当前状态，integration_event 保存历史。

## 13. audit_event

保留统一审计表，但 actor 需要同时支持：
- access user；
- portal admin user；
- application；
- system。

管理端操作应优先记录 admin_user_id。

## 14. 短信结构收敛

根据当前需求边界：
- 门户不自建短信通道；
- 不做短信费用统计；
- 公众/政务短信验证码依赖上层公共服务。

现有 sms_channel/sms_template/sms_application/sms_send_record/sms_send_attempt 属历史条件预留，0.3.0-B 应评估迁移为“废弃/归档/删除”，不继续作为门户核心 Schema 扩展。

## 15. 0.3.0-B Migration 建议顺序

1. 新增 portal_admin_user；
2. 新增 portal_admin_credential；
3. 新增 portal_admin_user_role；
4. 迁移现有 LOCAL 管理记录与角色；
5. unified_user 收敛为 CITIZEN/GOV；
6. portal_user_role 退役；
7. 应用集成模型收敛；
8. todo_item 删除旧 SLA/版本字段；
9. message_recipient 增加用户级删除；
10. announcement 状态字段收敛；
11. 审计 actor 增强；
12. 历史 sms_* 收敛；
13. Seed/Mock/Test 同步；
14. 完成回滚与数据核验脚本。

不得直接重跑 initial schema 覆盖现有 P3 数据库。
