# 数据设计（V1.0目标增量）

> 基线：V20260920-03。  
> 当前P3数据库验收事实保持不变；本文描述下一阶段目标增量，Migration完成前不得视为已落库。

## 1. 三类用户

统一用户模型支持：

- CITIZEN：闽政通公众用户
- GOV：闽政务政务用户
- LOCAL：门户本地用户

身份来源建议：

- MINZHENGTONG
- MINZHENGWU
- PORTAL_LOCAL

外部用户的权威姓名/手机号/账号仍由外部身份源负责。

LOCAL由门户负责身份资料和登录凭证。

## 2. unified_user调整

现有统一用户表继续作为门户统一索引。

需确保支持：

- user_type = LOCAL
- identity_source = PORTAL_LOCAL（如当前来源字段结构不同，Migration时映射）
- org字段允许NULL
- portal_status
- first_login_at
- last_login_at

本地用户不要求存在identity_mapping到闽政通/闽政务。

## 3. 本地登录凭证

建议新增独立表：

### portal_local_credential

字段建议：

- id
- user_id
- username
- password_hash
- password_algorithm
- must_change_password
- failed_login_count
- locked_until
- password_updated_at
- last_login_at
- created_at
- updated_at
- version

约束：

- user_id唯一
- username唯一
- user_id必须指向LOCAL用户
- password_hash绝不返回前端
- 不保存明文密码
- 失败次数/锁定需要原子更新

## 4. 门户角色

继续复用：

- portal_role
- portal_permission
- portal_role_permission
- portal_user_role

默认Seed只保留：

- SUPER_ADMIN
- PORTAL_ADMIN

不再预置应用/集成/公告/审计等细分角色。

权限类型继续支持：
- MENU
- PAGE
- ACTION

第一阶段两个默认角色数据范围均按ALL_PORTAL。

已有其它data_scope枚举可以兼容保留，但不作为P0页面复杂配置重点。

## 5. 首个超级管理员

不得在Git中保存固定管理员明文密码。

建议初始化方式：

1. Migration/Seed仅创建必要角色；
2. 通过部署环境变量/一次性初始化脚本创建首个LOCAL超级管理员；
3. 初始密码仅交付时生成；
4. 首次登录must_change_password=true；
5. 初始化动作写审计。

## 6. 组织

portal_organization继续作为门户组织索引：

- 政务用户组织优先闽政务；
- LOCAL组织可为空或手动关联；
- CITIZEN不强制组织。

首期组织不作为复杂RBAC数据范围的硬前置。

## 7. 应用访问申请

application增加：
- access_mode：DIRECT/BIND/REQUEST

新增：
- application_access_request
- application_access_grant

入口资格与portal_role分离。

LOCAL首期默认不参与普通应用访问，但数据模型不做物理禁止。

## 8. 字典

新增：
- dict_type
- dict_item

最终迁移：
- 应用系统分类
- 公告类型
- 组织类型

现有application_category迁移期间保留兼容。

## 9. 公告

announcement增加：
- publish_mode
- scheduled_publish_at
- submitted_at
- submitted_by

status增加SCHEDULED。

effective_end=NULL表示永久有效。

## 10. 审计

audit_event.details至少支持：

- userType
- identitySource
- loginSource
- loginMethod
- module
- page
- action
- errorCode
- ip
- client

LOCAL密码登录只记录“PASSWORD”，不得记录密码/Hash。

如需异常处理结构化字段，增加：
- resolved_by
- resolved_at
- resolution_note

## 11. 运行监控

monitor_status.status继续保留为单个SSO/TODO/MESSAGE服务状态。

不新增aggregate status物理字段。

## 12. Migration顺序建议

1. user_type / identity_source兼容LOCAL；
2. portal_local_credential；
3. 默认角色Seed收敛；
4. 权限种子/映射；
5. portal_organization；
6. application access request/grant；
7. dict_type/dict_item；
8. announcement状态与字段；
9. audit增强；
10. Mock/Seed/Test同步。

所有Migration必须可回滚或提供明确恢复策略。
