# 数据设计（V1.0目标增量）

> 基线：V20260920-03。  
> 当前P3数据库验收事实保持不变；本文描述下一阶段目标增量，Migration完成前不得视为已落库。

## 1. 三类用户

统一用户模型支持：

- CITIZEN：闽政通公众用户
- GOV：闽政务政务用户
- LOCAL：门户本地用户

身份来源建议：

- MINZHENGTONG
- MINZHENGWU
- PORTAL_LOCAL

外部用户的权威姓名/手机号/账号仍由外部身份源负责。

LOCAL由门户负责身份资料和登录凭证。

## 2. unified_user调整

现有统一用户表继续作为门户统一索引。

需确保支持：

- user_type = LOCAL
- identity_source = PORTAL_LOCAL（如当前来源字段结构不同，Migration时映射）
- org字段允许NULL
- portal_status
- first_login_at
- last_login_at

本地用户不要求存在identity_mapping到闽政通/闽政务。

## 3. 本地登录凭证

建议新增独立表：

### portal_local_credential

字段建议：

- id
- user_id
- username
- password_hash
- password_algorithm
- must_change_password
- failed_login_count
- locked_until
- password_updated_at
- last_login_at
- created_at
- updated_at
- version

约束：

- user_id唯一
- username唯一
- user_id必须指向LOCAL用户
- password_hash绝不返回前端
- 不保存明文密码
- 失败次数/锁定需要原子更新

## 4. 门户角色

继续复用：

- portal_role
- portal_permission
- portal_role_permission
- portal_user_role

默认Seed只保留：

- SUPER_ADMIN
- PORTAL_ADMIN

不再预置应用/集成/公告/审计等细分角色。

权限类型继续支持：
- MENU
- PAGE
- ACTION

第一阶段两个默认角色数据范围均按ALL_PORTAL。

已有其它data_scope枚举可以兼容保留，但不作为P0页面复杂配置重点。

## 5. 首个超级管理员

不得在Git中保存固定管理员明文密码。

建议初始化方式：

1. Migration/Seed仅创建必要角色；
2. 通过部署环境变量/一次性初始化脚本创建首个LOCAL超级管理员；
3. 初始密码仅交付时生成；
4. 首次登录must_change_password=true；
5. 初始化动作写审计。

## 6. 组织

portal_organization继续作为门户组织索引，而不是所有用户的权威“所属单位”主数据。

规则：
- CITIZEN不要求组织，`unified_user.org_id/org_name`允许NULL；不得为公众用户自动创建“公众服务”等虚拟组织；
- GOV组织优先来自闽政务。仅在上游实际提供时保存必要的组织ID/名称索引或快照，用于门户展示、筛选、公告范围等；门户不拥有该组织主数据维护权；
- LOCAL组织可为空，也可手动关联门户本地组织；
- 组织信息不是统一身份主键，不参与公众用户身份成立条件；
- 如上游组织变化，正式阶段应按同步策略更新门户索引/快照，不由用户在个人中心直接修改。

首期组织不作为复杂RBAC数据范围的硬前置。

## 7. 应用访问申请

application增加：
- access_mode：DIRECT/BIND/REQUEST

新增：
- application_access_request
- application_access_grant

入口资格与portal_role分离。

LOCAL首期默认不参与普通应用访问，但数据模型不做物理禁止。

### 7.1 子系统账号映射增强

application_user_mapping目标增加/规范：

- unified_user_id
- application_id
- external_user_id
- external_account
- binding_method：AUTO/SELF/REVIEW/ADMIN
- binding_status：UNBOUND/VERIFYING/REVIEWING/BOUND/FAILED/CONFLICT
- match_method
- verification_method
- verification_status
- risk_level
- external_account_status
- verified_at
- reviewed_by/reviewed_at
- bound_at/unbound_at
- conflict_reason
- created_at/updated_at/version

约束：

1. 同一 application_id + external_user_id 最多一个有效 BOUND 映射；
2. 已BOUND到其它unified_user时不得自动覆盖，必须进入CONFLICT/mapping_exception；
3. external_account_status与binding_status分离，子系统账号停用不自动删除映射历史；
4. 用户输入的子系统密码和OTP不得落库；
5. 关联、审核、解绑、重绑和冲突处理必须审计。

### 7.2 候选匹配与验证证据

候选匹配不是绑定。建议至少记录：

- match_method：TRUSTED_ID/NAME_PHONE/NAME_EMPLOYEE_NO/ACCOUNT/MANUAL
- verification_method：SUBSYSTEM_REDIRECT/SUBSYSTEM_OTP/UPSTREAM_REAUTH/SUBSYSTEM_CREDENTIAL/ADMIN_REVIEW
- verification_status：PENDING/PASSED/FAILED/REVIEW_REQUIRED
- verified_source
- verified_at
- risk_level：NORMAL/HIGH

姓名+手机号仅用于候选发现。SUBSYSTEM_OTP必须发送至子系统已有账号登记手机号。

如需要保留多次验证证据和失败历史，新增目标表 application_mapping_verification_event：

- id
- mapping_id或binding_request_id
- application_id
- unified_user_id
- external_user_id
- match_method
- verification_method
- verification_status
- verified_source
- risk_level
- details（不得包含密码、OTP、Token）
- created_at

### 7.3 跨身份源用户关联

CITIZEN/GOV如未来需要合并到同一自然人索引，不得仅凭姓名+手机号自动合并。建议采用候选匹配 + 上层重新认证/更强身份核验，并保存关联依据和审计记录。稳定权威跨源ID优先级最高。

## 10. 审计

audit_event.details至少支持：

- userType
- identitySource
- loginSource
- loginMethod
- module
- page
- action
- errorCode
- ip
- client

LOCAL密码登录只记录“PASSWORD”，不得记录密码/Hash。

如需异常处理结构化字段，增加：
- resolved_by
- resolved_at
- resolution_note

## 11. 运行监控

monitor_status.status继续保留为单个SSO/TODO/MESSAGE服务状态。

不新增aggregate status物理字段。

## 12. Migration顺序建议

1. user_type / identity_source兼容LOCAL；
2. portal_local_credential；
3. 默认角色Seed收敛；
4. 权限种子/映射；
5. portal_organization；
6. application access request/grant；
7. dict_type/dict_item；
8. announcement状态与字段；
9. audit增强；
10. Mock/Seed/Test同步。

所有Migration必须可回滚或提供明确恢复策略。
