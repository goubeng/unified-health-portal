## 2. 三层系统定位

统一门户处于身份来源与各业务子系统之间，三层关系固定为：

```text
身份来源层
├─ 闽政通 → 公众用户
└─ 闽政务 → 政务用户
        ↓
卫健统一门户
统一认证承接 / 最小身份索引 / 门户角色权限 / 应用入口资格
账号映射 / 待办聚合 / 消息聚合 / 公告 / 运行监控 / 日志审计
        ↓
各业务子系统
子系统账号 / 开户 / 业务角色 / 业务菜单 / 业务数据权限 / 业务审批
```

### 2.1 身份来源层

- 闽政通是公众用户的身份来源。
- 闽政务是政务用户的身份来源。
- “闽政通 / 闽政务”是身份来源，不是门户角色。
- “公众用户 / 政务用户”是用户类别，不是门户角色。
- 姓名、账号、手机号、身份可用性等权威身份资料以对应身份来源为准。

### 2.2 卫健统一门户

门户作为中间层负责：

- 承接闽政通 / 闽政务认证结果；
- 建立最小统一身份索引；
- 记录身份来源和用户类别；
- 管理门户自身用户访问状态；
- 管理门户自身角色、菜单、页面、操作权限和门户数据范围；
- 管理应用目录、应用入口资格及应用访问申请；
- 维护用户与下层子系统账号之间的映射关系；
- 汇聚子系统待办和消息；
- 管理门户自产公告；
- 配置 SSO / TODO / MESSAGE 接入；
- 提供运行监控和日志审计。

### 2.3 各业务子系统

下层子系统继续独立负责：

- 子系统账号；
- 子系统开户；
- 子系统业务角色；
- 子系统菜单权限；
- 子系统业务数据权限；
- 子系统内部业务审批与业务状态。

门户不得将自身“系统角色”扩展解释为子系统业务角色。

## 3. 权限模型

门户采用 RBAC：

```text
统一身份用户
  ↓
门户用户状态
  ↓
门户系统角色
  ↓
菜单权限 + 页面权限 + 操作权限 + 门户数据范围
```

关键约束：

1. 用户类别由身份来源确定：闽政通=公众用户，闽政务=政务用户。
2. 用户类别与门户角色是两个维度，不互相替代。
3. 门户角色只作用于统一门户中间层。
4. 普通用户访问用户端不需要创建“公众角色”或“政务角色”。
5. 管理端能力由门户系统角色授予。
6. 应用访问授权是应用入口资格，不是门户角色，也不是子系统角色。
7. 门户数据范围只控制门户自身管理数据，不控制子系统业务数据。

## 6. 用户、角色与组织

### 6.1 用户管理

用户管理维护门户中间层信息：

- 门户启用状态；
- 门户系统角色；
- 门户组织索引；
- 门户应用管理范围。

不得修改：

- 闽政通 / 闽政务身份来源；
- 公众 / 政务用户类别；
- 上游权威姓名、手机号、账号；
- 子系统业务角色和业务权限。

### 6.2 角色管理

角色管理只定义统一门户内部权限。

角色字段：

- 角色编码；
- 角色名称；
- 角色说明；
- 启用状态；
- 菜单权限；
- 页面权限；
- 操作权限；
- 门户数据范围；
- 已关联用户。

### 6.3 组织管理

组织是门户使用的组织索引，主要服务于：

- 政务用户组织归属；
- 管理员门户数据范围；
- 公告组织范围；
- 门户查询与统计。

政务用户组织优先来源于闽政务。公众用户不强制要求存在组织；若闽政通未来提供可信稳定组织信息，可按来源接入。

## 7. 应用访问申请与授权

应用访问模式：

- DIRECT：满足门户基本条件后直接进入；
- BIND：需要先完成子系统账号关联；
- REQUEST：需要先完成门户应用访问申请。

申请通过只产生“门户应用入口资格”，不会授予子系统业务角色、菜单或数据权限。

## 8. 管理首页

调整为：

1. 平台概览；
2. 接入运行；
3. 管理待办；
4. 快捷入口。

不展示短信费用统计。

## 9. 登录页

- 公众登录对应闽政通；
- 政务登录对应闽政务；
- 保留扫码 / 手机号登录；
- 手机号登录保留滑块本体；
- 删除滑块下方“按住滑块向右拖动 / 已通过人机验证”图标和文字；
- 真实认证仍待闽政通 / 闽政务接口联调。

## 10. 公告管理

状态：

- DRAFT 草稿
- SCHEDULED 定时发布
- PUBLISHED 已发布
- WITHDRAWN 已撤回
- EXPIRED 已失效

保存=草稿；提交=立即发布或定时发布。失效时间为空表示永久有效。

支持：

- 已发布编辑；
- 已撤回删除；
- 预览；
- .docx正文导入；
- 富文本正文插图；
- 附件。

## 11. 字典管理

新增统一字典管理。

最终纳入字典的业务配置包括：

- 应用系统分类；
- 公告类型；
- 组织类型；
- 其它允许业务维护的下拉项。

启停状态、运行状态、公告生命周期、映射状态、待办状态、消息阅读状态、接入协议等可进入统一字典展示体系，但属于系统受控字典，不能通过页面自由增加程序未支持的新状态或协议。

## 12. 日志审计

数据库保留稳定英文枚举，前端统一中文显示。

登录日志必须能够区分：

- 用户类别：公众用户 / 政务用户；
- 身份来源：闽政通 / 闽政务；
- 登录来源：门户直接访问 / 闽政通跳转 / 闽政务跳转；
- 登录方式：扫码 / 手机号 / 上层免登。

操作日志必须说明：谁、何时、在哪个模块/页面、对什么对象执行了什么操作、结果如何。

## 13. 运行监控

运行监控按应用分别展示：

- SSO
- TODO
- MESSAGE

详情不再重复展示由三类连接状态聚合出的无必要“状态”字段。

数据库 `monitor_status.status` 继续保留，因为其含义是某一个具体服务的运行状态。

## 14. UI与加载规则

- Vue + Vite + TDesign；
- 13px基准字号；
- 弹窗垂直居中；
- 页面级按钮放标题右侧；
- Loading / Empty / Error严格区分；
- 首次数据未加载完成前不得显示“暂无符合条件”。
