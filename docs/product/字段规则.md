# 字段规则

> P2字段规则用于页面和原型统一，不等同于P3数据库Schema。

# 1. 通用字段规范

| 类型 | 规则 |
|---|---|
| ID | 页面可展示业务编号时优先展示业务编号；内部ID默认不直接暴露给普通用户 |
| 编码 | 使用大写英文/数字/下划线或项目统一编码规则；系统编码需全局唯一 |
| 名称 | 中文展示名清晰、不可只显示技术代码 |
| 时间 | 列表统一 `YYYY-MM-DD HH:mm:ss`；纯日期 `YYYY-MM-DD` |
| 时区 | 页面统一按项目部署时区展示，接口内部时区策略后续确定 |
| 布尔值 | 页面优先使用开关/是-否，不显示 `true/false` |
| 状态 | 使用统一Tag组件；业务状态与运行状态不得混用 |
| 排序 | `sort_order` 类字段数值越小越靠前，页面可使用数字输入 |
| 备注 | 非必填，多行文本，避免承载结构化信息 |
| URL | 页面显示时允许复制；对用户业务跳转必须校验为已配置目标 |
| 分页 | 管理列表默认10条，可切换20/50 |
| 空态 | 使用统一Empty组件，不重复渲染图标/文案 |

# 2. 敏感字段

| 字段类型 | 页面规则 |
|---|---|
| 手机号 | 普通列表脱敏，例如 `138****1234` |
| Client Secret / App Secret | 保存后不回显明文，仅显示“已配置”或掩码；只允许重置 |
| Token | 不在普通页面展示完整值 |
| 子系统外部账号 | 普通用户可查看自己的账号；管理端按权限显示/脱敏 |
| 身份证件等上层身份敏感信息 | P2默认不纳入门户展示；确需使用需另行确认 |

# 3. 登录与身份字段

- `unified_user_id`：门户统一身份标识，页面只读。
- `identity_source`：公众侧/政务侧，使用固定枚举。
- `user_type`：公众/政务，避免与“门户角色”混用。
- `org_name`：来自上层身份摘要，门户不提供编辑。
- 手机号仅用于认证入口，不作为统一用户唯一主键。

# 4. 应用字段

## 应用自身状态
- `ENABLED`：启用；
- `DISABLED`：停用。

## 运行/接入状态
- `NORMAL`；
- `ABNORMAL`；
- `UNCONFIGURED`；
- `DISABLED`。

## 用户账号关联状态
- `UNBOUND`；
- `VERIFYING`；
- `BOUND`；
- `FAILED`；
- `CONFLICT`。

三类状态必须分别展示，不得复用一个字段/Tag语义。

“我的应用”：
- 不提供收藏字段；
- 不提供收藏/取消收藏按钮；
- DEMO按已关联、已开通、最近访问等规则生成列表。

# 5. 待办PUSH字段规则

P2接口/页面至少抽象以下业务字段，具体API Schema留后续阶段：

| 字段 | 规则 |
|---|---|
| source_system_code | 来源系统编码，必须可识别接入应用 |
| source_todo_id | 子系统原待办ID；与来源系统组合用于幂等 |
| target_user_key | 目标用户标识；具体映射键后续接口阶段确定 |
| title | 必填，简洁描述待办 |
| business_type | 业务类型，用于筛选 |
| summary | 摘要，可选 |
| status | PENDING/COMPLETED/WITHDRAWN/EXPIRED |
| priority | 可选，统一映射高/中/低或枚举 |
| created_time | 子系统业务创建时间 |
| due_time | 可选 |
| business_url | “去处理”目标地址 |
| updated_time | 子系统最后更新时间 |

规则：
- 仅支持子系统主动PUSH；
- 重复PUSH必须按来源系统+源待办ID进行幂等处理；
- 点击“去处理”不得把状态改为已处理；
- 已处理待办留存周期读取平台配置。

# 6. 消息PUSH字段规则

| 字段 | 规则 |
|---|---|
| source_system_code | 来源系统编码 |
| source_message_id | 子系统原消息ID；与来源系统组合用于幂等 |
| target_user_key | 目标用户标识 |
| message_type | 业务通知/系统通知/账号通知/安全提醒/待办提醒/其他 |
| title | 必填 |
| content | 必填正文 |
| business_url | 可选 |
| created_time | 子系统产生时间 |
| read_status | 门户侧UNREAD/READ |

规则：
- 仅支持子系统主动PUSH；
- 消息留存周期配置化；
- 是否向子系统回传已读状态后续确认；
- 待办本体进入待办中心，避免无规则复制成普通消息。

# 7. 通知公告字段规则

- 标题：必填。
- 公告类型：字典化。
- 正文：必填，富文本能力按Base Project选型。
- 发布范围：全部用户/公众用户/政务用户/指定组织（指定组织能力依赖上层组织信息可用性）。
- 生效时间、失效时间：可配置。
- 状态：DRAFT/PUBLISHED/WITHDRAWN/EXPIRED。
- 附件：**支持**。
  - 支持多个附件；
  - 页面至少显示文件名、大小、上传时间、下载操作；
  - 文件大小/类型限制作为配置或后续安全策略确定；
  - DEMO使用Mock上传或本地模拟，不在P2确定对象存储方案。

# 8. 上层公共服务字段规则（条件）

仅当门户需要参与上层短信等公共服务调用链路时适用：

- 服务地址、AppKey/ClientId、Secret/Token等按上层契约维护。
- Secret/Token保存后不回显明文，只允许重置/更新。
- 手机号等敏感目标信息仅在门户确有调用职责时处理，并按最小化原则脱敏/加密。
- 不在门户定义短信费用字段或费用统计口径。
- 不默认建设短信模板审批、短信渠道运营管理字段。
- 调用结果仅保存必要状态、错误摘要、请求关联ID等审计信息。


# 9. 配置项规则

P2/P3固定存在以下门户自身配置入口，但**默认值不冻结**；二维码、验证码等上层认证参数不由门户重复配置：

| 配置项 | 说明 |
|---|---|
| 消息保留周期 | 单位：天 |
| 已处理待办留存周期 | 单位：天 |
| 日志保留周期 | 单位：天 |
| Session有效期 | 单位：分钟/小时 |
| 登录失败限制 | 次数/窗口 |
| 接口默认超时 | 后续接口实现使用 |
| 接口默认重试 | 后续接口实现使用 |
| 监控异常阈值 | 后续监控使用 |

DEMO允许使用示例值，但必须标注为“示例配置”，不得写成正式业务约束。

## 页面校验补充

- 应用/分类/角色/模板的编码和名称为必填；编码去首尾空白后校验唯一，失败保留输入；长度上限待接口契约确定，不编造数据库字段长度。
- 手机号、验证码必填；号码格式按身份平台确认的支持范围校验，不以手机号推断统一身份。
- 时间范围起始不得晚于结束；公告填写失效时间时必须晚于生效时间；未设生效时间按发布时生效，未设失效时间不自动过期。用户可见性同时检查发布状态、有效期、发布范围。
- 排序为整数；留存周期、有效期、重试限制按各配置项明确单位并校验数值；零是否表示禁用/无限期未确认前不得自行解释或写入生产配置。
- 附件记录至少具备文件名、大小、上传时间及受控下载标识；不将浏览器临时File直接当持久化附件。附件上传失败时草稿保留，但不可发布。文件大小/类型阈值待确认。
- 子系统账号解绑后的状态为UNBOUND，“已解绑”是动作历史，不新增DEMO枚举；应用DISABLED不等于账号UNBOUND或服务ABNORMAL。
- 消息补充来源类型source_type（PORTAL/SUBSYSTEM）及read_time；门户消息由门户生成稳定标识，子系统消息保留源标识。read_time仅在首次成功已读时记录。
- PUSH去重按来源系统和源事项ID识别；如一个事项有多个接收人，须在契约中明确“事项”和“接收关系”的唯一范围，不得覆盖别人的待办/已读状态。乱序事件不能把终态回退PENDING；判序依据待接口契约确认。
- target_user_key无法唯一匹配时不猜测接收人，不进入任何用户正常列表；返回可定位失败并记录日志，待来源系统修正重推。
- 待办截止时间仅提供逾期提示；EXPIRED由子系统PUSH确认，任何门户自动过期规则须另行确认，保持源业务状态权威。

# 10. 操作履历字段约束

P2只定义统一格式，不展开P6完整事件矩阵：

| 字段 | 规则 |
|---|---|
| 事件编码 | 稳定英文编码，不由页面自由生成 |
| 业务动作 | 新增/编辑/发布/撤回/绑定/解绑/重绑/启用/停用/重发等 |
| 环节 | 使用统一环节名称 |
| 履历内容 | 使用模板生成，不由页面自由拼接 |
| 操作人 | 统一身份/管理员身份 |
| 时间 | 系统记录 |
| 备注 | 可选 |

# 11. UI字段展示统一

- 表格中的长ID、URL、错误信息采用省略+Tooltip/详情查看。
- 状态统一使用Tag，不用彩色纯文本代替。
- 空值统一显示 `--`，不混用空字符串、null、N/A。
- 数字统计统一千分位；比例统一 `%`。
- Dialog/Drawer字段顺序与详情字段顺序保持一致。
