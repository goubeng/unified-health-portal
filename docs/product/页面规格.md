# 页面规格

## 2026-09-19 当前执行规则（优先于以下历史设计）

以《卫健统一门户_需求与修改记录汇总_20260919 .md》及当前用户更正为准：公告/消息在内容区详情页打开，标题前左箭头返回；二维码点击进入、手机号免校验；应用用户端按身份和有效关联展示，管理目录可全量。PG-202内维护三类连接配置，下载门户公共OpenAPI契约；取消独立接入菜单。PG-205聚合两类来源用户及一对多子系统，PG-206/207/208仅兼容入口。任务不显示优先级，消息批量/分页/详情保留最新实现。运行监控按应用展示场景状态，配置与运行分离。下方旧设计中被该记录替代的行为不再实施。

## PG-229 · 管理端公告详情

- 路由：`/admin/announcements/:id`。
- 权限：announcement；当前内容区显示，标题前纯箭头返回列表；正文、范围、发布时间、附件，非详情弹窗。


## 2026-09-18 P4界面规则（优先于旧逐页展示描述）

- 即时查询，查询区置白色表格卡外；无查询/刷新按钮、无左上总数。表格首列序号，分页连续；分页文字13px。
- 第一业务字段为详情链接，行操作区不再放“查看”；详情为带边框网格，消息和个人中心对齐office-house。公告首页/列表均开详情弹窗。
- 首页无统计卡/欢迎概览；待办、消息、公告各最近5条，待办数量及本人未读公告数；我的应用展示可访问目录。
- PG-102/103合并呈现“我的应用+其他应用”，保留两路径兼容但菜单仅一个。目录采用原始需求42个未划除系统，紧凑卡片及即时检索。
- 顶栏TD消息图标小徽标、用户浮窗及用户切换；系统名旁标端名；无面包屑/菜单底部说明。身份源名称为闽政通/闽政务。
- 登录默认公众侧扫码，另支持手机号/滑块/验证码交互；不选择演示身份、不显示模拟文案，注册入口暂隐藏。P4本地模拟、不发送真实短信、不构成生产认证。
- 管理首页以常用操作及异常接入信息为主。技术未接入状态须如实显示，不以去掉“演示”字样声称实际连通。

## PG-228 · 门户用户

- **路由**：`/admin/users`
- **页面目的**：维护门户的用户访问及授权，不重复建设闽政通/闽政务身份主数据。

- **Tabs**：无

- **空态**：暂无符合条件的用户
- **权限**：门户管理员（超级管理权限）
- **数据源**：unified_user及portal_user_role/portal_role_permission；P4 Provider本地等价样本

- 查询区、标题、Tabs、表格、分页、Dialog/Drawer、Tag、Empty 的布局统一。
- 弹窗默认垂直居中；列表操作列保持稳定宽度。
- 列表默认提供序号时由前端计算，不作为业务字段。
- 密钥、手机号、外部账号等敏感信息按字段规则脱敏。
- DEMO Mock 数据集中存放，不在各页面内硬编码重复数据。

# 五、开发所需补充约束（2026-09-17）

以下为P2交互设计，不是已实现或已验收记录。候选管理角色均沿用《角色清单》，不因页面“权限”一栏的简称而认定最终角色划分已冻结。

## 5.1 通用状态与访问

所有37页共用：加载中展示Loading；请求失败展示可重试错误，不伪装成空列表；空数据与筛选无匹配分别提示；未登录/Session失效转登录，回跳地址仅允许已配置目标；无权限展示拒绝访问；记录不存在/已失效不展示陈旧详情。保存失败保留输入，保存期间防重复提交，成功后刷新关联列表。前端按钮可见性不能替代服务端权限和对象归属校验。

查询或切换Tabs回到第一页；同排序值按稳定业务标识排序。DEMO中Top N、预览费用等示例参数须明确标为示例，不形成生产统计口径。DB/API标签描述后续目标数据来源，不代表当前已连数据库或接口。

## 5.2 账号关联弹窗（PG-102/103共享，无新增路由）

| 项 | 规格 |
|---|---|
| 打开条件 | 当前用户已登录、应用启用，映射为UNBOUND/FAILED；CONFLICT转异常处理，不强制覆盖 |
| 字段 | 应用与当前身份只读、子系统账号必填、验证凭据按该系统确认的验证方式动态展示；未提供接口时仅Mock |
| 操作 | 验证并关联、取消；VERIFYING期间禁止重复提交；成功刷新两个应用列表与个人中心 |
| 结果 | BOUND允许发起SSO；FAILED显示失败原因并允许重试；CONFLICT显示联系管理员；无子系统账号展示子系统返回的开户/拒绝结果 |
| 安全边界 | 不保存明文子系统密码，不按姓名/手机号直接合并身份；关闭弹窗清除验证凭据；取消不会证明正在进行的服务端验证已撤销 |
| 自动关联 | 仅在已确认可信唯一标识和子系统支持时启用；未确认时显示未配置，不默认可用 |

## 5.3 页面操作与业务状态

| 页面 | 前置条件与结果 | 异常处理 |
|---|---|---|
| PG-001/002 | 上层已有有效凭证经校验成功直接进入；取消/过期请求结束，重新获取产生新请求 | 未认证、停用、冲突不得建立Session；上层无账号转注册/开通；二维码不可复用 |
| PG-102/103 | 全部应用保留完整目录；停用应用可见但进入按钮禁用；我的应用按关联/已开通/成功访问的并集去重 | 运行异常给出提示；无SSO配置不发起虚构跳转；映射状态不随应用停用改变 |
| PG-104 | 待处理=PENDING；已处理=COMPLETED；全部含WITHDRAWN/EXPIRED；只有PENDING可去处理 | 点击不改状态；超截止时间可显示逾期提示，不自行认定源业务EXPIRED |
| PG-105 | 本人消息详情成功加载后或主动标记才设READ；业务链接再次检查目标 | 加载/标记失败保持原状态并可重试；重复推送不能把READ改回UNREAD |
| PG-106/107/220 | 仅DRAFT可编辑/发布；PUBLISHED可撤回；WITHDRAWN/EXPIRED只读；发布前附件全部完成 | 未到生效时间不展示；撤回/到期后详情及附件入口重新校验；上传失败阻止发布 |
| PG-206/207/208 | 人工操作需门户操作权限及可信核验证据；解绑后UNBOUND；重绑需再次验证 | 不修改上层/子系统用户本体；标记异常已处理不能替代绑定成功；保留处理原因与履历 |
| PG-203 | 分类无应用引用才可删除；保存校验编码唯一 | 被引用时拒绝删除并提示先调整关联 |
| PG-214 | 仅在确认门户需要参与上层公共服务调用时启用；调用规则以正式上层契约为准 | 未配置或无需门户转接时不提供虚构发送/重试能力；UNKNOWN结果不自行判定失败 |
| PG-223～227 | 查看详情使用只读详情弹窗，展示列表字段及脱敏错误上下文 | 异常“标记已处理”仅为运维记录，不代表外部故障恢复 |

## 5.4 尚待工程交接确认

上层身份映射与映射异常是独立对象，其详细流转表由development负责补齐；不把上层“待确认/已解绑”直接写入子系统account_mapping_status。上层公共服务调用的超时/未知结果处理、PUSH乱序及多接收人唯一性由接口契约阶段确定，未明确前不能宣称真实集成验收通过。
