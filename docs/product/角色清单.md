# 角色与用户体系（V1.0）

> 本文重点解决“身份来源、用户类别、门户角色、子系统角色”容易混淆的问题。

## 1. 三层身份与权限关系

```text
身份来源层
├─ 闽政通 → 公众用户
└─ 闽政务 → 政务用户
        ↓
卫健统一门户（中间层）
├─ 门户用户状态
├─ 门户系统角色
├─ 门户菜单/页面/操作权限
├─ 门户数据范围
└─ 应用入口资格
        ↓
各业务子系统
├─ 子系统账号
├─ 子系统业务角色
├─ 子系统菜单权限
├─ 子系统数据权限
└─ 子系统业务审批
```

## 2. 四个概念必须严格区分

### 2.1 身份来源

| 身份来源 | 对应用户类别 | 说明 |
|---|---|---|
| 闽政通 | 公众用户 | 公众侧权威身份来源 |
| 闽政务 | 政务用户 | 政务侧权威身份来源 |

身份来源不是角色。

### 2.2 用户类别

系统只定义：

- 公众用户（CITIZEN）
- 政务用户（GOV）

用户类别由认证来源确定，不允许门户管理员手工把公众用户改成政务用户，或反向修改。

用户类别也不是角色。

### 2.3 门户系统角色

门户角色只存在于“卫健统一门户”中间层，用于控制管理端和门户自身管理能力。

角色可以配置：

- 菜单权限；
- 页面权限；
- 操作权限；
- 门户数据范围。

同一用户可拥有多个门户角色。

### 2.4 子系统业务角色

子系统角色属于各业务子系统，例如业务经办人、审核人、管理员等。

门户：

- 不创建；
- 不编辑；
- 不分配；
- 不回收；
- 不同步为门户系统角色。

## 3. 普通用户与管理端权限

### 3.1 普通用户

完成闽政通或闽政务认证且门户状态正常后，可以进入用户端。

不需要为公众用户创建“公众角色”，也不需要为政务用户创建“政务角色”。

用户端可见内容继续受到：

- 用户类别；
- 应用适用范围；
- 应用访问资格；
- 子系统账号映射；
- 公告发布范围；
- 本人待办/消息

等规则约束。

### 3.2 管理端用户

是否可进入管理端，由门户系统角色和权限决定。

身份来源本身不自动授予管理权限。

## 4. 建议内置门户角色

以下是门户初始内置角色模板，不是新的“用户类型”。

| 角色 | 主要职责 |
|---|---|
| 门户超级管理员 | 用户、角色、组织、字典、配置及全局门户管理 |
| 应用管理角色 | 应用目录、应用访问申请、应用入口管理 |
| 集成管理角色 | SSO / TODO / MESSAGE连接配置与运行监控 |
| 公告管理角色 | 公告创建、编辑、提交、发布、撤回、删除 |
| 身份映射管理角色 | 闽政通/闽政务身份摘要、子系统账号映射、异常处理 |
| 审计角色 | 登录、访问、操作、接口、异常日志查看与允许的异常处理 |

可按实际项目需要新增自定义门户角色。

## 5. 角色管理页面

角色管理最终承担原“门户权限配置”页面能力。

### 5.1 角色列表

字段：

- 角色编码
- 角色名称
- 角色说明
- 启用状态
- 已关联用户数
- 更新时间
- 操作

### 5.2 角色编辑

字段：

- 角色编码
- 角色名称
- 角色说明
- 启用状态

### 5.3 权限配置

采用权限树配置：

```text
一级菜单
└─ 页面
   └─ 操作按钮/动作
```

至少支持：

- 菜单权限；
- 页面访问权限；
- 新增/编辑/删除/发布/审核等操作权限。

### 5.4 门户数据范围

角色可配置：

- SELF：本人数据
- ORG：本组织
- ORG_AND_CHILDREN：本组织及下级组织
- ASSIGNED_APPS：指定应用
- ALL_PORTAL：全部门户数据

数据范围只控制门户管理数据，不控制各子系统业务数据。

### 5.5 关联用户

支持查看该角色已分配用户。

用户角色分配在“用户管理”中进行，也可以在角色详情中查看关联用户，但不允许在角色管理中修改用户的闽政通/闽政务身份资料。

## 6. 用户管理与角色关系

用户管理只允许维护：

- 门户启用状态；
- 所属门户组织索引；
- 门户系统角色。

只读显示：

- 姓名；
- 登录账号；
- 用户类别；
- 身份来源；
- 上游身份摘要。

禁止修改：

- 闽政通 / 闽政务身份来源；
- 公众 / 政务用户类别；
- 权威姓名、手机号；
- 子系统业务角色；
- 子系统业务权限。

## 7. 应用访问资格不是角色

应用访问申请通过后获得的是：

> 门户应用入口资格

它不属于门户系统角色，也不属于子系统业务角色。

后续真正进入子系统后，业务权限继续由对应子系统判断。

## 8. 角色设计验收原则

1. 页面上不得把“公众用户 / 政务用户”显示为门户角色。
2. 页面上不得把“闽政通 / 闽政务”显示为角色。
3. 角色权限不得出现子系统内部菜单或业务权限。
4. 用户类别不得通过角色编辑。
5. 应用访问资格不得通过角色模拟实现。
6. 服务端必须对角色权限进行二次校验，不能仅依赖前端隐藏按钮。
