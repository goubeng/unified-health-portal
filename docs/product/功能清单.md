# 功能清单（P3 当前基线整合版 v5）

> 项目：卫健XC统一门户系统  
> 当前阶段：P3（IN_PROGRESS）  
> 当前版本：0.1.0  
> 设计标识：V20260917-01（Draft）

本清单以当前 P3 项目档案、P1/P2 产品设计、P3 数据设计、Service 契约、核心操作矩阵及《统一门户系统完整功能清单 v3》对比结果为基础整合。已去除“系统名称展示、平台说明”等页面基础信息类功能；同时进一步区分“门户自有能力”和“上层/外部平台提供能力”，避免把外部认证、二维码、短信等公共服务误写成本系统自建能力。

## 优先级说明

| 优先级 | 定义 |
|---|---|
| P0 | 核心业务闭环 / DEMO 首批，优先保证可演示、可操作、可验证 |
| P1 | 第二批管理与支撑能力，核心闭环稳定后补齐 |
| P2 | 优化、统计与增强能力，不阻塞第一版核心 DEMO |

## 当前明确不纳入的功能

- 不包含“系统名称展示、平台说明、LOGO展示”等页面基础信息项。
- “我的应用”不提供收藏/取消收藏。
- 待办和消息不提供门户主动拉取/轮询模式，仅支持子系统主动 PUSH。
- 门户不提供上层用户完整生命周期、密码管理、子系统开户审批。
- 门户不管理子系统业务角色、菜单权限和数据权限。
- 门户不聚合子系统通知公告。
- 不建设数据采集治理、专项库或数据汇聚治理。
- 高权限账号 REVIEWING 审核流程当前未启用，不作为本期功能。
- 不建设短信费用统计。
- 短信不默认视为门户自建能力；若由上层平台统一提供，则门户只做必要的接入/调用/结果处理，不建设独立短信渠道、模板审批和费用核算体系。
- 二维码、手机验证码等认证载体和有效期规则由上层身份平台提供时，门户只负责发起认证、展示认证载体/状态、接收结果，不重复实现上层认证能力。

## 现阶段说明

- P0/P1/P2 为实现优先级，不是工程阶段编号。
- 当前 P3 已完成 32 张原生表和 356 个业务字段的基础结构落地，但 P3 仍为 IN_PROGRESS；功能清单不把数据库约束验证状态误写成“功能已完成”。
- 标注“外部能力/接口待确认”的功能仅作为接入边界保留，不代表门户自建对应平台能力；真实联调需等待上层身份平台、上层公共服务平台及43个子系统提供资料。
- 完整按钮级权限矩阵、消息触发矩阵和最终审计收敛仍按工程计划在后续阶段完成。



## 使用对象角色口径

本版统一按“用户类型 + 门户内部权限范围”表达使用对象：

- **公众用户**：通过公众侧上层身份平台认证后使用门户。
- **政务用户**：通过政务侧上层身份平台认证后使用门户。
- **门户普通用户**：登录后使用应用、待办、消息、公告、个人中心等门户功能。
- **门户管理员**：管理端用户总称，不代表单一固定角色；根据职责可授予不同门户权限范围：
  - 门户管理员（超级管理权限）
  - 门户管理员（应用管理权限）
  - 门户管理员（集成管理权限）
  - 门户管理员（公告管理权限）
  - 门户管理员（审计权限）
  - 门户管理员（身份映射权限）
- **短信管理员不再作为独立固定角色**。如最终需要门户接入上层短信服务，由“门户管理员（集成管理权限）”负责相关配置和运行管理。
- 上述权限范围均只针对**门户自身**，不延伸到子系统角色、菜单权限和数据权限。
