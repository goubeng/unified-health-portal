# 数据设计（V1.0目标增量）

> 基线：V20260920-02。当前数据库仍以P3已验收结构为事实基线；本文描述下一阶段目标增量。

## 1. 身份来源与用户类别

固定业务语义：

| 身份来源 | 用户类别 |
|---|---|
| 闽政通 | CITIZEN / 公众用户 |
| 闽政务 | GOV / 政务用户 |

身份来源与用户类别是身份属性，不属于portal_role。

unified_user继续保存最小身份索引；identity_mapping保存闽政通/闽政务来源身份与统一身份之间的映射。

## 2. 复用现有门户权限结构

继续使用：

- portal_role
- portal_permission
- portal_role_permission
- portal_user_role
- portal_user_application_scope

这些结构只控制统一门户中间层，不保存子系统业务角色和子系统业务权限。

## 3. 门户组织索引

新增/目标表：portal_organization。

关键字段：

id、code、name、parent_id、org_type、level、path、source_code、source_org_key、sort_order、status、remark、created_at、updated_at、version。

规则：

- 政务用户组织优先来源闽政务；
- 公众用户不强制存在组织；
- portal_organization是门户索引，不是新的权威组织主数据；
- source_code + source_org_key用于保持来源稳定映射。

## 4. 应用访问申请与入口授权

application增加access_mode：

- DIRECT
- BIND
- REQUEST

新增application_access_request保存申请流程。

新增application_access_grant保存当前有效的门户入口资格。

入口资格不得复用portal_role实现，也不得表示子系统业务授权。

## 5. 公告增量

announcement增加：

- publish_mode
- scheduled_publish_at
- submitted_at
- submitted_by

announcement_status增加SCHEDULED。

effective_end=NULL表示永久有效。

## 6. 字典

最终新增：

- dict_type
- dict_item

业务字典包括应用系统分类、公告类型、组织类型等。

现有application_category在迁移期间保留，待应用引用完成迁移后退出独立维护入口。

系统状态/协议设置system_locked或等价控制，不能自由增加代码不支持的值。

## 7. 审计增强

audit_event.details继续承载登录来源、身份来源、用户类别、页面、模块、错误等扩展上下文。

如异常处理需要结构化字段，增加：

- resolved_by
- resolved_at
- resolution_note

## 8. 运行监控

monitor_status.status继续表示单一服务（SSO/TODO/MESSAGE）的运行状态。

不增加或持久化无必要的“三类状态综合状态”。

## 9. 迁移原则

- 不破坏P3历史已验收数据；
- Migration可重复执行；
- 失败事务回滚；
- Mock、Schema、Service、测试同步；
- 任何门户角色/授权变更不得写入子系统业务权限。
