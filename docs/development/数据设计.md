| 待办消息 | todo_item、message、message_recipient | 来源+源ID唯一；待办一个目标；消息本体对收件人1:N，各自已读 |
| 公告 | announcement、announcement_org_scope、announcement_attachment | 仅门户创建；组织范围按身份源命名空间；附件为原生上传返回对象 |

## 约束、状态与并发

SQL落实NOT NULL、主键、外键RESTRICT、枚举CHECK、复合UNIQUE、版本下限及关键行内一致性。NocoDB原生建表不得以“Service先查再写”替代这些约束；其原生存储是否具备等价约束需要主线程回读验证。若元数据接口不能表达复合唯一/检查，应对原生本地存储安排经授权的约束迁移，不得改用外部关联。无法安装等价约束时暂停真实并发业务写入，保留缺口证据。

跨记录事务由后端业务执行单元负责：接收凭证、业务记录、收件人和审计一起提交，失败一起回滚。NocoDB多个独立HTTP写入不假设具有事务；实际事务执行路径未验证前不得宣称幂等与并发验收通过。锁定幂等键与业务行，使用version条件更新；唯一约束兜底并发竞争。

待办唯一键application_id+source_todo_id；一条待办一个目标身份，多接收人需源系统分配独立源ID。首次PUSH须PENDING，状态更新只允许PENDING转三个终态，同终态重放不回退；首包即终态作为乱序拒绝并要求源方补发首包。due_at只派生逾期提示，EXPIRED仅源PUSH确认。消息每收件人独立UNREAD→READ，重复接收不覆盖已读。

账号映射BOUND时active_account_key为JSON序列化数组[application_id,external_user_id]，SQL校验结构且唯一；其余状态为NULL。一个人每应用仅一个当前槽位，历史进入审计。仅CONFLICT经人工证据确认可直接BOUND；FAILED重试先VERIFYING。REVIEWING是后续需求，未启用审核流程，不偷偷写入现有枚举。

发布公告必须先完成附件上传、正文清理、发布范围校验；指定组织需上层稳定org_key和source namespace，缺失拒绝发布或访问。撤回/过期终态不可直接再发布。公告的时间过期与待办源状态不同，公告可由门户时间规则处理。

## 保留与删除

配置键未确认时不执行清理；配置值由服务校验为合法正数/明确结构。消息按源创建时间、终态待办按terminal_at、日志按created_at计算留存截止；具体天数不冻结。删除收件人后再删消息；所有关联删除显式检查并写清理审计，FK RESTRICT禁止无声级联。分类只可在无应用关联时删除；应用停用、映射解绑都不删历史。

幂等回执留存必须覆盖源方重试窗口和业务留存，窗口未协商不得单独清理回执，否则会复活已删消息/待办。会话到期/撤销不可用；Token仅摘要。附件孤儿清理与下载鉴权、敏感短信目标加密引用的销毁期限在P4实现，不能从普通日志恢复秘密。

## 核心统计口径（设计）

| 指标 | 公式/来源 | 时间/去重/状态 |
|---|---|---|
| 待处理数 | todo_item计数 | 当前身份、PENDING；源唯一键；逾期仍待处理 |
| 未读数 | message_recipient计数 | 当前身份、UNREAD；message+user去重 |
| 应用数/正常/异常 | application计数 | code去重；管理状态与runtime分开筛选 |
| 待办/消息/SSO接入正常数 | 各配置NORMAL的应用数 | 分能力去重；43为目标，真实登记数单列，不补造数据 |
| 今日登录人数 | audit_event LOGIN成功身份去重 | Asia/Shanghai今日边界转UTC，AUTH日志不重复计 |
| 今日访问次数 | audit_event ACCESS成功 | request_id去重；重试同请求不重复 |
| 映射/接口异常 | OPEN异常/失败API请求数 | 映射异常按id；接口按request_id，查询时间窗口明确 |
