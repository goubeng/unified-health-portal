## 一、终端定位与受众边界

卫健统一门户系统设计并实现了 **PC 公众端**、**PC 管理端** 及 **移动端** 三大终端界面，根据用户角色与使用场景实施清晰的终端职责划分与安全隔离：

| 终端形态 | 目标用户群体 | 核心应用场景与边界 | 界面与交互形态 |
| :--- | :--- | :--- | :--- |
| **PC 公众端** | 公众用户（市民、患者）、普通医护及政务业务经办人员 | 日常在办公电脑上进行业务系统单点登录跳转、待办事项审批、系统通知查看、应用访问权限申请等。 | 采用标准桌面级宽屏布局，具备顶部全局导航、轮播 Banner、多列应用栅格、综合待办抽屉与表格化筛选。 |
| **PC 管理端** | 系统管理员、业务审批管理员、安全审计管理员 | 负责业务系统纳管、连接配置、申请工单审批、账号映射仲裁、用户角色授权、运行健康监控、日志审计及系统参数维护。 | 采用现代企业级左侧中后台导航与顶部面包屑架构，具备统计卡片看板、多维数据表格、树形选择器及审批弹窗。 |
| **移动端 (H5/移动视口)** | 移动政务办公人员、外出公众人员 | 满足用户在移动设备随时随地查看待办事项、处理紧急待办（跳转移动端子系统）、浏览重要通知公告、查询个人申请进度。 | 采用沉浸式移动端布局，专属底部导航栏（Tabbar）、单手横向手势滑动（Horizontal Scroll）、移动专属返回顶栏及抽屉筛选。 |

## 三、移动端独立交互与返回逻辑核查

核查团队对移动端的路由体系、独立页面架构、返回层级与边界交互进行了逐项代码审计与链路测试：

### 3.1 移动端 7 大独立页面架构

移动端并非 PC 页面的简单缩放，而是基于 Vue 3 + TypeScript 独立编写的高可用移动端组件群（位于 `src/mobile/` 目录），包含 7 个核心一级与二级页面：

1. **移动登录页** (`/mobile/login`，`MobileLoginView.vue`)：独立移动端认证界面，适配手持软键盘与多身份切换。
2. **移动门户首页** (`/mobile/home`，`MobileHomeView.vue`)：聚合常用应用、待办总览、通知头条与用户信息。
3. **移动应用中心** (`/mobile/apps`，`MobileAppCenterView.vue`)：垂直应用流与分类标签，支持直接进入与发起申请。
4. **移动我的申请** (`/mobile/applications`，`MobileMyApplicationsView.vue`)：独立申请工单流水页面，支持查看进度与撤回。
5. **移动待办中心** (`/mobile/todos`，`MobileTodoCenterView.vue`)：待办列表与紧急程度筛选，提供直通办理入口。
6. **移动消息中心** (`/mobile/messages`，`MobileMessageCenterView.vue`)：消息卡片列表、未读徽标与多选批量标记。
7. **移动通知详情** (`/mobile/notices/:id`，`MobileNoticeDetailView.vue`)：移动端富文本渲染排版与附件安全下载。

### 3.2 导航体系与返回逻辑（Navigation & Back Logic）

核查重点确认了移动端各级页面的返回行为，杜绝“死胡同”和无法回退的情况：

- **二级页面返回机制**：
  - “我的申请”、“通知详情”、“全部应用”等二级页面顶部均设有专属返回按钮（`<van-nav-bar left-arrow>` 或统一图标）；
  - 点击优先触发 `router.back()`；
  - 若用户通过外链或直接访问进入（历史栈长度为1），兜底安全回退到移动首页 `/mobile/home`，确保用户永远不会卡死在子页面。
- **底部 Tabbar 核心路由**：
  - 首页（Home）、待办（Todos）、消息（Messages）、我的（Profile）四个常驻 Tab 之间切换平滑，保持页面滚动位置。
- **独立弹窗与浮层关闭**：
  - 申请弹窗、账号关联弹窗均具备右上角明确的关闭按钮（`×`）及蒙层点击关闭防护，键盘弹出时自动平移视口。

### 3.3 移动端专属交互细节验证

根据近期多项产品细节优化，核查团队专项复核了以下移动交互点：

1. **“我的应用”横向手势滑动**：
   - 首页默认展示前 8 个应用，超过 8 个时支持横向水平滑动手势；
   - 原“全部应用”已按新需求改为“我的申请”快捷链接，点击直达申请审批工单流。
2. **待办与应用视觉规范**：
   - 去除了“我的应用”、“待办事项”前方的过宽蓝色竖线，采用紧凑现代标题排版；
   - 缩小了移动端应用图标的阴影面积与透明度，阴影颜色精准吸取图标主色调（彩色弥散阴影）。
3. **消息多选复选框（Checkbox）**：
   - 复选框对齐与圆角遵循最新移动设计规范，移除多余外边框，右下角复选标记对齐自然，交互反馈流畅。

### 3.4 移动端代码质量与规范检查

核查期间执行了移动端专用静态检查套件：
```bash
npm run check:mobile
```
- **检查内容**：Vue-tsc 模板类型检查 + ESLint 代码质量规则。
- **检查结果**：**0 错误、0 警告**，TypeScript 类型契约严谨，完全符合工程规范。

## 四、端间一致性与数据共享机制

1. **共享底座服务层**：
   - PC 端与移动端完全复用 `src/services/portal.js` 统一封装的 API 契约与本地数据存储底座；
   - 确保待办已处理状态、消息已读状态、申请单审批状态在 PC 端与移动端之间实现秒级双向同步，不存在数据孤岛。
2. **权限与安全一致性**：
   - 统一由 `server/security-middleware.mjs` 与后端鉴权机制保护；
   - 移动端无论如何绕过前端路由，未经授权访问管理端 API 均被服务端强制拒绝（HTTP 403 / NO_PERMISSION）。
