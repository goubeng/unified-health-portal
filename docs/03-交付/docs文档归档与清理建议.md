# 卫健统一门户系统 docs文档归档与清理建议

> **版本**：V1.0  
> **日期**：2026-10-12  
> **核查原则**：实事求是盘点、保护项目过程凭证、明晰交付资产；**本阶段只提供归档与清理建议，暂不执行任何物理删除**。

---

## 一、文档现状全景盘点

当前 `docs/` 目录下共有 4 个一级分类目录、70 余个文档及模式定义文件。随着系统经历 P0～P6 多个敏捷迭代阶段，文档资产呈现“核心基线健全、过程产物丰富、但存在历史阶段性碎片”的特征。

```
docs/
├── 01-需求/          # 需求说明书、细化需求清单、业务模型
├── 02-设计/          # 架构设计、数据库Schema、接口契约、阶段评审、研发计划、过程记录
└── 03-交付/          # 交付前功能完整性核查报告、对照表、矩阵、问题清单（本次成果）
```

---

## 二、文档分类标准与处置准则

为便于交付给业主团队后续进行长期运维、二次开发以及第三方审计，建议将现有文档划分为以下三类：

1. **【A 类：建议持续维护与保留】（核心交付资产）**
   - 系统的正式需求基线、架构设计、数据库 Schema、标准化接口契约及正式交付核查文档；
   - 作为系统全生命周期运维和验收的标准依据，必须与代码保持严格同步。
2. **【B 类：建议移入历史归档】（过程凭证与阶段快照）**
   - 各开发迭代阶段的评审纪要、阶段自查比对表、模型冻结记录及执行计划；
   - 具备审计追溯价值，但不属于日常运维阅读文档。建议新建 `docs/04-归档/` 目录集中封存。
3. **【C 类：建议后续清理/废弃】（研发临时碎片与冗余草稿）**
   - 敏捷冲刺期间产生的临时记录文件（如阶段性 `findings.md`、`lessons.md`、`task_plan.md` 等碎片笔记）；
   - 现阶段保持原样不删，待交付验收并备份后，由技术团队统一下线清理。

## 四、建议实施步骤与时间表

1. **当前阶段（交付前准备）**：
   - **严格保持现有目录结构和文件内容不动**，不执行删除或移动，避免因路径变动导致现有自动化测试脚本或外链引用失效。
2. **下一阶段（软件功能验收通过后）**：
   - 由项目经理与技术负责人统一组织文档治理操作：
     - 新建 `docs/04-归档/` 目录；
     - 将 B 类文件（历史评审、阶段计划、原始立项材料）平移至 `docs/04-归档/`；
     - 将 C 类零散过程记录（`04-过程记录/` 中的碎片 md 文件）打包压缩备份到项目归档网盘后，从代码仓库中安全移除；
     - 更新 `docs/README.md`，呈现清晰的一级目录导航（需求、设计、交付、归档）。
