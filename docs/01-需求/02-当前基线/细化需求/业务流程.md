# 业务流程（V1.0）

> 基线：V20260921-01。

## 1. 总体身份链路

```text
闽政通 → CITIZEN ┐
                   ├→ 门户访问主体（portal_user）→ 用户端 → 各业务子系统
闽政务 → GOV     ┘

闽政通/闽政务访问主体 ──授予管理资格──┐
                                     ├→ 门户管理用户（portal_admin_user）→ 管理端
门户本地管理账号（LOCAL认证）─────────┘
```

## 2. 用户端登录

公众：闽政通认证 → 门户建立/更新统一身份 → CITIZEN → Session → 用户端。

政务：闽政务认证 → 门户建立/更新统一身份 → GOV → Session → 用户端。

## 3. 管理端本地登录

```text
输入门户本地账号/密码
→ 校验账号启用/锁定
→ 校验密码Hash
→ 检查是否拥有管理角色
→ 建立管理端Session
→ 写登录日志
→ 管理端
```

首次登录如设置must_change_password，则先完成改密。

## 4. 外部身份进入管理端

闽政务/闽政通认证 → 门户访问主体 → 检查是否存在有效 `portal_admin_user` 管理授权 → 检查门户角色 → 有效则允许进入管理端，否则只进入用户端。

普通 CITIZEN / GOV 不因为用户类别自动获得管理端权限。

## 5. 本地管理账号创建

超级管理员 → 新建 `portal_admin_user(auth_type=LOCAL)` → 按安全策略初始化登录凭证 → 分配门户角色 → 首次登录或凭证重置后按策略执行改密。

不创建 LOCAL 普通访问用户，不开放公众自助注册门户本地管理账号。

## 6. 角色授权

```text
portal_admin_user
→ 分配门户超级管理员/门户管理员/自定义门户角色
→ 菜单/页面/操作权限
→ 后端鉴权
```

首期默认ALL_PORTAL。

### 6.1 上层单点进入门户

```text
用户已登录闽政通/闽政务
→ 从上层平台进入统一门户
→ 携带受控 AuthCode / Ticket / Token
→ 门户校验认证结果
→ 查找/建立门户访问主体
→ 创建 Portal Session
→ 进入用户端
```

上层已完成等价身份认证时不重复要求扫码；Portal Session 仍由门户独立建立和维护。

## 7. 应用访问

总体流程：

```text
用户端用户
→ 判断应用适用用户
→ 应用启用状态
→ DIRECT / BIND / REQUEST
→ 检查门户入口资格
→ 必要时建立子系统账号映射
→ SSO进入子系统
→ 子系统自行校验业务角色、菜单和数据权限
```

### 7.1 DIRECT

满足用户类别和应用启用条件后直接进入 SSO/跳转流程，不要求门户先建立子系统账号映射。

### 7.2 BIND

```text
用户点击应用
→ 查询 application_user_mapping
→ 已 BOUND：直接进入后续 SSO
→ 未绑定：查找候选子系统账号
→ AUTO / SELF / REVIEW / ADMIN
→ 完成账号所有权验证
→ 建立 BOUND 映射
→ SSO
```

候选匹配规则：

- 有可信统一人员标识时优先 AUTO；
- 无统一标识时可用姓名 + 已登记手机号、姓名 + 工号等查找候选；
- 姓名 + 手机号只用于候选定位，不直接完成绑定；
- 候选匹配后必须通过子系统跳转认证、子系统登记手机号 OTP、上层重新认证、子系统账号一次性校验或管理员审核中的一种/多种方式完成二次验证。

高权限子系统账号可配置：

```text
VERIFYING
→ 验证成功
→ REVIEWING
→ 管理员审核
→ BOUND
```

同一个 application_id + external_user_id 只能存在一个有效 BOUND 映射。已绑定其他 unified_user 时禁止自动覆盖，转 CONFLICT / mapping_exception。

### 7.3 REQUEST

REQUEST 只解决“是否有门户应用入口资格”。

```text
提交申请
→ PENDING
→ APPROVED / REJECTED
→ APPROVED 后生成 application_access_grant
→ 如应用还要求账号映射则继续 BIND
→ SSO
```

入口资格不等于子系统业务权限。

### 7.4 解绑/重绑

普通账号解绑至少要求当前身份再次确认并记录审计；高权限账号解绑建议审核。解绑后重新绑定其他统一用户时不得绕过唯一绑定和冲突校验。

本地管理员默认不参与普通应用访问链路；未来如需要可按用户类别和应用规则扩展。

## 8. 公告

```text
新增公告
├─ 保存草稿 → DRAFT
├─ 立即发布 → PUBLISHED
└─ 定时发布 → SCHEDULED → 到时 PUBLISHED
```

状态规则：

- DRAFT 可继续编辑、保存草稿、立即发布或定时发布；
- SCHEDULED 可修改内容和定时计划；保存草稿时取消定时计划并回到 DRAFT；也可切换为立即发布进入 PUBLISHED；
- PUBLISHED 允许继续编辑，保存后直接更新已发布内容，并可撤回；
- 撤回后进入 WITHDRAWN，可继续编辑、删除、保存为 DRAFT，也可重新立即发布或定时发布；
- EXPIRED 不允许编辑，仅允许按规则删除；
- 失效日期为空表示永久有效，填写日期时按当天 23:59:59 作为截止时间。

## 9. 待办/消息

待办：

```text
子系统 PUSH
→ 门户幂等接收
→ PENDING（待处理）
→ 用户去处理进入来源子系统
→ 来源子系统同步 COMPLETED（已处理）或 WITHDRAWN（已撤回）
```

门户不自行产生逾期状态，不承接来源系统内部审批。

消息由子系统或门户产生并按用户聚合，支持 UNREAD（未读）/READ（已读）；存在业务地址时可跳转对应业务页面。

## 10. 组织

政务组织优先来源闽政务；本地用户组织可选；公众用户不强制组织。

## 11. 异常日志

OPEN → 管理员处理 → RESOLVED。
