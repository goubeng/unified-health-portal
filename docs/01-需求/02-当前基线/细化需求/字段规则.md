# 字段规则（V1.1）

> 基线：V20260921-01。本文为主SRS的字段细化，不形成第二套需求基线。

## 1. 外部身份与门户访问主体

用户端只存在两类访问主体：

| identity_source | user_type | 中文 |
|---|---|---|
| MINZHENGTONG | CITIZEN | 闽政通 / 公众用户 |
| MINZHENGWU | GOV | 闽政务 / 政务用户 |

`identity_source` 与 `user_type` 是访问身份属性，不是门户角色。

不得再使用 `PORTAL_LOCAL / LOCAL` 表示第三类用户端访问主体。

外部身份字段同步规则：

- 外部稳定用户ID作为身份定位依据，不使用姓名作为唯一键；
- 姓名、手机号、组织等只同步最小必要字段；
- 首次认证按需建档，后续登录按正式同步规则刷新；
- CITIZEN/GOV 跨身份源关联不得仅凭姓名或手机号自动合并；
- 外部身份密码、长期认证凭据和生物识别模板不得进入门户业务表。

## 2. 门户管理用户

管理端授权主体：`portal_admin_user`。

关键字段：
- admin_user_id
- account
- name
- auth_type：EXTERNAL / LOCAL
- access_user_id：EXTERNAL时绑定门户访问主体，可空
- enabled
- protected_flag
- last_login_at
- created_at / updated_at / version

EXTERNAL 仅表示管理资格绑定外部访问身份；不得修改闽政通/闽政务权威主数据。

LOCAL 为门户本地管理认证方式，不创建 LOCAL 普通访问用户。

## 3. 本地管理凭证

建议实体：`portal_admin_credential`。

字段：
- admin_user_id
- username
- password_hash
- password_algorithm
- must_change_password
- failed_login_count
- locked_until
- password_updated_at
- last_login_at
- version

禁止：
- 保存明文 password
- 普通接口返回 password_hash
- 在日志中输出密码、验证码或完整Token
- 在代码、Seed、文档中写死正式超级管理员明文密码

安全行为：
- `must_change_password=true` 时，首次登录或重置后必须先改密；
- 登录失败累计更新 `failed_login_count`，达到安全阈值后写入 `locked_until`；
- 成功登录后按安全策略清理失败计数并更新 `last_login_at`；
- 密码修改/重置更新 `password_updated_at`；
- 密码重置、解锁、启停和失败登录必须产生审计记录。

## 4. 门户角色

默认：
- SUPER_ADMIN：门户超级管理员
- PORTAL_ADMIN：门户管理员

门户角色只授予 `portal_admin_user`，不直接授予普通 `unified_user`。

第一阶段采用资源+操作权限编码，未授权即拒绝，不引入显式DENY。

## 5. 应用

## 6. 子系统账号映射

映射对象必须是：

`门户访问主体(unified_user) ↔ application ↔ 子系统账号`

建议字段：
- mapping_id
- unified_user_id
- application_id
- external_user_id
- external_account
- binding_method
- binding_status
- match_method
- verification_method
- verification_status
- risk_level
- external_account_status
- verified_at
- reviewed_by
- reviewed_at
- bound_at
- unbound_at
- conflict_reason
- created_at
- updated_at
- version

binding_status：
- UNBOUND
- VERIFYING
- REVIEWING
- BOUND
- FAILED
- CONFLICT

external_account_status：
- ACTIVE
- DISABLED
- UNKNOWN

姓名+手机号只允许用于候选匹配，不允许作为统一主键或直接绑定依据。

## 7. 应用访问申请

字段：
- request_no
- application_id
- user_id
- reason
- status
- submitted_at
- reviewed_by
- reviewed_at
- review_note
- version

状态：
- PENDING
- APPROVED
- REJECTED
- WITHDRAWN
- EXPIRED

EXPIRED 在应用访问申请域中仍为正式业务状态，与公告的派生过期状态不是同一概念。

## 8. 待办

目标字段：
- application_id
- source_todo_id
- target_user_id
- title
- business_type
- summary
- status
- source_created_at / received_at
- source_updated_at
- business_url
- created_at / updated_at / version

状态：
- PENDING
- COMPLETED
- WITHDRAWN

正式模型不再包含：
- priority
- due_at
- source_revision
- terminal_at
- EXPIRED

门户不根据时间自行产生逾期状态。

## 9. 消息

消息本体与收件人状态分离。

`message_recipient` 至少包含：
- message_id
- user_id
- read_status：UNREAD / READ
- read_at
- deleted
- deleted_at

用户删除采用收件人级逻辑删除，不物理删除消息本体。

## 10. 公告

持久化字段：
- status：DRAFT / PUBLISHED / WITHDRAWN
- publish_mode：IMMEDIATE / SCHEDULED
- scheduled_publish_at
- published_at
- effective_end（NULL=永久）
- submitted_at / submitted_by

页面派生展示：
- SCHEDULED：status=DRAFT 且 publish_mode=SCHEDULED 且发布时间未到
- EXPIRED：status=PUBLISHED 且 effective_end早于当前时间

因此 SCHEDULED / EXPIRED 可继续作为前端展示标签和查询条件，但不得作为新增永久主状态依赖。

附件与正文约束：
- 公告附件最多 5 个；
- 单个附件最大 20MB；
- 支持图片、PDF、Word、Excel、TXT、ZIP 等当前允许类型；
- 正文插入图片与普通附件分开校验，当前正文图片单张最大 2MB；
- “清空正文”只清空富文本正文，不自动删除已选择的附件。
- 富文本编辑支持对选区应用斜体等文字格式，编辑区和正文展示区都应呈现对应字形。
- 定时发布时间（新增公告、编辑公告、提交发布）：过去日期不可选；当天已经过去的小时、分钟和秒不可选；选定值在提交前与服务端均需校验晚于当前时间，且必须早于设置的失效时间。列表显示“定时发布”，不附加“（展示）”。

## 11. 应用接入能力

integration_type：
- SSO
- TODO
- MESSAGE

config_status：
- UNCONFIGURED
- CONFIGURED

enabled：
- true / false

runtime_status：
- UNCONFIGURED
- DISABLED
- NORMAL
- ABNORMAL

综合运行状态由应用启停和必需接入能力计算：应用停用优先；启用应用的 SSO 始终必需，已启用的 TODO / MESSAGE 也属于必需能力，按异常、停用、未配置优先级判断，全部必需能力正常才为正常。管理员不能直接编辑综合运行状态；当前提供 `monitor:view` 查看权限，已移除 `monitor:check` 和人工检测录入命令。正式真实探测器仍待接入。

接入状态变更历史保留应用、接入服务、原状态、新状态、发生时间、原因和来源；仅有效状态迁移新增历史，异常日志的人工“已处理”不等于接入恢复。最近检测/成功/失败属于当前快照，不可据此补造既往状态变化。UI 在运行监控应用详情的“状态变更记录”Tab 按应用过滤展示；管理端应用列表详情不展示此 Tab。

## 12. 登录与审计

外部访问主体登录：
- actorType=ACCESS_USER
- identitySource=MINZHENGTONG / MINZHENGWU

门户本地管理账号登录：
- actorType=PORTAL_ADMIN_USER
- authType=LOCAL
- identitySource=PORTAL_LOCAL
- loginMethod=PASSWORD

审计必须能够区分 access_user、portal_admin_user、application、system。

## 13. API 与展示

- API时间统一ISO 8601；
- 数据库存储使用 timestamptz；
- API Boolean使用 true/false；
- 枚举使用稳定英文编码；
- 空值保持NULL语义；
- 前端无值统一展示英文半角 `-`，不得将占位写回数据库；
- 管理端时间展示格式属于前端格式化规则，例如 `2026/9/18 07:00:00`。
