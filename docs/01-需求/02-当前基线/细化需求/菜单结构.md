# 菜单结构

> 本文件用于描述卫健统一门户当前正式菜单信息架构。  
> 菜单结构以《卫健统一门户系统需求规格说明书》中的“信息架构与菜单”为权威基线。  
> 页面内部分组、详情页、弹窗及兼容路由不等同于左侧菜单项。

## 1. 用户端门户

用户端左侧导航采用**单层菜单**，不显示“个人事务”等额外一级分组标题。

```text
用户端门户
├─ 首页
├─ 待办事项
├─ 消息中心
├─ 通知公告
├─ 全部应用
├─ 我的申请
└─ 个人中心
```

### 1.1 菜单与路由

| 顺序 | 菜单名称 | 路由 | 说明 |
|---|---|---|---|
| 1 | 首页 | `/portal/home` | 聚合待办、公告、消息、我的应用及快捷入口 |
| 2 | 待办事项 | `/portal/todos` | 查看本人待办、待办详情及进入来源业务处理 |
| 3 | 消息中心 | `/portal/messages` | 查看本人消息、已读处理、删除及消息详情 |
| 4 | 通知公告 | `/portal/announcements` | 查看当前用户可见公告及公告详情 |
| 5 | 全部应用 | `/portal/apps/all` | 支持“按开通情况 / 按所属系统”分组视图、查询与应用访问处理 |
| 6 | 我的申请 | `/portal/applications` | 查看应用访问申请及适用的子系统账号开通申请 |
| 7 | 个人中心 | `/portal/profile` | 查看当前用户身份、组织及登录信息 |

### 1.2 全部应用内部结构

“按开通情况”和“按所属系统”是**全部应用页面内的视图切换**，不作为左侧二级菜单；默认的“按开通情况”视图再分为“我的应用”和“其它应用”。

```text
全部应用
├─ 按开通情况（默认）
│  ├─ 我的应用
│  └─ 其它应用
└─ 按所属系统（按归属子系统分组）
```

说明：

- “我的应用”展示当前用户已经满足访问条件、可以使用的应用；
- “其它应用”展示当前用户可见但仍需申请、账号确认、等待处理或异常处理的应用；
- `/portal/apps/mine` 仅作为兼容隐藏路由保留，不作为当前菜单入口；
- “我的申请”是独立菜单，不属于“全部应用”的子菜单。

### 1.3 非菜单页面

以下页面或交互不单独占用左侧菜单：

| 页面/交互 | 进入方式 | 菜单上下文 |
|---|---|---|
| 公告详情 | 从通知公告列表或首页公告标题进入 | 保持“通知公告”选中 |
| 消息详情 | 从消息中心或首页消息标题进入 | 保持“消息中心”选中 |
| 待办详情 | 从待办事项或首页待办标题进入 | 保持“待办事项”上下文 |
| 应用访问/账号处理 | 从全部应用应用卡片触发 | 保持“全部应用”上下文 |
| 应用访问申请 | 从全部应用或我的申请触发 | 不新增菜单 |
| 子系统账号开通引导 | 从应用处理流程触发 | 不新增菜单 |

## 2. 平台管理端

平台管理端按“工作台 / 应用管理 / 系统管理 / 日志审计”四个一级分组组织。

```text
平台管理端

工作台
├─ 管理首页
└─ 通知公告管理

应用管理
├─ 应用列表
├─ 应用访问申请
├─ 子系统账号开通申请
└─ 运行监控

系统管理
├─ 用户管理
├─ 角色管理
├─ 组织管理
├─ 字典管理
├─ 身份与子系统映射
└─ 配置管理

日志审计
├─ 登录/认证日志
├─ 应用访问日志
├─ 门户操作日志
├─ 接口调用日志
└─ 异常日志
```

### 2.1 工作台

| 菜单名称 | 路由 | 说明 |
|---|---|---|
| 管理首页 | `/admin/home` | 管理指标、待处理事项、常用管理、接入运行状态及异常 |
| 通知公告管理 | `/admin/announcements` | 公告新增、草稿、发布、定时发布、编辑、撤回、重新发布及删除 |

### 2.2 应用管理

| 菜单名称 | 路由 | 说明 |
|---|---|---|
| 应用列表 | `/admin/apps` | 纳管应用基础信息、启停、详情及连接配置 |
| 应用访问申请 | `/admin/application-requests` | 门户应用入口资格申请审核 |
| 子系统账号开通申请 | `/admin/account-opening-requests` | 在子系统提供标准开户注册接口时承接申请状态 |
| 运行监控 | `/admin/monitor` | 查看各应用 SSO / TODO / MESSAGE 接入健康状态 |

### 2.3 系统管理

| 菜单名称 | 路由 | 说明 |
|---|---|---|
| 用户管理 | `/admin/users` | 公众、政务、本地用户查看及门户侧维护 |
| 角色管理 | `/admin/roles` | 门户角色及 MENU / PAGE / ACTION 权限配置 |
| 组织管理 | `/admin/organizations` | 外部组织索引及门户本地组织维护 |
| 字典管理 | `/admin/dictionaries` | 业务字典和受控字典维护 |
| 身份与子系统映射 | `/admin/identities` | 查看及处理统一用户与子系统账号映射 |
| 配置管理 | `/admin/settings` | 门户级规则和系统参数配置 |

### 2.4 日志审计

| 菜单名称 | 路由 |
|---|---|
| 登录/认证日志 | `/admin/logs/login` |
| 应用访问日志 | `/admin/logs/access` |
| 门户操作日志 | `/admin/logs/operation` |
| 接口调用日志 | `/admin/logs/api` |
| 异常日志 | `/admin/logs/error` |

## 3. 管理端非菜单页面与合并入口

以下能力保留页面、详情或兼容路由，但不新增独立菜单：

| 能力 | 当前归属 |
|---|---|
| 公告详情 | 通知公告管理下的详情页面 |
| 应用连接配置 | 应用列表中的“连接配置” |
| 门户权限配置 | 角色管理中的权限配置 |
| 系统分类 | 字典管理 |
| 本地账号管理 | 用户管理 |
| 映射审核 / 冲突处理 / 异常查看 | 身份与子系统映射 |
| `/admin/app-categories` | 兼容隐藏页面，不作为菜单 |
| `/admin/permissions` | 兼容隐藏页面，不作为菜单 |
| `/admin/identity-mappings` | 兼容隐藏路由，不作为菜单 |
| `/admin/account-mappings` | 兼容隐藏路由，不作为菜单 |
| `/admin/mapping-exceptions` | 兼容隐藏路由，不作为菜单 |

不恢复“业务集成”“身份与映射”等独立一级菜单。

---

## 4. 菜单权限规则

- 用户端菜单按当前登录用户可访问范围展示；
- 平台管理端菜单由门户角色的 `MENU` 权限控制；
- 页面及操作权限分别由 `PAGE`、`ACTION` 权限控制；
- 页面存在不代表必须显示为菜单；
- 详情页、弹窗、页面内部 Tab/分组不得重复配置为左侧菜单；
- 无有效门户管理角色的用户不得进入平台管理端；
- 默认门户管理角色为“门户超级管理员”和“门户管理员”，后续可扩展自定义门户角色。

## 5. 菜单调整归并关系

| 历史入口/分组 | 当前处理 |
|---|---|
| 用户端“个人事务”一级分组 | 取消，用户端改为单层菜单 |
| 用户端“全部应用”一级分组 | 取消一级分组，仅保留单个“全部应用”菜单 |
| “我的应用 / 其它应用”菜单 | 改为全部应用页面内部分组 |
| “我的申请”全部应用子菜单 | 改为用户端独立菜单 |
| “身份与映射”一级分组 | 取消，“身份与子系统映射”归入系统管理 |
| 门户权限配置 | 合并至角色管理 |
| 应用接入配置 | 合并至应用列表 → 连接配置 |
| 系统分类 | 合并至字典管理 |
| 本地账号管理 | 合并至用户管理 |
| 业务集成 | 不恢复独立一级菜单 |


## 附录：移动端底部导航与路由

移动端与 PC 左侧菜单是两套独立界面，不应将移动端“底部导航”反向加到 PC 菜单。

- 底部主导航：**首页、待办事项、消息中心、全部应用、我的**（`MobileShell.vue`）。
- 通知公告与公告详情由首页等入口进入；“我的申请”及申请详情使用顶部返回，并按来源 `from=home` / `from=apps` 返回正确页面；移动端消息详情隐藏主导航。
- 移动端路由及交互规则统一见[需求规格说明书第48章](../卫健统一门户系统需求规格说明书.md#48-移动端页面与交互需求)。相关页面和业务功能以正式验收记录确认。
