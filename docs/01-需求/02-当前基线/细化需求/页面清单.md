## 4. 页面与菜单关系

- 页面存在不等于必须显示为菜单；
- 详情页、弹窗、页面内部 Tab/分组不得重复作为左侧菜单；
- 用户端全部应用的“我的应用/其它应用”为页面内部分组；
- 管理端公告详情保持“通知公告管理”选中；
- 用户端公告详情保持“通知公告”选中；
- 消息详情保持“消息中心”选中；
- 待办详情属于待办事项业务上下文；
- 身份映射审核、冲突处理均属于“身份与子系统映射”，不再定义独立正式页面。


## 附录：移动端页面（不增加 PC 菜单项目）

以下为移动端页面及路由清单，用于明确入口与业务定位，不改变 PC 菜单或门户管理权限边界。

| 路由 | 页面 | 说明 |
|---|---|---|
| `/m/home` | 首页 | 待办、公告、应用及我的申请等快捷入口 |
| `/m/todos` | 待办事项 | 列表及移动端待办详情弹窗 |
| `/m/messages` | 消息中心 | 列表；详情通过 `messageId` 查询参数承载 |
| `/m/apps` | 全部应用 | 分类与应用列表，进入应用/账号处理 |
| `/m/profile` | 我的 | 个人入口 |
| `/m/announcements` | 通知公告 | 公告列表 |
| `/m/announcements/:id` | 公告详情 | 独立详情路由 |
| `/m/applications` | 我的申请 | 申请列表与分组 |
| `/m/applications/:id` | 申请详情 | 独立详情路由 |

`/m` 自动跳转 `/m/home`。详情交互、返回上下文与核对要求统一见[需求规格说明书第48章](../卫健统一门户系统需求规格说明书.md#48-移动端页面与交互需求)。
