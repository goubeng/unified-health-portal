# 原型交付与接口模拟口径

> 项目：卫健XC统一门户系统  
> 当前定位：高保真演示原型  
> 日期：2026-09-22；数据源说明复核：2026-10-01
> 适用范围：当前前端验收、演示数据、接口模拟、演示交付

## 1. 交付目标

当前阶段不追求生产上线，而是形成一套：

1. 页面完整、交互稳定；
2. 用户端与管理端关键业务可闭环演示；
3. Mock数据具有真实业务状态和异常场景；
4. SSO / TODO / MESSAGE / 账号映射等接口设计接近真实工程；
5. 下载的接口文档可被开发工具识别并具备实现参考价值；
6. 后续如进入真实开发，可沿用当前业务模型和技术契约。

## 2. 当前必须完成

- 登录端、用户端、管理端逐页人工验收；
- DIRECT / BIND / REQUEST 三类应用访问场景；
- 应用申请、审核、账号确认、映射审核/冲突、账号开通申请等演示链路；
- TODO、MESSAGE、公告、日志、运行监控等演示闭环；
- SSO / TODO / MESSAGE 连接配置字段和业务规则核对；
- OpenAPI文件下载、解析、示例和错误响应核对；
- npm test、npm run build；
- 浏览器控制台及非预期4xx/5xx检查；
- 修复后形成原型冻结版本。

## 2.1 登录演示

- 登录页保留公众/政务扫码、手机号、滑块、验证码等模拟元素；
- 管理账号保留账号、密码和图形验证码元素，默认账号为 `admin`；
- 上述字段和验证流程仅用于界面与交互演示，不作为登录校验条件；
- 用户可直接点击二维码或登录按钮进入对应端；
- 一键进入的本质是建立对应 Mock Session，不代表真实认证已接入。

## 3. 当前不要求完成

- 真实闽政通认证；
- 真实闽政务认证；
- 42个子系统逐一联调；
- 生产级SSO Ticket服务；
- 生产AppKey/AppSecret密钥管理；
- 生产数据库全量Migration和切换；
- 生产部署、高可用、灾备和正式运维体系；

上述能力可以保留设计文档和接口目标，但不得作为本轮原型验收阻塞项。

## 4. “接口模拟要真实”的统一标准

### 4.1 通用规范

接口契约至少满足：

- OpenAPI 3.x；
- JSON；
- camelCase业务字段；
- ISO 8601时间；
- 稳定英文枚举；
- requestId / traceId；
- 明确HTTP状态与业务错误码；
- 写接口考虑幂等；
- 外部PUSH考虑调用方鉴权；
- 不使用姓名作为唯一用户定位依据；
- 密码、OTP、Secret、Token不进入普通日志和响应；
- Mock成功不等于真实连通，页面状态必须能区分配置状态与运行状态。

### 4.2 SSO

演示配置应至少表达：

- 接入协议：OIDC / SAML2 / CUSTOM等；
- clientId/应用标识；
- authorizeUrl；
- tokenUrl（协议需要时）；
- callbackUrl；
- credentialRef；
- 启用状态；
- 配置状态；
- 运行状态。

推荐目标流程仍采用可信、短时、一次性Ticket或标准协议回调，禁止直接在URL中拼接姓名、手机号、角色等可信身份信息。

### 4.3 TODO

接口契约至少表达：

- eventId；
- sourceTodoId；
- appCode/appId；
- receiverIdentity；
- title；
- businessType；
- description/summary；
- actionPath；
- status；
- sourceUpdatedAt/receivedAt。

状态限定为：

- PENDING；
- COMPLETED；
- WITHDRAWN。

门户“去处理”不自行把待办改为COMPLETED。

### 4.4 MESSAGE

接口契约至少表达：

- eventId；
- sourceMessageId；
- appCode/appId；
- receivers/receiverIdentity；
- title；
- content；
- messageType/businessType；
- actionPath；
- sentAt/receivedAt。

门户维护用户级UNREAD/READ和逻辑删除状态。

### 4.5 鉴权与幂等

目标技术规范采用：

- AppKey / AppSecret；
- timestamp；
- nonce；
- signature；
- requestId/eventId幂等；
- 重放防护；
- 401/403/409等明确错误语义。

当前本地Mock接收器可以使用简化凭据，但下载文档必须明确“当前可调用方式”和“目标正式鉴权方式”的区别，不能混写。

## 5. 下载接口文件验收标准

下载文件必须：

1. 是有效OpenAPI 3.x JSON/YAML；
2. 可导入Swagger Editor、Swagger UI或Postman；
3. 包含title、version、server、path、method；
4. 包含请求参数和Schema；
5. 包含成功/失败响应；
6. 包含示例值；
7. 包含鉴权说明；
8. 包含幂等/状态规则；
9. 明确当前本地Mock地址与未来目标地址的边界；
10. 与页面“连接配置”字段含义一致。

如果当前接口可以在本地Mock服务实际调用，则文档示例应能够直接用于该调用；如果属于目标接口，则必须明确标记为“目标契约/未实际接入”。

## 6. 公告正文与附件

正文支持：

- 富文本编辑；
- 正文图片；
- HTML导入；
- TXT导入。

附件可支持：

- 图片；
- PDF；
- Word 文档；
- XLS/XLSX；
- TXT；
- ZIP。

Word文件仅作为附件，不提供公告正文解析导入。

## 7. 当前验收依据

- 主SRS；
- 功能清单；
- 页面与业务链路验收清单；
- SSO/TODO/MESSAGE/API统一规范；
- 当前代码与数据库持久化的演示数据（第三方身份与上下游接口仍为模拟或预留）；
- npm test / npm run build结果。

真实外部系统是否可连接，不作为当前原型验收结论。
