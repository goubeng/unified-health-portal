# 移动端原型实现范围（代码对照 2026-10-12）

> 性质：**当前 Vue/TDesign Mobile 高保真原型实现记录**，不是独立于《卫健统一门户系统需求规格说明书》的第二套需求基线，也不代表已通过移动端全量人工验收。来源：`src/mobile/routes.ts`、`src/mobile/MobileShell.vue` 和各独立组件；权限与业务状态仍以门户服务为准。

## 1. 路由及页面清单

| 路由 | 页面 | 核心交互 |
|---|---|---|
| `/m` | 入口 | 重定向 `/m/home` |
| `/m/home` | 首页 | 业务入口、我的申请快捷入口、最新公告及应用跳转 |
| `/m/todos` | 待办事项 | 标题搜索、待办列表、待办详情弹窗与去处理 |
| `/m/messages` | 消息中心 | 消息查看与未读提示，详情通过页面查询参数承载 |
| `/m/apps` | 全部应用 | 分类侧栏、应用搜索、应用访问或账号处理、我的申请快捷入口 |
| `/m/profile` | 我的 | 用户个人入口与相关服务导航 |
| `/m/announcements` | 通知公告 | 公告列表 |
| `/m/announcements/:id` | 公告详情 | 公告内容与附件 |
| `/m/applications` | 我的申请 | 应用访问申请/账号开通申请分组与进度 |
| `/m/applications/:id` | 申请详情 | 申请信息、审核信息及状态允许的操作 |

实际页面是否达到最终用户体验要求，以移动端浏览器验收结果为准。

## 2. 导航和返回上下文

- `MobileShell.vue` 底部主导航是“首页、待办事项、消息中心、全部应用、我的”，采用 `tdesign-mobile-vue` TabBar。
- “我的申请”列表与独立详情页隐藏底部导航，使用顶部返回；公告、申请等详情不因此增加独立主导航项目。
- 从首页进入我的申请时携带 `from=home`，从全部应用进入携带 `from=apps`；申请详情返回申请列表时继续保留 `from` 与申请类型 Tab；从申请列表返回时依据来源进入首页、全部应用或默认“我的”。
- 消息详情使用 `messageId` 查询参数，详情状态下隐藏底部导航。
- 首页、列表和详情进入/返回过程需要验证 Tab 选中、滚动、遮罩层与返回路径是否符合移动端规范。

## 3. 详情与弹窗

- 待办列表点击详情，打开移动端专用弹窗；**弹窗标题直接使用该待办标题**，右上角有关闭图标，不应额外出现“待办详情”固定标题或冗余“关闭”按钮。仅待处理状态出现“去处理”操作。
- 我的申请详情是 `/m/applications/:id` 的独立路由，展示申请信息、审核信息及按状态可执行的操作，不当作 PC 端的通用详情弹窗。
- 账号确认/应用访问结果使用 `MobileAccountBindingModal.vue` 等移动端专用组件；不要套用 PC 的 `AccountBindingWizard.vue` 弹窗边距、关闭按钮或尺寸。
- 弹窗打开时遮罩应覆盖底部导航，不允许导航浮在遮罩上方；关闭后应恢复原列表上下文。

## 4. 与 PC 和数据服务的边界

- PC 公众全部应用采用关键词/系统分类查询；移动端“全部应用”使用应用关键词及分类侧栏，其视觉与交互不必与 PC 查询栏同形。
- 移动端与 PC 共享用户可见范围、应用访问和子系统账号关联、待办/消息/公告、申请审核结果等业务语义，不能将演示跳转当作真实 SSO 成功。
- 终态由来源系统模拟或推送回写；“去处理”不直接修改待办为已处理。
- 与 PC 业务数据共用门户服务，但移动端布局和交互依照移动端组件规范分别验收。当前真实上层认证及 42 个子系统外部联调不在已完成范围。
