# 页面规格（V1.0）

> 基线：V20260920-03。

## PG-001 统一登录

用户端和平台管理端共用同一个 `/login`，不建设两套独立登录页。

登录页提供三个入口/Tab：

### 公众用户

- 身份来源：闽政通；
- 扫码/手机号等具体能力按外部身份源接口；
- 登录成功默认进入用户端。

### 政务用户

- 身份来源：闽政务；
- 扫码/手机号/上层免登等具体能力按外部身份源接口；
- 登录成功默认进入用户端；
- 若拥有有效门户管理角色，可在登录后进入/切换平台管理端。

### 管理账号

目标正式能力：门户本地账号密码登录。

A阶段原型演示方式：
- 页面必须展示“用户账号、登录密码、验证码、登录”完整登录组件；
- 默认账号可展示 `admin01`，密码和验证码可提供演示默认值；
- 验证码组件仅用于页面形态展示，可点击刷新；
- 点击“登录”后直接以 `MOCK_LOCAL_ADMIN` 建立Mock Portal Session；
- A阶段不校验账号、不校验密码、不校验验证码；
- A阶段不读取本地数据库；
- 页面应明确提示“当前为Mock演示，输入内容不参与真实认证”。

正式环境规则仍保留：
- 用户必须为LOCAL来源；
- 账号必须启用且未锁定；
- 密码校验通过；
- 必须拥有有效管理角色；
- 首次登录可强制改密；
- 登录成功第一阶段默认进入平台管理端。

公众/政务手机号登录的滑块属于其各自Mock登录流程，本次管理账号调整不影响这两类入口。

三类方式认证成功后统一创建 Portal Session，再根据用户类别和门户角色决定可访问端。

## PG-002 认证结果

覆盖：
- 登录成功；
- 认证失败；
- 账号停用；
- 账号锁定；
- 无管理权限；
- 外部认证异常；
- Session建立失败。

## PG-101 用户首页

用户端默认面向CITIZEN/GOV。顺序：待办 → 公告 → 消息 → 我的应用。Loading结束前不得显示Empty。

## PG-102/103 应用中心

根据用户类别、应用适用范围、访问模式和入口资格决定按钮：

- 进入应用；
- 关联账号；
- 继续验证；
- 等待审核；
- 处理关联冲突；
- 申请使用；
- 查看申请。

### BIND关联账号交互

当应用需要BIND且当前用户无有效BOUND映射：

1. 门户先尝试可信唯一标识匹配；
2. 无可信ID时，可用姓名+已登记手机号、姓名+工号等查找候选账号；
3. 候选匹配成功后不得直接绑定，进入二次验证；
4. 验证方式按子系统能力显示：
   - 跳转子系统认证；
   - 向子系统登记手机号发送验证码；
   - 上层身份重新认证；
   - 原系统账号一次性校验；
   - 提交管理员审核；
5. 普通账号验证通过后可BOUND；
6. 高权限账号按配置进入“待审核”；
7. 账号已绑定其他门户用户或匹配多条时显示“关联冲突”，不得自动覆盖。

用户输入子系统密码时页面必须明确“仅用于本次验证、不保存”。

### Mock原型演示要求

本阶段即使没有真实外部接口，也必须把未来真实交互完整体现在前端。

应用卡片按状态显示：

- DIRECT可访问 → 进入应用；
- BIND/UNBOUND → 关联账号；
- VERIFYING → 继续验证；
- REVIEWING → 查看进度；
- BOUND → 进入应用；
- FAILED → 重新关联；
- CONFLICT → 查看异常；
- REQUEST未申请 → 申请使用；
- REQUEST/PENDING → 查看申请；
- REQUEST/APPROVED → 进入或继续关联；
- REQUEST/REJECTED → 查看原因/重新申请；
- 未开户 → 申请开通/前往原系统；
- 子系统账号停用 → 查看原因。

账号关联采用三步向导：

```text
查找账号
→ 身份验证
→ 关联结果
```

“查找账号”支持自动查找和输入已有账号；候选结果至少显示账号、姓名、脱敏手机号、所属单位、账号状态。

“身份验证”根据Mock应用配置支持：

- 子系统跳转认证模拟；
- 子系统原登记手机号验证码；
- 原系统账号密码一次性验证；
- 闽政通/闽政务重新认证模拟；
- 提交管理员审核。

演示环境可固定OTP为 `123456`，但必须明显标记“演示验证码”。

未找到账号时，根据应用Mock配置显示：

- 申请开通账号；
- 前往原系统开通；
- 联系系统管理员。

LOCAL首期不默认参与普通应用中心业务。

## PG-109 我的申请

路由：`/portal/applications`

建议两个Tab：

1. 应用访问申请；
2. 子系统账号开通申请。

应用访问申请字段：

- 申请编号；
- 应用名称；
- 申请时间；
- 申请原因；
- 状态；
- 审核时间；
- 审核意见；
- 操作。

操作规则：

- PENDING：查看/撤回；
- APPROVED：查看，并根据应用规则显示“进入应用/继续关联”；
- REJECTED：查看原因/重新申请；
- WITHDRAWN/EXPIRED：查看。

子系统账号开通申请字段：

- 申请编号；
- 应用名称；
- 申请人；
- 申请时间；
- 开通状态；
- 处理说明；
- 操作。

COMPLETED后显示“去关联”。

## PG-110~112 应用访问交互弹窗

### 申请使用

REQUEST应用显示申请表单：

- 应用名称；
- 申请人；
- 所属组织；
- 申请原因*；
- 联系方式；
- 备注。

### 账号开通申请

当BIND未找到账号时，根据应用配置允许发起Mock账号开通申请。

必须明确：

> 门户只承接/演示申请流程，子系统账号是否创建仍由目标子系统负责。

### 失败结果

不同错误码给出不同下一步，不允许统一显示“关联失败”。

至少覆盖：

- ACCOUNT_NOT_FOUND；
- INVALID_CREDENTIALS；
- OTP_INVALID；
- OTP_EXPIRED；
- ACCOUNT_DISABLED；
- ACCOUNT_ALREADY_BOUND；
- MULTIPLE_CANDIDATES；
- REVIEW_REQUIRED；
- UPSTREAM_UNAVAILABLE；
- ACCOUNT_MAPPING_CONFLICT。

### 详情/处理能力

- 查看匹配依据和验证方式；
- 查看验证/审核履历；
- 审核高权限账号关联；
- 管理员人工关联；
- 处理 CONFLICT；
- 解绑/重绑；
- 查看关联异常。

规则：

- application_id + external_user_id存在有效BOUND时不得被其他用户直接覆盖；

- 高权限账号可要求REVIEWING；
- 子系统账号DISABLED不等于映射关系被删除，应分别展示账号状态与映射状态。

LOCAL通常无子系统映射；页面允许显示“无映射需求”，不得制造虚假映射。

### 外部用户操作

允许：
- 查看
- 门户启停

- 闽政通/闽政务来源

- 编辑门户资料
- 启停

- 重置密码

密码、密码Hash不得出现在列表/详情/API响应中。

## PG-229 组织管理

政务用户组织优先闽政务；LOCAL组织可选；公众用户不强制组织。

组织首期主要用于资料、公告范围和查询，不作为复杂RBAC数据范围的首期前置条件。

## PG-230 字典管理

承接应用系统分类、公告类型、组织类型等业务字典。

## PG-231 应用访问申请

管理员审核门户入口资格，不审核子系统业务角色。

支持：

- 查询；
- 列表；
- 详情；
- 通过；
- 驳回；
- 操作履历。

用户端提交后应立即在管理端Mock数据中可见，审核结果同步回用户端“我的申请”。

## PG-232 账号关联审核

处理REVIEWING：

- 查看用户和应用；
- 查看候选账号；
- 查看匹配依据；
- 查看验证方式及结果；
- 查看风险级别；
- 通过/驳回；
- 记录审核说明。

## PG-233 关联冲突处理

处理CONFLICT：

- 当前用户；
- 子系统账号；
- 已绑定用户；
- 冲突原因；
- 匹配/验证证据；
- 保留原绑定；
- 驳回当前绑定；
- 解除原绑定后重绑（必须二次确认）；
- 处理说明。

用户端与管理端必须共用同一Mock数据源，处理完成后状态同步。

- 详情不叠加无意义外层卡片。

## PG-234 子系统账号开通申请

路由：`/admin/account-opening-requests`。

用于A阶段Mock演示“未找到子系统账号 → 用户提交开通申请 → 管理端处理 → 用户继续关联”闭环。

字段建议：
- 申请编号；
- 申请人；
- 应用名称；
- 申请原因；
- 申请时间；
- 处理状态；
- 处理说明；
- 操作。

边界：门户仅承接/展示申请状态，不代表门户拥有目标子系统账号创建权。A阶段的“模拟已开通”仅用于原型演示，真实开通必须由子系统在C阶段联调后返回结果。
