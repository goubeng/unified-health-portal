# 页面规格（V1.0）

> 基线：V20260921-01。
>
> 本页面规格仅约束页面业务内容、字段、状态、权限和交互行为；具体视觉设计、组件选型、字号、颜色、间距、图标及视觉验收标准由配套设计规范定义，不在本文件重复约束。
> 本文件描述业务页面要求，不记录阶段进度或验收结果；外部系统认证与接口对接以双方确认的实施及联调条件为准。

## PG-001 统一登录

用户端与平台管理端共用 `/login`，提供公众、政务与管理用户的身份入口。

### 公众用户

- 身份来源：闽政通，用户类别为 `CITIZEN`；
- 根据闽政通提供的方式支持扫码与手机号登录，完成二维码过期、刷新及短信安全校验；
- 登录认证由权威身份平台完成；门户仅接收认证结果并建立相应访问会话；
- 未注册和忘记密码等情况转至上层身份平台办理。

### 政务用户

- 身份来源：闽政务，用户类别为 `GOV`；
- 支持闽政务提供的适用身份认证方式及异常处理；
- 门户依据认证结果、用户启用状态和访问范围建立会话。

### 管理账号

- 支持已获管理授权的外部身份及门户本地管理账号；
- 账号密码、安全验证码等校验按管理账号的认证策略执行；
- 登录成功后校验管理主体是否有效及门户角色、页面和操作权限；
- 对认证失败、停用、锁定或无权限场景给出明确提示，不允许越权进入管理端。

## PG-002 认证结果

路由：`/auth/result`。

通过认证结果状态统一展示：
- `SUCCESS`：认证成功；
- `FAILURE`：认证失败；
- `DISABLED`：账号停用；
- `LOCKED`：账号锁定；
- `NO_PERMISSION`：认证成功但无平台管理权限；
- `UPSTREAM_ERROR`：闽政通/闽政务等外部认证异常；
- `SESSION_ERROR`：Portal Session建立失败。

页面显示认证来源、结果状态、可选请求ID。操作规则：
- SUCCESS：已有Portal Session时进入目标端；未建立Session时返回登录；
- NO_PERMISSION：已有用户Session时允许返回用户端；
- FAILURE / UPSTREAM_ERROR / SESSION_ERROR：重新登录；
- DISABLED / LOCKED：返回登录并提示联系门户管理员。

## PG-101 用户首页

用户端默认面向 CITIZEN/GOV。展示顺序：待办 → 公告 → 消息 → 我的应用。Loading 完成前不得显示 Empty。

首页交互：
- “全部待办 / 全部公告 / 全部消息”分别进入对应列表页；
- 点击待办、公告、消息标题查看该条记录详情；
- 首页“我的待办”条目展示来源应用和接收时间；
- 首页“消息”区域只展示当前用户未读消息，已读消息仍在消息中心完整列表中查看；
- 仅可处理待办显示“去处理”，点击后进入来源业务子系统办理页面；
- “我的应用”标题旁展示当前用户可访问应用总数；
- “我的应用”只统计并展示当前已具备正常入口资格的应用，即 DIRECT 或有效 BOUND；
- 首页最多展示8个“我的应用”，按既有显示顺序排列；不足8个时全部展示；
- 首页提供进入“全部应用”的快捷入口，查看完整应用目录和个人可用应用；
- 我的应用卡片“进入”用于进入目标应用；
- 首页仅承担聚合和快捷入口作用，不替代各模块完整列表、详情和处理页面。

## PG-104 待办事项

路由：`/portal/todos`。

查询条件：
- 待办标题；
- 来源应用；
- 状态。

列表字段：
- 序号；
- 待办标题；
- 来源应用；
- 业务类型；
- 状态；
- 接收时间；
- 操作。

交互：
- 点击“待办标题”打开待办详情；
- 首页“我的待办”和“待办事项”列表打开的详情展示相同业务信息和操作规则；
- 详情展示待办标题、来源应用、业务类型、接收时间、状态、待办说明；
- “源待办ID”不对用户展示，仅内部保留；
- 不展示优先级、截止时间、逾期、来源版本、终态时间；
- 仅 `PENDING` 状态显示“去处理”；
- 门户不根据时间生成“已逾期/已过期”状态；
- “去处理”前继续执行应用启用、入口资格、账号映射等必要校验，校验通过后跳转来源业务子系统。

状态首期只保留：`PENDING / COMPLETED / WITHDRAWN`。

排序：待处理优先，其余按接收时间近到远。

## PG-102/103 全部应用

PC 公众门户查询包含应用名称/应用编码关键词、系统分类和归属子系统；**不显示**“综合运行状态”“适用用户”查询（两者仅限管理端应用管理视角）。归属子系统和系统分类分别筛选，多个条件取交集。

归属子系统查询和“按开通情况 / 按所属系统”分组视图仅用于 PC 门户 `/portal/apps/all`。移动端 `/m/apps` 保留现有关键词搜索、左侧应用分类栏和页面样式，头部不增加归属子系统或视图切换按钮。

用户端以“当前结果 + 下一步操作”为核心，不要求用户理解门户内部访问模式、账号匹配方式或验证状态机。

用户可见操作统一收敛为：

- 进入应用；
- 申请使用；
- 申请使用（其它应用卡片初始入口）；
- 查看进度；
- 重新处理 / 查看原因。

### 应用分组展示规则

- PC 默认选中“按开通情况”视图，按“我的应用 / 其它应用”分组；切换至“按所属系统”后按归属子系统分组，不增加导航菜单；
- 两种视图共用当前用户可见且符合查询条件的应用结果，切换视图不改变权限、访问状态或操作；按所属系统视图显示各组名称和组内应用，历史或异常数据中未配置归属的应用单独显示为“未设置归属子系统”；
- 现行清单中第 42 项已划掉、第 43 项保留，42 个应用分别归入 7 个整合后平台；应用系统分类不因归属变化而改变；
- “我的应用”只包含当前已经可正常使用的应用，即内部已满足 DIRECT 或有效 BOUND 条件的应用；
- “我的应用”不重复显示“已关联/可访问”等正常状态标签；
- “其它应用”展示仍需申请、账号确认、等待处理或异常处理的应用；
- 用户端状态文案使用“待申请、申请处理中、需确认账号、处理中、账号不可用、账号异常”等业务表达，不直接展示 BIND / VERIFYING / REVIEWING / CONFLICT 等内部状态代码；
- 应用卡片第一行显示应用名称，第二行只显示应用类型，第三行独立显示“状态 + 操作”，例如“账号异常 / 查看原因”，避免状态与应用类型挤在同一行；
- 对需要进入账号确认流程但尚未开始处理的其它应用，卡片主操作统一显示“申请使用”，点击后再进入具体账号确认流程；

**视图组件与查询栏布局（PC）**：两个选项采用同一个胶囊状分段切换组件，默认整体白色背景、未选中深色文字，选中项为系统蓝底白字，外围细边框；与关键词、系统分类、归属子系统及重置按钮处于同一查询工具栏，查询靠左，视图切换靠右；窄屏可整体换行但不拆分两个选项。切换视图保留当前筛选条件。

**卡片展示（PC）**：两种视图均按分组直接显示当前筛选结果的全部卡片和准确数量；不显示组内页码、每页条数、跳页器，不按 20 条截断。移动端仍使用现有关键词搜索和分类侧栏，首页“我的应用”快捷卡片数量不受此规则影响。

### 账号确认交互

门户内部仍可根据 AUTO / SELF / REVIEW / ADMIN、候选账号、验证方式和映射状态执行判断，但用户端不展示“查找候选账号 → 选择验证方式 → 输入验证码/密码”等底层处理过程。

当应用需要确认子系统账号时：

1. 门户先在后台判断当前用户是否已具备有效访问关系；
2. 若可信唯一标识可以唯一确认，可直接完成账号确认并返回成功结果；
3. 若需要历史账号、密码、验证码或子系统自身身份核验，用户端仅提示“需要完成账号确认”，并提供“前往子系统确认”；
4. 历史账号、密码、验证码等凭据信息原则上在目标子系统完成输入与校验，统一门户不采集、不保存；
5. 子系统处理完成后，用户返回门户执行“完成后重新检测”，门户根据返回结果或后续接口状态更新可访问状态；
6. 高权限账号如需管理员审核，用户端显示“处理中/账号确认已提交”；
7. 账号冲突、账号停用、处理失败等情况直接显示结果和下一步，不向用户暴露内部匹配规则。

当未检测到可用子系统账号时：

- 用户端显示“需要开通账号”；
- 原则上提供“前往子系统开通”，由目标子系统完成注册/开户；
- 门户不直接创建子系统账号；
- 若后续目标子系统提供标准开户申请接口，门户可以承接申请提交与状态回显，但账号创建责任仍属于目标子系统。

应用卡片按用户可见结果显示：

- 已满足访问条件 → 进入应用；
- 尚未取得入口资格 → 申请使用；
- 入口申请处理中 → 查看申请；
- 申请未通过 → 查看原因 / 重新申请；
- 需要确认已有账号 → 申请使用（进入后续账号确认流程）；
- 账号确认处理中 → 查看进度；
- 处理失败 → 重新处理；
- 账号关系异常 → 查看原因；
- 未检测到账号 → 前往子系统开通；
- 子系统账号停用 → 提示账号不可用并联系目标系统管理员。

门户本地管理账号不属于用户端访问主体，不参与普通全部应用业务。
## PG-109 我的申请

路由：`/portal/applications`

建议两个Tab：

1. 应用访问申请；
2. 子系统账号开通申请。

应用访问申请字段：

- 申请编号；
- 应用名称；
- 申请时间；
- 申请原因；
- 状态；
- 审核时间；
- 审核意见；
- 操作。

详情与操作规则：

- 申请编号作为详情入口，操作列不重复提供“查看”；
- PENDING：撤回；
- APPROVED：根据应用规则显示“进入应用/完成账号确认”；
- REJECTED：重新申请，驳回原因在详情中查看；
- WITHDRAWN/EXPIRED：仅通过申请编号进入详情。

子系统账号开通申请字段：

- 申请编号；
- 应用名称；
- 申请人；
- 申请时间；
- 开通状态；
- 处理说明；
- 操作。

子系统账号开通申请同样以申请编号作为详情入口，操作列不重复提供“查看”；COMPLETED后显示“去关联”。

必须明确：

> 门户只承接申请与状态，不拥有目标子系统账号创建权。

- INVALID_CREDENTIALS；
- OTP_INVALID；
- OTP_EXPIRED；
- ACCOUNT_DISABLED；
- ACCOUNT_ALREADY_BOUND；
- MULTIPLE_CANDIDATES；
- REVIEW_REQUIRED；
- UPSTREAM_UNAVAILABLE；
- ACCOUNT_MAPPING_CONFLICT。

## PG-201 管理首页

面向拥有门户管理角色的用户，作为门户管理工作台。

页面包含以下业务区域：

1. 顶部概览：纳管应用、启用应用、门户访问用户、接入异常应用；
2. 待处理事项；
3. 常用管理；
4. 接入运行状态；
5. 接入异常。

业务规则：
- 接入运行状态按 SSO / TODO / MESSAGE 分别统计正常、异常、未配置/停用数量；
- 接入异常按最近检测时间展示异常服务；一个应用多个服务异常时分别展示；
- 公告常用入口为“新增公告”，点击后进入通知公告管理并直接发起新增公告；
- 其他主要入口包括应用列表、用户管理、身份与子系统映射。

规则：
- 删除“正常应用 / 异常应用”综合指标；
- 顶部“接入异常应用”按应用列表综合运行状态为“异常”的应用去重统计；右侧“接入异常”仍逐条展示异常服务；
- 顶部不再重复放“待审核申请”；
- 映射异常不混入“接入异常”列表；
- “异常接入消息”统一改名“接入异常”；
- “集成运行健康”统一改名“接入运行状态”；
- “管理提醒”统一改名“待处理事项”；
- “管理工作”统一改名“常用管理”。
- “访问与调用趋势”支持“门户访问量”和“接口调用量”指标切换，曲线、数据点、面积填充随指标一并切换配色：门户访问量使用青绿色（#0D9488），接口调用量使用紫色（#7C3AED）；与登录/认证日志、接口调用日志对应面积图保持一致。统计口径及近7天、近30天时间切换不变。

## PG-202 应用列表

路由：`/admin/apps`。

查询条件：

- 应用名称 / 应用编码；
- 系统分类；
- 归属子系统；
- 综合运行状态；
- 启用状态；
- 适用用户。

查询条件筛选规则：

- “启用状态”按应用实际 `enabled` 字段筛选：“启用”只匹配启用应用，“停用”只匹配停用应用；
- “适用用户”按应用配置值精确匹配：“公众用户”只匹配 CITIZEN，“政务用户”只匹配 GOV，“公众及政务”只匹配 BOTH；
- 未选择查询条件时不限制对应字段，展示管理端权限范围内的全部纳管应用。

管理端应用列表不得按照当前管理员本人的用户类别过滤数据。

列表字段：

- 序号；
- 应用名称；
- 应用编码；
- 系统分类；
- 归属子系统；
- 适用用户；
- 访问模式；
- 综合运行状态；
- 启用状态；
- 操作。

应用名称作为详情入口；详情弹窗直接显示“基本信息”“连接信息”，不显示单独的“应用信息”或“状态变更记录”Tab，状态变更历史统一在运行监控应用详情中查看。操作提供编辑、连接配置和删除。所有应用均支持删除，不区分预置应用和后续新增应用。删除前需二次确认，并同步清理其连接配置、运行样本、账号映射、申请、待办、消息等关联业务数据；审计与接入状态变更历史保留追溯。

归属子系统由 7 个整合后平台稳定目录提供；新增应用必须选择归属，编辑已有应用可以修正归属。历史或异常数据缺少归属时显示“未归属”，不得按系统分类或名称推断。保存后应从数据库重新读取归属编码和名称；调整归属不改变应用访问资格、账号映射和接入状态。

综合运行状态：应用停用优先显示“停用”；启用应用的 SSO 为必需能力，启用的 TODO / MESSAGE 也计入必需能力，存在“异常、停用、未配置”时按该顺序判定，全部必需能力正常才显示“正常”。编辑弹窗的“启用状态”位于“访问模式”后，以开关呈现，改变启停需具备独立启停权限。

排序与编辑：
- 应用名称、应用编码、综合运行状态、适用用户支持表头排序；
- 编辑已有应用时不显示“显示排序”字段；新增应用仍允许设置初始显示排序。

本页面只管理门户访问主体与子系统账号映射，不展示门户本地管理账号。

### 映射列表建议显示

- 用户
- 用户类别

## PG-220 / PG-235 公告管理

支持草稿、立即发布、定时发布、预览、正文插图、附件、已发布编辑、撤回、撤回后重新编辑/发布、按状态删除和永久有效。正文导入支持 HTML/TXT。

新增公告、草稿编辑及定时公告编辑提供相同的业务字段和操作集合：“取消、预览、保存草稿、立即发布/定时发布”。DRAFT可选择立即发布或定时发布；SCHEDULED编辑时默认保持定时发布，但允许切换为立即发布。选择立即发布时不需要定时发布时间；选择定时发布时必须填写未来的定时发布时间，禁选过去日期及当天已经过去的小时/分钟/秒，并在提交前和服务端再次校验。状态文案只显示“定时发布”，不带“（展示）”。SCHEDULED点击“保存草稿”时取消原定时计划并回到DRAFT。

失效时间统一改为“失效日期”：
- 仅选择日期，不显示时间选择；
- 留空表示永久有效；
- 选择日期后按当天23:59:59作为有效截止时间。

公告详情/编辑交互：
- 用户端打开公告详情时，左侧“通知公告”菜单保持选中；
- 管理端打开公告详情时，左侧“通知公告管理”菜单保持选中；
- 管理端公告详情与用户端复用同一详情内容组件，在右侧内容区打开，不使用详情弹窗；
- 管理端“编辑公告”采用编辑弹窗；
- 从公告列表点击“编辑”直接打开编辑弹窗，取消/关闭后保持在列表页，不跳详情；
- 从公告详情点击“编辑”打开编辑弹窗，取消/关闭后保持在当前详情；
- 新增、草稿、定时发布三种场景提供一致的业务字段与操作集合；
- 草稿编辑：显示发布方式，可“保存草稿”或直接“立即发布 / 定时发布”，选择定时发布时才显示定时发布时间；
- 定时发布公告编辑：继续显示发布方式，默认定时发布；可“保存草稿”取消定时计划并回到DRAFT，也可更新定时发布时间后再次“定时发布”，或切换立即发布后直接转为PUBLISHED；
- 已发布公告编辑：不显示发布方式，保存修改后直接生效；
- 已撤回公告：允许编辑和删除；编辑弹窗与新增、草稿、定时发布使用相同字段排布和Footer操作，可“保存草稿”转DRAFT，也可重新立即发布或定时发布；
- 已过期公告：禁止编辑，只允许删除；
- 新增公告继续使用新增弹窗；
- 新增和编辑公告均支持“全屏 / 退出全屏”，全屏时正文区域内部滚动，关闭后再次打开默认恢复普通尺寸；
- 富文本工具栏支持加粗、斜体、下划线等格式与“清空正文”；选择文字点击斜体后，应作用于原选区，并在编辑、预览和展示时可见；
- 附件最多5个，单个附件最大20MB。

撤回/删除确认：
- 撤回操作需要确认；
- 删除操作需要二次确认，并明确删除后不可从当前列表恢复；
- 列表与公告详情页使用相同的状态操作权限：WITHDRAWN显示“编辑、删除”，编辑后允许转草稿或重新发布；EXPIRED仅显示“删除”。
