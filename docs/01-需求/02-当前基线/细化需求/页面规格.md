# 页面规格（V1.0）

> 基线：V20260920-03。
>
> 本页面规格仅约束页面业务内容、字段、状态、权限和交互行为；当前 Mock 原型中的组件库、字号、颜色、字重、间距、图标、卡片、弹窗尺寸等视觉细节仅用于原型调试，不作为正式系统 UI 规范或最终验收依据。

## PG-001 统一登录

用户端和平台管理端共用同一个 `/login`，不建设两套独立登录页。

登录页提供三个入口/Tab：

### 公众用户

- 身份来源：闽政通；
- 扫码/手机号等具体能力按外部身份源接口；
- 登录成功默认进入用户端。

### 政务用户

- 身份来源：闽政务；
- 扫码/手机号/上层免登等具体能力按外部身份源接口；
- 登录成功默认进入用户端；
- 若拥有有效门户管理角色，可在登录后进入/切换平台管理端。

### 管理账号

目标正式能力：门户本地账号密码登录。

A阶段原型演示方式：
- 页面必须展示“用户账号、登录密码、验证码、登录”完整登录组件；
- 默认账号可展示 `admin01`，密码和验证码可提供演示默认值；
- 验证码组件可点击刷新；
- 点击“登录”后直接以 `MOCK_LOCAL_ADMIN` 建立Mock Portal Session；
- A阶段不校验账号、不校验密码、不校验验证码；
- A阶段不读取本地数据库；
- 页面不得显示“原型演示 / Mock演示 / 演示验证码 / 默认演示账号 / 密码和验证码可任意填写”等研发说明文案。

正式环境规则仍保留：
- 用户必须为LOCAL来源；
- 账号必须启用且未锁定；
- 密码校验通过；
- 必须拥有有效管理角色；
- 首次登录可强制改密；
- 登录成功第一阶段默认进入平台管理端。

公众/政务手机号登录的滑块属于其各自Mock登录流程，本次管理账号调整不影响这两类入口。

三类方式认证成功后统一创建 Portal Session，再根据用户类别和门户角色决定可访问端。

## PG-002 认证结果

路由：`/auth/result`。

通过认证结果状态统一展示：
- `SUCCESS`：认证成功；
- `FAILURE`：认证失败；
- `DISABLED`：账号停用；
- `LOCKED`：账号锁定；
- `NO_PERMISSION`：认证成功但无平台管理权限；
- `UPSTREAM_ERROR`：闽政通/闽政务等外部认证异常；
- `SESSION_ERROR`：Portal Session建立失败。

页面显示认证来源、结果状态、可选请求ID。操作规则：
- SUCCESS：已有Portal Session时进入目标端；未建立Session时返回登录；
- NO_PERMISSION：已有用户Session时允许返回用户端；
- FAILURE / UPSTREAM_ERROR / SESSION_ERROR：重新登录；
- DISABLED / LOCKED：返回登录并提示联系门户管理员。

A阶段使用Query参数模拟不同认证结果；C阶段由真实认证回调映射相同状态，不改变页面结构。

- 来源应用；
- 状态。

列表字段：
- 序号；
- 待办标题；
- 来源应用；
- 业务类型；
- 状态；
- 接收时间；
- 操作。

交互：
- 点击“待办标题”打开待办详情；
- 首页“我的待办”和“待办任务”列表打开的详情展示相同业务信息和操作规则；
- 详情展示待办标题、来源应用、业务类型、接收时间、状态、待办说明；
- “源待办ID”不对用户展示，仅内部保留；
- 不展示优先级、截止时间、逾期、来源版本、终态时间；
- 仅 `PENDING` 状态显示“去处理”；
- 门户不根据时间生成“已逾期/已过期”状态；
- “去处理”继续执行应用启用、入口资格、账号映射等校验，A阶段返回Mock访问结果，C阶段切换真实子系统跳转。

状态首期只保留：`PENDING / COMPLETED / WITHDRAWN`。

排序：待处理优先，其余按接收时间近到远。

## PG-102/103 应用中心

用户端以“当前结果 + 下一步操作”为核心，不要求用户理解门户内部访问模式、账号匹配方式或验证状态机。

用户可见操作统一收敛为：

- 进入应用；
- 申请使用；
- 完成账号确认；
- 查看进度；
- 重新处理 / 查看原因。

### 应用分组展示规则

- “我的应用”只包含当前已经可正常使用的应用，即内部已满足 DIRECT 或有效 BOUND 条件的应用；
- “我的应用”不重复显示“已关联/可访问”等正常状态标签；
- “其它应用”展示仍需申请、账号确认、等待处理或异常处理的应用；
- 用户端状态文案使用“待申请、申请处理中、需确认账号、处理中、账号不可用、账号异常”等业务表达，不直接展示 BIND / VERIFYING / REVIEWING / CONFLICT 等内部状态代码；

### 账号确认交互

门户内部仍可根据 AUTO / SELF / REVIEW / ADMIN、候选账号、验证方式和映射状态执行判断，但用户端不展示“查找候选账号 → 选择验证方式 → 输入验证码/密码”等底层处理过程。

当应用需要确认子系统账号时：

1. 门户先在后台判断当前用户是否已具备有效访问关系；
2. 若可信唯一标识可以唯一确认，可直接完成账号确认并返回成功结果；
3. 若需要历史账号、密码、验证码或子系统自身身份核验，用户端仅提示“需要完成账号确认”，并提供“前往子系统确认”；
4. 历史账号、密码、验证码等凭据信息原则上在目标子系统完成输入与校验，统一门户不采集、不保存；
5. 子系统处理完成后，用户返回门户执行“完成后重新检测”，门户根据返回结果或后续接口状态更新可访问状态；
6. 高权限账号如需管理员审核，用户端显示“处理中/账号确认已提交”；
7. 账号冲突、账号停用、处理失败等情况直接显示结果和下一步，不向用户暴露内部匹配规则。

当未检测到可用子系统账号时：

- 用户端显示“需要开通账号”；
- 原则上提供“前往子系统开通”，由目标子系统完成注册/开户；
- 门户不直接创建子系统账号；
- 若后续目标子系统提供标准开户申请接口，门户可以承接申请提交与状态回显，但账号创建责任仍属于目标子系统。

### 原型演示要求

A阶段继续保留内部 Mock 状态与固定场景，用于覆盖 DIRECT、REQUEST、账号确认、审核、失败、冲突和账号停用等分支；但用户侧页面按照正式产品形态展示，不显示“Mock、A阶段、候选账号、验证方式、演示验证码”等实现细节。

应用卡片按用户可见结果显示：

- 已满足访问条件 → 进入应用；
- 尚未取得入口资格 → 申请使用；
- 入口申请处理中 → 查看申请；
- 申请未通过 → 查看原因 / 重新申请；
- 需要确认已有账号 → 完成账号确认；
- 账号确认处理中 → 查看进度；
- 处理失败 → 重新处理；
- 账号关系异常 → 查看原因；
- 未检测到账号 → 前往子系统开通；
- 子系统账号停用 → 提示账号不可用并联系目标系统管理员。

LOCAL首期不默认参与普通应用中心业务。

## PG-201 管理首页

面向拥有门户管理角色的用户，作为门户管理工作台。

页面包含以下业务区域：

1. 顶部概览：纳管应用、启用应用、门户用户、接入异常；
2. 待处理事项；
3. 常用管理；
4. 接入运行状态；
5. 接入异常。

业务规则：
- 接入运行状态按 SSO / TODO / MESSAGE 分别统计正常、异常、未配置/停用数量；
- 接入异常按最近检测时间展示异常服务；一个应用多个服务异常时分别展示；
- 公告常用入口为“新增公告”，点击后进入通知公告管理并直接发起新增公告；
- 其他主要入口包括应用列表、用户管理、身份与子系统映射。

规则：
- 删除“正常应用 / 异常应用”综合指标；
- 接入异常按已配置且运行异常的服务数量统计，未配置/停用不算异常；
- 顶部不再重复放“待审核申请”；
- 映射异常不混入“接入异常”列表；
- “异常接入消息”统一改名“接入异常”；
- “集成运行健康”统一改名“接入运行状态”；
- “管理提醒”统一改名“待处理事项”；
- “管理工作”统一改名“常用管理”。

## PG-220 / PG-235 公告管理

支持草稿、立即发布、定时发布、预览、正文插图、附件、已发布编辑、撤回、撤回/失效删除、永久有效。导入方面：HTML/TXT正文导入已实现；`.docx`正文解析仍为已知缺口；`.doc`不支持。

新增公告、草稿编辑及定时公告编辑提供相同的业务字段和操作集合：“取消、预览、保存草稿、立即发布/定时发布”。DRAFT可选择立即发布或定时发布；SCHEDULED编辑时默认保持定时发布，但允许切换为立即发布。选择立即发布时不需要定时发布时间；选择定时发布时必须填写未来的定时发布时间。SCHEDULED点击“保存草稿”时取消原定时计划并回到DRAFT。

失效时间统一改为“失效日期”：
- 仅选择日期，不显示时间选择；
- 留空表示永久有效；
- 选择日期后按当天23:59:59作为有效截止时间。

公告详情/编辑交互：
- 用户端打开公告详情时，左侧“通知公告”菜单保持选中；
- 管理端打开公告详情时，左侧“通知公告管理”菜单保持选中；
- 管理端公告详情与用户端复用同一详情内容组件，在右侧内容区打开，不使用详情弹窗；
- 管理端“编辑公告”采用编辑弹窗；
- 从公告列表点击“编辑”直接打开编辑弹窗，取消/关闭后保持在列表页，不跳详情；
- 从公告详情点击“编辑”打开编辑弹窗，取消/关闭后保持在当前详情；
- 新增、草稿、定时发布三种场景提供一致的业务字段与操作集合；
- 草稿编辑：显示发布方式，可“保存草稿”或直接“立即发布 / 定时发布”，选择定时发布时才显示定时发布时间；
- 定时发布公告编辑：继续显示发布方式，默认定时发布；可“保存草稿”取消定时计划并回到DRAFT，也可更新定时发布时间后再次“定时发布”，或切换立即发布后直接转为PUBLISHED；
- 已发布公告编辑：不显示发布方式，保存修改后直接生效；
- 已撤回公告：允许编辑和删除；编辑保存后仍保持WITHDRAWN；
- 已过期公告：禁止编辑，只允许删除；
- 新增公告继续使用新增弹窗。

撤回/删除确认：
- 撤回操作需要确认；
- 删除操作需要二次确认，并明确删除后不可从当前列表恢复；
- 列表与公告详情页使用相同的状态操作权限：WITHDRAWN显示“编辑、删除”，EXPIRED仅显示“删除”。

## PG-223～PG-227 日志审计统一列表规则

- 五类日志列表最前统一增加“序号”列；
- “请求ID”作为日志详情链接，固定显示在序号后的第一业务列；
- 点击请求ID打开对应日志详情；
- 操作列不再重复提供“详情”；
- 其余业务字段按各日志类型依次展示。

## PG-223 登录/认证日志

字段：
- 序号
- 请求ID
- 登录时间
- 登录用户
- 登录账号
- 用户类别
- 身份来源
- 登录来源
- 登录方式
- 登录结果
- 失败原因
- IP
- 客户端

LOCAL：
- 用户类别=门户本地用户
- 身份来源=门户本地
- 登录方式=账号密码

## PG-228 用户管理

### 查询

- 姓名/账号（使用较紧凑的查询宽度）
- 用户类别
- 身份来源
- 门户角色
- 启用状态

### 列表

- 序号
- 用户账号
- 姓名
- 用户类别
- 身份来源
- 门户角色
- 启用状态
- 最近登录
- 操作

交互：
- “用户账号”作为详情入口，点击后弹出用户详情；
- 操作列不再重复提供“详情”按钮，仅保留编辑、重置密码、解除锁定等业务动作；
- 启用状态支持维护；
- 用户类别应明确区分公众用户、政务用户、门户本地用户；
- 新增/编辑用户时支持多选门户角色。

### 外部用户操作

允许：
- 查看
- 门户启停
- 分配门户角色（仅授权人员）
- 维护门户组织索引（必要时）

不允许修改：
- 闽政通/闽政务来源
- CITIZEN/GOV
- 权威姓名/手机号/账号

### 本地用户操作

超级管理员可：
- 新建
- 编辑门户资料
- 启停
- 分配角色
- 重置密码
- 解除锁定

密码、密码Hash不得出现在列表/详情/API响应中。

## PG-229 组织管理

政务用户组织优先闽政务；LOCAL组织可选；公众用户不强制组织。

组织首期主要用于资料、公告范围和查询，不作为复杂RBAC数据范围的首期前置条件。

交互：
- “组织编码”作为详情入口，点击后弹出组织详情；
- 操作列不再重复提供“详情”按钮，仅保留编辑、删除等业务动作；
- 编辑表单支持维护启用状态。

## PG-230 字典管理

承接应用系统分类、公告类型、组织类型等业务字典。

## PG-231 应用访问申请

管理员审核门户入口资格，不审核子系统业务角色。

支持：

- 查询；
- 列表；
- 详情；
- 通过；
- 驳回；
- 操作履历。

用户端提交后应立即在管理端Mock数据中可见，审核结果同步回用户端“我的申请”。

## PG-232 账号关联审核

处理REVIEWING：

- 查看用户和应用；
- 查看候选账号；
- 查看匹配依据；
- 查看验证方式及结果；
- 查看风险级别；
- 通过/驳回；
- 记录审核说明。

## PG-233 关联冲突处理

处理CONFLICT：

- 当前用户；
- 子系统账号；
- 已绑定用户；
- 冲突原因；
- 匹配/验证证据；
- 保留原绑定；
- 驳回当前绑定；
- 解除原绑定后重绑（必须二次确认）；
- 处理说明。

用户端与管理端必须共用同一Mock数据源，处理完成后状态同步。

## 全局加载与交互

- 未初始化、路由切换或重新读取数据时，应先进入 Loading 状态；
- 数据准备完成前不得误显示 Empty；
- 成功且真实返回 0 条时显示 Empty；
- 读取失败时显示 Error，并提供重试能力；
- 关键提交、确认、删除、撤回等操作应提供明确的结果反馈；
- 当前原型所使用的弹窗位置、组件类型、字号、图标、颜色、间距等不作为正式系统页面规格。

## PG-234 子系统账号开通申请

路由：`/admin/account-opening-requests`。

用于承接目标子系统提供标准开户申请接口时的申请状态管理。用户侧默认优先前往目标子系统完成开户，不强制经过门户申请。

字段建议：
- 申请编号；
- 申请人；
- 应用名称；
- 申请原因；
- 申请时间；
- 处理状态；
- 处理说明；
- 操作。

边界：门户仅承接/展示申请状态，不拥有目标子系统账号创建权。真实开通必须由目标子系统完成并返回结果；未提供标准开户接口的子系统不要求启用此能力。
