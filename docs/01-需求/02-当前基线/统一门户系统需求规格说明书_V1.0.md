# 卫健统一门户系统需求规格说明书 V1.0

> 版本：V1.0  
> 设计基线：V20260920-03  
> 日期：2026-09-20  
> 状态：下一阶段目标设计基线；当前代码仍为P4 Mock可运行基线。

## 1. 系统定位

卫健统一门户位于外部身份来源与各业务子系统之间，作为统一入口和中间层。

```text
外部身份来源
├─ 闽政通 → 公众用户
└─ 闽政务 → 政务用户

门户自有身份
└─ 门户本地账号 → 门户本地用户
                ↓
          卫健统一门户
                ↓
          各业务子系统
```

门户不是第三套完整社会/政务身份中心，但需要保留一套**门户本地账号体系**，主要用于平台维护人员在没有闽政通或闽政务身份时登录管理端。

## 2. 三种身份来源与用户类别

| 身份来源 | 用户类别 | 权威主体 | 默认使用场景 |
|---|---|---|---|
| 闽政通 | 公众用户 CITIZEN | 闽政通 | 用户端 |
| 闽政务 | 政务用户 GOV | 闽政务 | 用户端；具备门户角色时也可进入管理端 |
| 门户本地 | 门户本地用户 LOCAL | 卫健统一门户 | 默认用于管理端 |

关键规则：

1. 闽政通、闽政务、门户本地是**身份来源**。
2. 公众用户、政务用户、门户本地用户是**用户类别**。
3. 用户类别不是角色。
4. 门户本地用户不强制绑定闽政通或闽政务身份。
5. 第一阶段本地用户默认用于管理端；数据模型不限制未来扩展本地普通用户。
6. 闽政通/闽政务身份资料由外部身份源负责；门户本地账号资料和密码由门户负责。

## 3. 用户端与管理端

“用户端 / 管理端”是两个使用入口，不是两个互斥用户类型。

### 3.1 用户端

第一阶段主要面向：

- 闽政通公众用户；
- 闽政务政务用户。

应用可见和可访问由以下条件共同决定：

```text
用户类别
+ 应用适用用户
+ 应用启用状态
+ 访问模式 DIRECT/BIND/REQUEST
+ 门户应用入口资格
+ 子系统账号映射
```

### 3.2 管理端

能够进入管理端的前提是用户拥有有效门户管理角色。

管理端访问可来自：

- 门户本地账号 + 有效门户管理角色；
- 闽政务用户 + 门户管理角色；
- 其它外部身份 + 门户管理角色（能力保留，不作为主要场景）。

### 3.3 统一登录入口

用户端和平台管理端不建设两套独立登录页，统一使用 `/login`。

登录页提供：

- 公众用户 → 闽政通；
- 政务用户 → 闽政务；
- 管理账号 → PORTAL_LOCAL本地账号密码。

认证成功后统一创建Portal Session：

- CITIZEN/GOV默认进入用户端；
- CITIZEN/GOV拥有有效管理角色时允许进入/切换平台管理端；
- LOCAL拥有有效管理角色时第一阶段默认进入平台管理端；
- LOCAL没有管理角色时不得进入管理端。

A阶段原型说明：
- 管理账号页保留“用户账号、登录密码、验证码、登录”完整形态；
- A阶段点击“登录”直接进入默认Mock管理账号，不校验账号、密码、验证码，也不访问数据库；
- 正式账号密码、锁定、首次改密等安全校验仍属于B/C阶段真实能力，不因原型直登而取消。

## 4. 门户角色模型

考虑实际仅1～2名维护人员，默认角色收敛为两个：

| 角色 | 说明 |
|---|---|
| 门户超级管理员 | 全部门户管理权限；负责管理员、本地账号、角色和系统级配置 |
| 门户管理员 | 日常门户维护；默认覆盖应用、公告、映射、监控、日志等日常能力 |

底层仍保留RBAC能力：

- 菜单权限；
- 页面权限；
- 操作权限。

第一阶段不预置“应用管理员、公告管理员、集成管理员、审计管理员”等细分角色。后续如果确有多人分工，再按需新建自定义角色。

第一阶段两个默认管理角色的数据范围均可按 ALL_PORTAL 处理；ORG、ASSIGNED_APPS 等细粒度范围作为后续扩展能力，不作为P0复杂度。

## 5. 本地账号体系

门户本地账号主要解决：

> 门户维护人员没有闽政通或闽政务账号时，仍能独立登录平台管理端。

本地账号至少包括：

- 用户ID；
- 登录账号；
- 姓名；
- 手机号/邮箱（可选）；
- 密码凭证；
- 启用状态；
- 门户角色；
- 是否首次登录需改密；
- 密码更新时间；
- 最近登录时间；
- 锁定状态/失败次数。

规则：

- 本地账号仅由门户超级管理员创建、启停和重置密码；
- 不开放公众自助注册本地账号；
- 密码不得明文保存；
- 初始管理员密码不得硬编码进源码或Git；
- 本地用户没有管理员角色时，不自动获得管理端权限。

## 6. 门户与子系统权限边界

门户角色只控制卫健统一门户自身权限。

门户不负责：

- 子系统业务账号主数据；
- 子系统业务角色；
- 子系统菜单权限；
- 子系统数据权限；
- 子系统业务审批。

应用申请审核通过只产生“门户应用入口资格”，不产生子系统业务授权。

## 7. 管理端信息架构

```text
工作台
├─ 管理首页
└─ 通知公告管理

应用管理
├─ 应用列表
├─ 应用访问申请
└─ 运行监控

身份与映射
└─ 身份与子系统映射

系统管理
├─ 用户管理
├─ 角色管理
├─ 组织管理
├─ 字典管理
└─ 配置管理

日志审计
├─ 登录/认证日志
├─ 应用访问日志
├─ 门户操作日志
├─ 接口调用日志
└─ 异常日志
```

原独立“门户权限配置”并入角色管理。

“系统分类”最终迁入字典管理中的“应用系统分类”。

## 8. 用户管理

用户管理统一查看三类用户：

- 公众用户；
- 政务用户；
- 门户本地用户。

外部用户只允许维护门户侧信息：

- 门户启用状态；
- 门户角色；
- 门户组织索引（按来源）；
- 应用入口相关管理信息。

本地用户允许维护门户自身资料和凭证，但密码只能重置，列表/详情不得展示密码或密码Hash。

用户管理页面口径：
- 查询条件：姓名/账号、用户类别、身份来源、门户角色、启用状态；不提供“所属组织”查询；
- 列表字段不显示“所属组织”，用户账号作为详情入口；
- 所属组织仍保留在用户详情/新增/编辑中，允许为空；
- 新增/编辑用户时，门户角色使用平铺多选；
- 启用状态使用文字显示在开关内部的统一开关样式。

## 9. 角色管理

角色管理负责：

- 角色基本信息；
- 菜单权限；
- 页面权限；
- 操作权限；
- 关联用户。

默认只创建：

- 门户超级管理员；
- 门户管理员。

不在第一阶段实现复杂组织/应用数据范围配置页面；底层保留扩展能力。

角色权限配置页面只保留Dialog外层滚动条，“门户权限”内容区不再设置独立纵向滚动条，避免双滚动。

## 10. 应用访问

应用访问模式：

- DIRECT：直接进入；
- BIND：需先关联子系统账号；
- REQUEST：需先提交门户应用访问申请。

访问资格与门户角色完全分离。

### 10.1 BIND子系统账号关联

BIND支持：

- AUTO：可信稳定唯一标识唯一匹配后自动关联；
- SELF：用户自助关联；
- REVIEW：用户验证后由管理员审核；
- ADMIN：管理员人工关联。

当子系统缺少稳定唯一标识时：

```text
姓名 + 已登记手机号 / 姓名 + 工号等
→ 只生成候选账号
→ 二次验证
→ 验证通过
→ 建立BOUND映射
```

姓名+手机号不能作为永久统一身份键，也不能直接完成子系统账号绑定。

二次验证优先支持：

1. 子系统跳转认证；
2. 子系统原账号已登记手机号OTP；
3. 闽政通/闽政务重新认证；
4. 子系统账号一次性认证；
5. 管理员审核。

高权限账号可配置为验证成功后进入REVIEWING，再由管理员审核。

同一 application_id + external_user_id 只允许一个有效BOUND。若已绑定其他统一用户，必须转CONFLICT处理，不得自动覆盖。

子系统账号启停状态与门户映射状态分离；子系统账号停用时拒绝进入，但不删除映射历史。

### 10.2 跨身份源关联

如未来需要把CITIZEN与GOV关联为同一自然人：

- 稳定权威跨源ID优先；
- 无稳定ID时，姓名+已验证手机号等仅生成候选；
- 必须通过上层重新认证或更强实名核验后确认；
- 如需人脸核验，优先调用闽政通/闽政务等权威平台能力，门户不自行保存人脸模板；
- 关联后保留两个外部identity_mapping及审计依据。

### 10.3 REQUEST入口资格

REQUEST审核只授予门户应用入口资格；如目标应用仍要求子系统账号映射，APPROVED后继续执行BIND。

门户入口资格不等于子系统业务角色、菜单或数据权限。

## 11. 公告管理

状态：

- DRAFT 草稿
- SCHEDULED 定时发布
- PUBLISHED 已发布
- WITHDRAWN 已撤回
- EXPIRED 已失效

支持草稿、提交、立即/定时发布、已发布编辑、撤回、已撤回/失效删除、预览、正文插图、附件。A阶段HTML/TXT正文导入已实现；`.docx`正文解析仍为已知缺口，`.doc`不支持。失效时间为空表示永久有效。

公告页面交互：
- 用户端公告详情在右侧内容区打开，进入详情后左侧“通知公告”保持选中；
- 管理端公告详情与用户端复用同一详情内容组件，在右侧内容区打开；
- 管理端公告编辑也在右侧内容区打开，不使用编辑弹窗；编辑返回先回详情，详情返回再回列表；
- 管理端公告详情/编辑路由归属“通知公告管理”菜单并持续保持选中；
- 公告详情正文最小高度350px；
- 撤回确认使用warning提示；删除确认使用danger提示及危险色确认按钮。

## 12. 字典管理

业务字典：

- 应用系统分类；
- 公告类型；
- 组织类型。

系统受控字典：

- 启停状态；
- 运行状态；
- 公告生命周期；
- 映射状态；
- 待办状态；
- 消息阅读状态；
- 接入协议。

受控字典不能通过页面自由增加程序尚未支持的新状态或协议。

## 13. 日志审计

登录日志必须区分：

- 用户类别：公众/政务/门户本地；
- 身份来源：闽政通/闽政务/门户本地；
- 登录来源；
- 登录方式；
- 登录结果。

本地账号登录方式为“账号密码”。

## 14. 运行监控

按应用分别展示 SSO / TODO / MESSAGE 服务状态。详情不重复展示额外综合状态；数据库单服务 `monitor_status.status` 保留。

## 15. UI与加载

继续统一：

- Vue + Vite + TDesign；
- 13px基准字号；
- Dialog垂直居中；
- 页面级按钮位于标题右侧；
- Loading / Empty / Error严格区分；
- 首次数据未加载完成前不得闪现空态；
- 全系统无数据占位统一使用英文半角 `-`；
- 普通Dialog主操作放Footer，正文区域独立滚动。
