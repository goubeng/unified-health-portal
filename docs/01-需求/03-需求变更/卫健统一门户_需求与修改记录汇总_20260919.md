# 卫健统一门户需求与修改记录汇总

> 文档日期：2026-09-19  
> 当前基线：第十一轮“应用列表连接配置”修复后全量包，并补充第十二轮“配置管理固定操作区”调整  
> 样式参考：`office-house` 系统  
> UI 技术规范：TDesign / Vue，系统默认字号 13px，公共样式集中维护

---

## 1. 文档目的

本文档用于汇总“卫健统一门户”从初始版本至当前版本提出的功能、交互、样式和数据展示调整要求，并记录最终确认口径。后续原型、开发、联调、测试和验收应优先以本文“最终确认规则”为准；历史需求中已经被后续要求替代的内容，仅作为变更记录保留，不应继续实现旧方案。

---

## 2. 全局设计与开发规范

### 2.1 样式基线

1. 整体样式参考 `office-house`，包括页面标题、查询区、列表区、弹窗、详情页、消息详情、个人信息浮层等。
2. 系统默认文字字号统一为 **13px**。
3. 字重集中管理，不在页面组件中零散定义：
   - 普通正文、字段值、查询条件、列表链接、文字按钮：400；
   - 表头、页面标题、分区标题、应用名称、选中菜单：500；
   - 顶部系统名称等少量高层级标题：600；
   - 待办数量等强调数字可使用 600。
4. 页面组件尽量不写局部 `<style>` 或行内 `style`，固定样式统一维护在公共 `core.css / index.css / layout.css` 中。
5. 系统主要卡片和列表内容区采用直角布局，取消大面积圆角和阴影。
6. 普通列表/内容白色区域不显示灰色外边框；应用中心卡片例外，需要保留 1px 浅灰边框，Hover 时改为浅蓝边框且不能消失。
7. 空数据图片 `nopic.svg` 缩小显示，约 80px，并设置 75% 透明度。
8. 系统弹窗默认垂直居中。

### 2.2 页面标题与页面级操作

页面级主操作不放在列表卡片内部，应显示在“页面名称”同一行右侧。例如：

| 页面 | 页面标题栏操作 |
|---|---|
| 通知公告管理 | 新增公告 |
| 应用列表 | 新增应用、下载接口文件 |
| 系统角色 | 新增角色 |
| 系统分类 | 新增分类 |
| 待办/消息接入（历史方案） | 录入来源推送 |

详情页返回入口统一参考 `office-house`：显示在页面标题最左侧，仅使用左箭头图标，不显示“返回”文字按钮。

## 3. 顶部导航与菜单

### 3.1 顶部区域

1. 左侧菜单折叠图标缩小，与消息图标大小保持一致。
2. 消息徽标宽度按内容自适应，不使用过宽的固定宽度。
3. 当前端名称（如“用户端门户”“平台管理端”）需要有明确视觉识别，但不使用过重字重。
4. “切换用户”组件位于端切换入口之前。
5. “平台管理端 / 用户端门户”切换名称前增加简洁的端切换图标，避免顶部出现多个相似双向箭头。
6. 头像旁用户姓名如“陈宁”使用约 14px，较系统普通文字略突出。

### 3.2 用户浮动窗

参考 `office-house` 排布，浮层主要展示：

- 姓名；
- 账号 ID；
- 所属单位；
- 用户类别/角色标签；
- 个人信息；
- 修改密码；
- 退出系统。

避免堆叠过多权限说明和重复信息。

### 3.3 左侧菜单

1. 一级菜单支持折叠交互，参考 `office-house`。
2. 用户端一级菜单原“门户”更名为 **“个人事务”**。
3. 平台管理端取消独立一级菜单 **“内容管理”**；“通知公告管理”归入“管理首页”所在的 **工作台** 分组，并显示在“管理首页”下方。
4. 原“系统权限”菜单组最终更名为 **“系统管理”**，下设：
   - 系统用户；
   - 系统角色；
   - 门户权限配置；
   - 配置管理。
5. “门户角色”统一改称“系统角色”。
6. “业务集成”一级菜单最终取消，避免与“应用连接配置”重复。
7. “应用接入配置”独立菜单最终取消，连接配置收回“应用列表”。
8. “运行监控”归入“应用管理”分组。

## 4. 登录页

### 4.1 基础展示

1. 去掉“欢迎使用统一门户”。
2. 保留“公众用户 / 政务用户”身份切换，文字不应过大。
3. 身份 Tab 下划线宽度与文字本身一致，不铺满整个 Tab 容器。
4. “扫码登录 / 手机号登录”使用紧凑胶囊切换样式，未选中项不使用过深背景。
5. 登录区域使用白色背景，与页面背景形成明确层级。
6. 底部版权固定为：
   **卫健XC统一门户 · 由中电福富提供技术支持**
7. 最后一行保留：
   **尚未注册？立即注册 | 忘记密码**
8. 注册和忘记密码跳转至当前身份对应的闽政通或闽政务平台。

### 4.2 二维码登录

1. 二维码登录不显示“登录”按钮，也不显示“我已扫码”。
2. 提示文字：
   - 公众用户：`请使用闽政通扫一扫登录`；
   - 政务用户：`请使用闽政务扫一扫登录`。
3. 二维码按实际 5 秒倒计时显示：`00:05 → 00:00`。
4. 5 秒内点击二维码，模拟扫码成功并跳转首页。
5. “扫码成功”图标缩小并居中。
6. 二维码过期时保留原二维码，在二维码上增加半透明模糊浮层，显示“点击重新刷新”。
7. 二维码下方提示保留原位置，过期后改为“二维码已过期，请刷新”。
8. 不显示独立“刷新二维码”按钮；直接点击过期二维码区域刷新并重新从 5 秒倒计时。
9. 避免多层重复提示，不显示“二维码已刷新，请重新扫码”等额外提示框。

### 4.3 手机号登录

1. 滑块按 TDesign/门户统一视觉调整。
2. 手机号登录选中状态不使用过强的大面积蓝色填充。
3. 去掉“验证码步骤已完成，请点击登录”等过程型提示。

## 5. 首页

### 5.1 用户端首页布局

首页优先展示个人事务信息，再展示我的应用：

1. 我的待办；
2. 通知公告；
3. 消息；
4. 我的应用。

### 5.2 数量与未读

1. “我的待办 / 通知公告 / 消息”数量使用 TDesign `danger + light + small` 浅红 Tag。
2. 不再使用“未读 3”“未读 8”等文本组合，只显示数字标签。
3. 未读公告和未读消息不显示红点。
4. 已读信息不使用加粗蓝色。

### 5.3 链接与待办操作

1. 首页和列表页的可点击标题使用蓝色普通字重，不加粗。
2. “去处理”最终改为蓝色文字按钮，不使用纯色或线框大按钮。

### 5.4 我的应用

1. 我的应用只展示当前登录账号有权访问/已关联的应用，不展示全量应用。
2. 首页“我的应用”卡片无需重复显示“已关联”。
3. 后续又明确去掉“正常”等重复状态信息，卡片重点保留系统名称、分类和进入操作。
4. 应用名称使用黑色中等字重。
5. “进入 / 关联”使用蓝色文字，12px。
6. 应用卡片可以使用很淡的颜色区分，但整体保持简洁。

### 5.5 管理首页

1. 原管理首页内容过于单调，增加管理概览和快捷工作入口。
2. “管理工作”改为更紧凑的图标型入口，避免大块卡片占位过多。
3. “运行概况”与顶部统计存在重复，因此调整为更偏“管理提醒”的内容。
4. 接入运行、异常等最终由“运行监控”承载。

## 6. 查询区、列表与分页统一规范

### 6.1 查询区

1. 查询布局参考 `office-house` 和 TDesign 标准方式。
2. 查询按钮“重置”不得与查询条件重叠，也不能被 TDesign inline form 拉伸产生过大间距。
3. 查询条件之间保持统一的小间距。
4. 查询条件宽度根据字段语义设置，不得全部等宽。
5. 宽度规则集中放公共 CSS，并同时锁定 `width / min-width / max-width / flex-basis`，避免 TDesign 表单项重新拉伸。

当前统一宽度参考：

| 类型 | 宽度参考 |
|---|---:|
| 关键词 | 360px |
| 状态 | 170px |
| 系统分类 | 220px |
| 用户类别 | 190px |
| 优先级 | 170px |
| 消息类型 | 210px |
| 发布范围 | 200px |
| 来源应用 | 280px |
| 所属单位 | 280px |
| 接入类型 | 190px |
| 接入模式 | 200px |
| 单日期 | 230px |
| 日期区间 | 360px |

“通知公告”的关键词搜索框需要确保“请输入名称、标题或账号”等提示文字能完整显示。

### 6.2 列表

1. 列表中的操作文字统一为蓝色文字按钮。
2. 列表主字段/链接文字最终统一取消加粗，保持蓝色普通字重。
3. 表头、正文、分页等统一 13px 基准。
4. 列表内容区白色背景不显示外层灰色边框。
5. 分页控件内部间距和分页与列表之间的间距均缩小。

## 7. 通知公告

### 7.1 公告管理

1. “新增公告”放页面名称同一行右侧。
2. 新增/编辑公告弹窗加宽并始终垂直居中。
3. 正文使用富文本编辑器。
4. 富文本工具栏：加粗、斜体、下划线、项目符号、编号、左对齐、居中、右对齐等尽量使用图标。
5. 图标 Hover 时通过 Tooltip 显示中文名称。
6. 生效/失效时间使用 TDesign 日期时间组件。
7. 附件使用 TDesign Upload 组件。

### 7.2 公告详情

1. 公告详情在当前页面打开，不使用详情弹窗。
2. 页面标题左侧使用 `office-house` 风格左箭头返回图标，不显示“返回”文字按钮。
3. 详情顶部只显示：
   - 公告类型；
   - 发布范围；
   - 发布时间。
4. 去掉“公告状态”。
5. 三个指标显示在同一行，不使用网格化信息表。
6. 三个指标文字前增加小图标。
7. 指标下方增加横向分隔线，再显示正文。
8. 详情高度随内容自适应；页面出现滚动时，仅主内容区域滚动。
9. 无附件时缩小附件区，仅显示“无附件”，不显示空态图标。
10. 通知公告列表和详情加载时不增加额外白色遮罩背景，仅保留加载指示。

## 12. 系统权限

### 12.1 门户权限边界

1. 门户不拥有上层身份体系的用户管理权。
2. 门户的系统角色仅管理门户自身权限。
3. 子系统内部业务访问授权由各子系统自行负责。
4. 系统用户通过分配系统角色获得门户权限，不鼓励每个用户直接维护一套权限。

### 12.2 菜单

“系统权限”下统一：

- 系统用户；
- 系统角色；
- 门户权限配置。

“新增角色”放“系统角色”页面标题同一行右侧，不放列表内部。

## 13. 应用管理与连接配置

### 13.1 应用列表

1. “新增应用”放页面标题同一行右侧。
2. 应用状态不再在操作列显示启用/停用按钮，而是直接在“状态”列使用 TDesign Switch。
3. 操作列主要保留：
   - 编辑；
   - 连接配置。
4. “下载接口文件”显示在“应用列表”页面标题右侧，不显示在单条记录操作中。

### 13.2 连接配置最终结构

独立“应用接入配置”菜单已经取消，连接配置统一收回应用列表。

点击“连接配置”打开居中弹窗，页签包括：

- SSO 接入配置；
- TODO 接入配置；
- MESSAGE 接入配置。

每个页签独立维护其启用状态、接入参数、字段映射、凭据引用、备注等信息。

如果某应用第一次打开连接配置且尚未初始化，系统自动初始化 SSO / TODO / MESSAGE 三类配置。

### 13.3 接口文件

“下载接口文件”属于门户级公共接入规范，应由各子系统下载后按门户规范实现接口，不属于某一条应用记录的行级操作。

接口规范应覆盖 SSO、TODO、MESSAGE 的字段、请求/响应、状态映射等公共规范；应用自己的 Client ID、凭据引用等仍在该应用连接配置中维护。

## 14. 运行监控与业务集成边界

1. “业务集成”一级菜单最终取消。
2. 连接“怎么配置”统一由“应用列表 → 连接配置”负责。
3. 接入后的运行状态、最近调用、异常、接口状态等跟踪信息统一归入“运行监控”。
4. 避免同时在“应用接入配置”和“业务集成”维护两套 SSO/TODO/MESSAGE 配置。

## 15. 配置管理 / 规则配置

### 15.1 页面布局

1. 页面级提示信息显示在白色规则内容区外。
2. 提示窗缩小，文字统一 13px，提示图标约 16px。
3. 白色内容区取消圆角。
4. “公告规则 / 留存规则”等分组标题保持左侧基线。
5. 指标配置区相对子标题向右缩进，避免指标与子标题完全左对齐。
6. 一行显示 2 个指标，窄屏自动单列。
7. 每项配置按三行展示：
   - 字段名称；
   - 数字输入组件；
   - 提示信息。

### 15.2 第十二轮新增确认

“应用修改”操作必须始终显示在页面下方，不能随着配置内容滚动离开视野：

- 页面级提示固定在配置区上方；
- 白色规则内容区占据剩余高度；
- 中间规则配置内容独立滚动；
- 底部操作栏固定在配置内容区底部；
- “应用修改”按钮始终可见；
- 错误信息显示在底部操作栏左侧，不改变按钮位置。

## 16. 数据隔离与应用可见性

1. 待办、消息、公告按当前用户和发布范围过滤。
2. 用户端应用中心不读取并展示完整应用目录，应根据当前账号的应用授权/映射展示。
3. 平台管理端仍可以管理完整应用目录。
4. 管理端和用户端数据视图需要明确区分，避免普通用户看到无权访问的数据。

## 18. 已被后续需求替代的历史口径

为避免后续开发误用，以下内容属于历史过程，不应再按旧方案实现：

1. **列表链接加粗**：曾要求蓝色加粗，最终改为蓝色普通字重。
2. **消息详情弹窗**：曾加宽消息详情弹窗，最终改为当前页面详情展示并参考 `office-house`。
3. **独立“应用接入配置”菜单**：曾实现一应用一条接入记录，最终菜单取消，迁移至“应用列表 → 连接配置”弹窗。
4. **业务集成菜单**：最终取消；接入跟踪放运行监控。
5. **应用状态启用操作**：曾在操作列使用开关，最终状态列直接显示 TDesign Switch。
6. **二维码刷新按钮**：曾显示独立刷新按钮，最终改为点击过期二维码区域刷新。
7. **二维码过期后替换图片**：最终改为原二维码保留，叠加模糊遮罩层。
8. **应用卡片显示“已关联/正常”**：最终从应用中心卡片去除。
9. **管理首页运行概况**：因与头部统计重复，最终弱化为管理提醒/运行监控入口。

## 19. 当前验收重点

后续验收建议重点检查：

1. 用户切换后待办、消息、公告、应用是否严格按用户过滤；
2. 所有查询项是否按字段语义呈现不同合理宽度；
3. 列表页页面级按钮是否全部在页面标题右侧；
4. 全系统字号、字重、卡片、边框、圆角是否一致；
5. 公告详情和消息详情是否都按最终确认方式打开；
6. 消息多选、删除、已读、全部已读、上一封/下一封是否形成完整闭环；
7. 应用列表状态 Switch 与“连接配置”弹窗是否正常工作；
8. SSO / TODO / MESSAGE 是否只有一套配置入口；
9. 运行监控是否位于“应用管理”下，并按应用聚合显示 SSO / TODO / MESSAGE 的未配置、停用、正常、异常状态；
10. 配置管理中间区域滚动时，“应用修改”按钮是否始终固定在底部左侧可见，且不再出现“显示规则”；
11. 连接配置中间区域滚动时，“保存配置”是否始终完整固定在弹窗底部；
12. 点击应用名称进入应用详情时，SSO / TODO / MESSAGE 连接信息是否正确展示，未配置项是否明确显示“未配置”；
13. 全系统 Dialog 弹窗是否统一使用直角样式。
