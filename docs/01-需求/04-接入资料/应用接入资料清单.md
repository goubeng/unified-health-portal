## 逐应用登记模板

正式资料到达后每个真实系统建一条记录；以下只有列定义，没有任何真实接入记录。

| 字段 | 填写要求 |
|---|---|
| 正式系统名称、系统编码 | 使用业主确认清单，编码不得用示例编号代替 |
| 分类、身份、网络区域、入口 | 标明资料来源和批准地址；不以临时IP:端口判定入口 |
| 业务/技术负责人 | 待项目指定，不编造姓名 |
| SSO能力、账号验证、开户路径 | 已支持/需改造/待核实，并附契约或确认记录 |
| 子系统稳定用户标识 | 明确 external_user_id / account / employee_no 等稳定用户键及唯一性 |
| 子系统用户来源 | 自建 / 上级同步 / 其他；说明账号主数据责任方 |
| 原登录入口 | 是否继续保留、是否允许门户与原入口并行登录 |
| SSO返回方式 | Token / Ticket / Session / Cookie / 自定义，并说明有效期和校验方式 |
| 账号查询/验证接口 | 是否支持账号查询、账号归属校验、停用状态查询及返回错误码 |
| 账号关联策略 | AUTO / SELF / REVIEW / ADMIN；是否存在高权限账号强制审核 |
| 无账号处理 | 子系统开户入口、标准开户注册接口或拒绝原因返回方式 |
| 账号停用处理 | 子系统账号停用后门户如何识别、映射是否保留、SSO如何拒绝 |
| 待办PUSH能力 | 新增、状态变更、目标用户键、幂等与乱序处理；不得切换为门户拉取 |
| 消息PUSH能力 | 消息唯一键、目标用户、类型、已读回传支持情况 |
| 短信调用需求 | 是否需要、模板授权、额度、通道依赖；不强制假定42个子系统均已开通 |
| 接入阶段 | 待资料/待设计/待开发/待联调/待验收/已验收；实际进度需证据 |
| 验收证据 | 环境、版本、日期、执行人、成功/失败/重复/越权用例及结果位置 |

## 入口与验收规则

全部应用目录包含全部确认系统；停用或未配置显示相应状态及不可进入原因，不伪装为正常。账号映射与入口授权分离，最终业务资格由子系统判断。

未关联可进入自助关联路径；接口不支持时说明待接入；无子系统账号显示子系统的开户或拒绝结果。没有正式名单时仅允许明确标记“示例应用”的Mock数据，不将示例凑成42条并报告覆盖率。

接入率需要正式清单分母和逐应用验收分子；当前均无证据，显示“待核验”，不报告0/42或42/42为真实统计。
