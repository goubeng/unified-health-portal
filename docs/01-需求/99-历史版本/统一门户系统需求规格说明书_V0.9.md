# 1. 项目背景

本项目建设一个位于上层身份平台与下层业务系统之间的**统一门户 / 统一认证中间层系统**。

当前整体结构如下：

```text
┌──────────────────────────────────────────────┐
│                上层身份平台                  │
│                                              │
│  公众侧统一身份平台       政务侧统一身份平台   │
│  （类似“闽政通”）         （类似“闽政务”）     │
└──────────────────────┬───────────────────────┘
                       │
            注册 / 登录 / 身份认证 / 核验
                       │
                       ▼
┌──────────────────────────────────────────────┐
│              本次建设：统一门户               │
│                                              │
│  统一登录入口   统一身份索引   账号映射        │
│  应用目录       单点登录       待办汇聚        │
│  消息汇聚       通知公告       短信服务        │
│  接入管理       运行监控       日志审计        │
└──────────────────────┬───────────────────────┘
                       │
           SSO / 待办 / 消息 / 短信服务
                       │
                       ▼
┌──────────────────────────────────────────────┐
│              约43个业务子系统                 │
│                                              │
│ 各自保留：用户账号、业务角色、菜单权限、数据权限 │
└──────────────────────────────────────────────┘
```

# 2. 建设目标

本项目的核心目标包括：

1. 建设统一门户，作为约43个既有业务系统的统一入口；
2. 对接公众侧、政务侧两个上层身份平台，统一完成身份认证；
3. 支持用户从上层平台单点进入，或直接访问门户后通过扫码 / 手机号验证码完成认证；
4. 建立统一身份索引，实现上层身份与多个子系统账号之间的映射；
5. 43个子系统全部进入“全部应用”目录；
6. 子系统访问资格、账号开户、业务角色及业务权限继续由各子系统负责；
7. 43个子系统的待办事项全部接入统一门户；
8. 43个子系统的消息全部接入统一门户；
9. 通知公告仅由统一门户自身发布，不接入子系统公告；
10. 建设统一短信服务能力，供43个子系统统一调用；
11. 提供应用接入、身份映射、SSO、待办、消息、短信、监控、日志等管理能力；
12. 数据汇聚治理不纳入本统一门户后台建设范围。

# 3. 已确认的系统边界

## 3.1 已确认边界

| 编号 | 边界事项 | 确认结果 |
|---|---|---|
| B-01 | 门户是否拥有用户管理权 | **否** |
| B-02 | 门户角色管理范围 | **仅管理门户自身权限** |
| B-03 | 应用访问授权 | **由各子系统负责** |
| B-04 | 43个系统是否全部进入“全部应用” | **是** |
| B-05 | 上层无用户时如何注册 | **跳转至上层平台完成注册** |
| B-06 | 子系统无账号时如何开户 | **由子系统自行决定和处理** |
| B-07 | 待办是否全部接入 | **43个系统全部接入** |
| B-08 | 消息是否全部接入 | **43个系统全部接入** |
| B-09 | 短信能力 | **门户统一提供给子系统调用** |
| B-10 | 数据汇聚治理 | **不属于本门户后台** |

## 3.2 本门户不承担的职责

本门户原则上不承担：

- 上层公众用户完整生命周期管理；
- 上层政务用户完整生命周期管理；
- 用户密码管理；
- 子系统用户完整生命周期管理；
- 子系统业务角色维护；
- 子系统菜单权限维护；
- 子系统数据权限维护；
- 子系统开户审批；
- 子系统业务流程审批；
- 数据采集治理与专项库建设。

# 4. 用户与身份体系

## 4.1 用户来源

| 用户来源 | 面向对象 | 权威身份来源 |
|---|---|---|
| 公众侧用户 | 社会公众、自然人 | 公众侧上层身份平台 |
| 政务侧用户 | 政务工作人员、管理人员 | 政务侧上层身份平台 |
| 子系统用户 | 各业务系统内部账号 | 各子系统自身用户体系 |

## 4.2 中间层用户定位

中间层不建设第三套完整用户中心，只维护：

- 统一身份ID；
- 上层身份来源；
- 上层唯一身份标识；
- 最小必要展示信息；
- 子系统账号映射；
- 登录Session；
- 登录与访问日志。

## 4.3 一人多身份、多账号关系

```text
统一身份 U000001
│
├─ 公众身份：CITIZEN_928371
├─ 政务身份：GOV_287362
│
├─ 系统01账号：zhangsan
├─ 系统08账号：user_8276
└─ 系统31账号：ZS001
```

## 4.4 身份认证与业务权限关系

必须明确：

```text
身份认证
≠
门户登录
≠
子系统账号
≠
子系统业务权限
```

门户负责确认“这个人是谁”，子系统负责确认“这个人在本系统能做什么”。

# 5. 系统端划分

本系统分为三个主要使用区域：

1. **登录端**：统一身份认证入口；
2. **用户端门户**：普通用户登录后的统一应用入口；
3. **平台管理端**：平台管理员进行应用、接入、身份映射、集成、短信、监控、日志等管理。

# 7.4 子系统账号关联

当用户点击应用，中间层无映射但子系统已有账号时，可支持用户自助关联。

## 流程

```text
用户点击应用
    ↓
门户无账号映射
    ↓
选择“关联已有账号”
    ↓
完成子系统账号验证
    ↓
验证成功
    ↓
建立统一身份 ↔ 子系统账号映射
    ↓
后续SSO进入
```

## 关联方式

| 方式 | 说明 |
|---|---|
| 自动关联 | 使用可信唯一标识自动匹配 |
| 自助关联 | 用户验证原子系统账号 |
| 审核关联 | 用户发起，管理员审核 |
| 管理员关联 | 特殊历史系统人工处理 |

门户不保存子系统明文密码。

---

# 7.5 子系统无账号

当目标子系统没有账号时：

> 门户不负责开户。

处理方式由子系统自行决定：

- 自动开户；
- 子系统申请开户；
- 拒绝访问；
- 返回原系统开户入口。

门户仅展示子系统返回结果。

# 10. 关键业务流程

# 10.1 登录流程

```text
访问门户
  ↓
是否携带上层有效凭证？
  ├─ 是 → 校验 → 建立Session → 首页
  └─ 否
      ↓
选择公众 / 政务
      ↓
扫码 / 手机号
      ↓
上层认证
      ↓
上层是否有用户？
  ├─ 否 → 跳转上层注册 / 开通
  └─ 是
      ↓
中间层是否已有统一身份？
  ├─ 否 → 自动建立最小身份索引
  └─ 是
      ↓
建立Session
      ↓
进入门户
```

# 10.2 应用访问流程

```text
用户点击应用
    ↓
查询账号映射
    ↓
是否已映射？
 ┌──┴──┐
 是    否
 │      │
SSO   尝试自动关联 / 用户自助关联
 │      │
 │   子系统是否已有账号？
 │      ├─ 有 → 验证并建立映射
 │      └─ 无 → 交由子系统自行处理开户
 │
 ↓
子系统判断访问资格及业务权限
 ↓
进入系统 / 拒绝访问
```

# 10.3 待办流程

```text
子系统产生待办
    ↓
推送 / 门户拉取
    ↓
门户标准化
    ↓
用户待办中心
    ↓
用户点击“去处理”
    ↓
SSO跳转子系统业务页面
    ↓
子系统处理完成
    ↓
更新门户待办状态
```

# 10.4 消息流程

```text
子系统产生业务消息
        ↓
推送 / 门户拉取
        ↓
统一消息模型
        ↓
门户消息中心
        ↓
用户阅读 / 跳转业务详情
```

门户自身也可产生账号关联、身份异常、安全提醒等消息。

# 10.5 短信流程

```text
子系统
   ↓
调用统一短信API
   ↓
门户校验应用身份与模板权限
   ↓
调用短信渠道
   ↓
短信服务商
   ↓
记录发送结果 / 费用 / 失败原因
```

- 短信由门户统一提供；
- 数据治理不属于门户后台；
- 我的应用 + 全部应用采用混合模式；

- 支持用户自助关联已有子系统账号。
