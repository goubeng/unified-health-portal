## 4. 评审与历史

阶段Review统一位于 `02-开发/02-评审/`，只记录当时验证事实，不随当前需求回写。

原始需求位于 `01-需求/01-原始需求/`；旧需求规格位于 `01-需求/99-历史版本/`。

## 5. 交付区

[交付文档管理说明](./03-交付/README.md)

交付区只放冻结后的最终需求、详细设计、测试、用户手册、部署和数据库说明，开发草稿不得提前进入。

## 6. 当前权威顺序

1. 当前确认的产品决策 / ADR；
2. `01-需求/02-当前基线/`；
3. `02-开发/01-设计/`；
4. `02-开发/03-计划/`；
5. 历史需求、过程记录和历史评审。

## 7. 新文档放置规则

- 客户新给的原始材料 → `01-需求/01-原始需求/`
- 已确认需求新增/修改记录 → `01-需求/03-需求变更/`
- 已确认并整理后的最新需求 → 回写 `01-需求/02-当前基线/`
- 开发设计 → `02-开发/01-设计/`
- Review/阶段验收 → `02-开发/02-评审/`
- 下一阶段任务/整改计划 → `02-开发/03-计划/`
- progress/findings/lessons → `02-开发/04-过程记录/`
- 最终交付文件 → `03-交付/`

`.project/`继续作为工程元数据和ADR目录；`database/`继续与数据库源码一起管理。
