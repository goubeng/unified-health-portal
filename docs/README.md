## 3. 细化需求辅助材料

`01-需求/02-当前基线/细化需求/` 中保留的材料用于产品分析、开发交接和局部查阅，例如：

- 登录与用户体系；
- 角色清单；
- 范围边界；
- 菜单结构；
- 页面清单；
- 页面规格；
- 业务对象清单；
- 业务流程；
- 字段规则；
- 待确认问题。

这些文件属于**辅助细化材料**，不得形成第二套需求基线。若与主需求规格说明书冲突，以主需求规格说明书为准，并应同步修订辅助材料。

## 5. 原始需求与历史追溯

原始客户/项目材料保留在：

- `01-需求/01-原始需求/`

需求演进和历史版本不再通过复制需求规格说明书文件维护，统一通过：

- Git Commit；
- Git Tag / Release（阶段冻结时）；
- 开发阶段 Review / 验收记录。

因此不再保留 `03-需求变更/` 和 `99-历史版本/` 作为并行需求基线目录。

## 6. 交付区

[交付文档管理说明](./03-交付/README.md)

交付区只放冻结后的最终需求、详细设计、测试、用户手册、部署和数据库说明，开发草稿不得提前进入。

## 7. 权威顺序

1. `01-需求/02-当前基线/卫健统一门户系统需求规格说明书.md`
2. `.project/DECISIONS.md` 中已经确认且尚未回写主需求的即时决策
3. `01-需求/02-当前基线/细化需求/` 辅助材料
4. `02-开发/01-设计/`
5. `02-开发/03-计划/`
6. 原始需求、过程记录和历史评审

一旦产品决策确认，应尽快回写主需求规格说明书，避免长期存在第2级临时口径。

## 8. 新文档放置规则

- 客户新给的原始材料 → `01-需求/01-原始需求/`
- 已确认需求新增/修改 → **直接更新主需求规格说明书**
- 模块级范围概览 → 更新 `功能清单.md`
- 子系统接入信息 → `01-需求/04-接入资料/`
- 开发设计 → `02-开发/01-设计/`
- Review/阶段验收 → `02-开发/02-评审/`
- 下一阶段任务/整改计划 → `02-开发/03-计划/`
- progress/findings/lessons → `02-开发/04-过程记录/`
- 最终交付文件 → `03-交付/`

`.project/` 继续作为工程元数据和 ADR 目录；`database/` 继续与数据库源码一起管理。
