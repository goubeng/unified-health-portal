# 公众端手机网页实施计划（2026-10-09）

## 目标与范围

面向公众用户建设可在手机浏览器访问的移动网页，设置五个底部栏目：**首页、待办事项、全部应用、消息中心、我的**。内容、权限、数据状态与现有公众端保持一致，界面采用适合手机单手操作的 TDesign 移动端组件。闽政通作为政务服务类 APP 的信息层级、清晰配色与高频入口参考，不照搬其栏目或业务内容。

本文件是手机网页实施方案，尚未开始功能开发。原生安装包、PWA 离线能力和系统推送通知不在本期范围内；真实认证与外部系统接通状态需独立核验。

## 现状依据

- 项目采用 Vue 3、Vite、Vue Router，当前依赖 `tdesign-vue-next` 桌面组件；未安装 `tdesign-mobile-vue`，也没有独立的移动端底部导航。
- 公众端已有 `/portal/home`、`/portal/todos`、`/portal/apps/all`、`/portal/messages`、`/portal/profile` 等路由；现有窄屏样式仍保留桌面侧栏和表格交互，不能直接充当 APP 界面。
- `src/services/runtime.js` 提供会话、读取、命令调用；`src/services/portal.js` 已处理公众身份的应用范围、用户数据过滤与应用访问状态。移动端应复用数据契约和业务规则。
- 当前登录属于演示会话，外部系统接入也有未完成边界。正式开放给公众前需落实正式认证、接口入口及会话策略；开发验收须明确演示会话边界。

## 页面规划

| 栏目 | 主要内容 | 数据与动作口径 |
| --- | --- | --- |
| 首页 | 顶部搜索/服务入口、常用应用、待办摘要、未读消息、通知公告 | 从现有首页聚合与对应资源取数；摘要点击进入相同详情，不另造统计口径 |
| 待办事项 | 待处理/全部切换、筛选、待办卡片与详情、去处理 | 保留现有 `openTodo` 行为；来源系统状态以接口结果为准，不在本地擅改 |
| 全部应用 | 搜索、分类、我的应用/其他应用、应用详情 | 保留公众适用范围、直接访问/关联/申请等状态与动作；我的申请作为次级入口 |
| 消息中心 | 消息列表、未读/全部筛选、未读状态、消息详情；已读、批量已读、删除和业务跳转 | 展示消息与未读数；上述动作复用现有消息资源与命令，遵守当前用户过滤及权限；公告保留首页入口与独立详情，不混入业务消息 |
| 我的 | 身份与个人资料、我的申请、设置、退出 | 仅展示当前已有资料字段和可用动作；不新增未经支持的资料编辑 |

## 技术方案

1. 在现有 Vue 项目内新增独立移动路由和五栏布局，建议以 `/m` 为入口；桌面公众端及管理端继续使用原路由。
2. 移动界面选用官方 `tdesign-mobile-vue` 的导航栏、底部标签栏、搜索、列表、筛选、弹层与反馈组件；新增代码采用 TypeScript，并在实施前确认版本及样式隔离方式。
3. 抽取可复用的数据访问和状态映射，移动页面按现有会话、身份、应用范围和权限取数；对详情跳转、返回、刷新及加载/空/错误状态作统一处理。
4. 适配安全区、不同屏宽、系统字体放大、触控目标、键盘遮挡与弱网重试；减少首页单次请求体量，避免重复拉取。
5. 本期交付手机浏览器可访问的移动网页。以现有站内消息数据展示列表、未读状态和详情，复用既有已读、批量已读、删除及业务跳转；不接入系统推送。

## 分阶段实施与验收

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 1. 原型与契约 | 五栏线框/视觉稿、页面字段与动作清单、接口与权限映射 | 手机网页五栏内容、次级入口、消息状态和设计稿经确认 |
| 2. 移动底座 | `/m` 路由、移动布局、TD 移动组件、会话守卫、主题与安全区 | 手机宽度下五栏切换、返回、刷新正常；不影响桌面端 |
| 3. 业务页面 | 按首页→全部应用→待办→消息→我的实现列表、详情和既有动作 | 同一用户在桌面与手机网页看到一致数据和权限；消息列表、未读状态、详情及既有操作按当前规则执行 |
| 4. 联调与验收 | 定向测试、构建、手机浏览器/真机视觉与交互、数据库读回及重启复核 | 五栏、消息展示与操作、深链、弱网/空态、权限边界通过；持久化由数据库证据证明，外部集成单独标记状态 |

## 实施前需明确的接口边界

1. 正式登录方式与已有身份平台的对接安排；当前演示会话不能直接作为公众正式登录。
2. 手机网页对外访问的正式域名、反向代理和接口入口，以便做实际手机网络与会话验收。

阶段 1 可以立即开展；正式开放前须完成上述入口与认证核验。本期消息仅包含站内展示及现有操作，不包含系统推送。
