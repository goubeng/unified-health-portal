## 本地运行

Node.js 20.19+ 或 22 LTS，首次执行 `npm ci`。本地 PostgreSQL 的目标 schema 须先完成 `001`–`009` 迁移，并执行 `npm run db:bootstrap-missing` 补齐旧快照缺省的演示样本。当前仓库使用本机 Docker 容器 `postgres14` 中的 `nocodb_data.pb3gir75kkooyea`；换环境时需先调整数据库连接配置。

执行 `npm run dev` 会同时启动数据库模式 API（`127.0.0.1:4011`）和前端（`0.0.0.0:4010`）。本机访问 `http://127.0.0.1:4010`；局域网访问 `http://<本机局域网IPv4>:4010`。如果 4011 已有内存模式 API，先停止旧进程再启动数据库模式，启动器不会静默复用错误的数据源。

隔离测试仍可用 `npm run dev:mock`，或分别运行 `npm run api` 与 `npm run dev:ui`。仅启动数据库 API 可用 `npm run api:db`。

健康检查 `/api/portal/health` 会返回 `repository=MEMORY_A` 或 `DATABASE`，用于确认当前运行模式。

数据库模式的 GET 健康检查、会话及页面读取会在 API 进程内复用 1 秒只读快照；写操作后立即失效，下一次读取会重新查询数据库。直接从其它进程修改数据库的数据，页面最多可能延迟约 1 秒看到变化；这不改变登录、权限和写入语义。数据库读取已按依赖分两波并发执行，本机复测首次冷读取约 1.2 秒，6 个并发页面读取约 1.1 秒，缓存命中的单次应用读取约 15 毫秒；实际耗时会随机器和数据库负载变化。若切换数据库内容后仍看到旧页面，可稍候刷新，不要以进程内缓存代替数据库回读验收。

## 局域网访问

当前本地开发网络策略：

- 前端：`0.0.0.0:4010`，允许同一局域网访问；
- API：`127.0.0.1:4011`，只允许本机直接访问；
- 浏览器所有 `/api/portal` 请求由 Vite 代理转发到本机 4011；
- API 仅接受来自 `4010` 的 localhost 或 RFC1918 私有 IPv4（`10.x`、`172.16-31.x`、`192.168.x`）页面 Origin。

在 Windows 上执行 `ipconfig` 获取本机 IPv4，例如 `192.168.1.100`，局域网其他设备访问：

```text
http://192.168.1.100:4010
```

如果无法访问，请确认 Windows 防火墙允许 TCP 4010 入站。无需对局域网开放 4011。

构建：`npm run build`；测试：`npm test`；P3静态校验：`npm run check:p3`。

## 当前实现边界

当前登录、SSO、子系统账号核验、PUSH 外部联调仍为模拟或本地契约，不代表正式生产集成。

最新目标身份与授权模型为：

- 闽政通 → CITIZEN / 公众门户访问主体；
- 闽政务 → GOV / 政务门户访问主体；
- 门户管理用户由独立的 `portal_admin_user` 管理授权域承载；
- LOCAL 仅表示门户本地管理认证方式，不是第三类普通访问用户；
- 管理用户可通过 EXTERNAL 绑定现有访问主体，或使用 LOCAL 本地管理账号。

默认门户角色收敛为 SUPER_ADMIN 和 PORTAL_ADMIN；门户权限采用 `resource:action` 权限码，子系统业务角色和业务权限仍由各子系统负责。

公告、应用和分类、待办、消息、应用访问申请与授权、账号开通申请已由数据库业务表读写。组织、字典、角色、用户、映射与本地配置等使用逐条持久化的过渡实体表；完整生产关系模型和外部系统对接仍需后续建设。旧 `P4RUN_STATE` 继续承担兼容快照和全局版本控制。
